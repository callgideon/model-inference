## Findings and dispositions

### 0-G8-R1 and 2-ACC-1 (one hole): fixed in code, and the runbook gains a check

**Reproduced at `6a075c56`**, with the reviewers' own scripts run on g8:
- `scratchpad/g8acc/race.py` (C holds `infrx.credit_holds` in SHARE mode) printed `transition exit: 0`, all three flags applied, `audited: 1`, `A result: admitted`, and `legacy jobs in flight after 'successful' transition: 1`. The dry-run rerun gave exit 1 with `['in_flight']`.

**Cause.** `infrx.require_feature` reads the flag with no lock. An admission that passed both flag checks before the freeze committed is still an open transaction when the drain is measured. The drain's repeatable-read snapshot cannot see its job, and the final recheck runs before that job commits.

**Fix (G8 code only, no SQL).** Once the freeze has committed, `apply` records the virtual transaction ids of every transaction open in the database. A `pg_locks` row of locktype `virtualxid` is held by every transaction from its start. The query joins `pg_stat_activity` for the database, and a non-null `usesysid` excludes autovacuum. `pg_locks` and those `pg_stat_activity` columns are readable by any role; `service_role` was probed on g8. `apply` then polls until none of those transactions remains, before it measures the drain.
- This is CREATE INDEX CONCURRENTLY's wait. Any transaction that read the flag before the freeze committed was open at that moment, so it is waited for. A transaction that starts later reads the flag frozen. The caller's own listing drops out of the intersection, because each listing is a new transaction.
- The wait shares the drain's bound (`--drain-timeout-s`). Past the bound, the run raises `TransitionBlocked` with blocker `open_transactions`. The freeze stays in place, the target flags are untouched, nothing is audited, and a rerun continues.
- I chose this over the reviewer's `txid_snapshot_xmin > T` suggestion. The xmin form misses a transaction whose xid is assigned after T: on the CREDIT side, the insert's BEFORE trigger checks the flag before the heap insert assigns the xid. The xmin form also spans every database in the cluster.

**After the fix** (`44ea4770`):
- `race.py` prints `transition exit: 1`, applied = the freeze only, `audited: 0`. After C commits, A is admitted, and the dry run gives exit 1 with `['in_flight']`.
- The outbox-lock variant (`scratchpad/g8rev/t/test_rev_race.py`, whose last line is a report-only `assert False`) prints `TRANSITION 1 … blockers: [open_transactions] … "2 transaction(s) open since the freeze of legacy_usd_admission may still commit legacy_usd work"`, and its dry run gives `DRYRUN 1 ['in_flight']`.

**Regression at the seam.** `test_transition_pg::test_credit_cutover__an_admission_open_across_the_freeze_is_waited_for`, on two connections:
1. The USD admission passes both flag checks, inserts its job and parks on C's SHARE lock on `infrx.credit_holds`.
2. `credit-transition --drain-timeout-s 0.5 --poll-s 0.1` must exit 1 with `{open_transactions}`. Applied must be the freeze only, `credit_admission` off, and zero audit rows.
3. C rolls back and the admission commits. The dry run must exit 1 with `{in_flight}` and inventory `{"legacy_usd": {"preparing": 1}}`.
4. The job settles in USD, and the rerun then exits 0 with CREDIT enabled and zero drift.

The fake-store case `test_transition::test_credit_cutover__apply_waits_out_every_transaction_open_at_the_freeze` checks two things:
- Order: freeze, then listings until the set open at the freeze is gone, then the drain. A transaction that began later does not count.
- The bound: blocked with `open_transactions`, freeze only, nothing audited.

## Fix: transition lock bound on the D10 schema (2026-09-25)

Branch `codex/g8-transition-lock` from `bd556c5f` (`codex/m6-merge`: integration + D10 + M5 + M6; D10's 0019–0021 present). Lane G8-TRANSITION-LOCK.

**Defect.** D10 applied wiring request 1: `infrx.require_feature` (0021) reads the flag `FOR SHARE`. An admission in flight now holds the flag row until it commits. The transition's freeze `UPDATE infrx.feature_flags` therefore waited on it (Lock/transactionid) with no bound. In the straddle case the admission is parked on `infrx.credit_holds`, so the run never returned. This is the 76-minute hang in the D10 merged-tree cross-track run.

**Fix** (`infrx/operations/transition.py`). `PgTransition.set_flag` runs its UPDATE in a transaction with `set local lock_timeout = <ms>`. The ms value is `max(1, …)`, because PostgreSQL reads 0 as no limit. It maps SQLSTATE 55P03 to a new `FlagLocked`. `apply` computes the deadline before the freeze and passes the drain's remaining bound to every flag write (the freeze and the enables). `FlagLocked` becomes the existing `open_transactions` refusal: exit 1, the flags already changed stay, nothing else is applied and nothing is audited. The `pg_locks` wait after the freeze is kept for schemas without the FOR SHARE read. D10's DB-side guard is unchanged.

On the D10 schema a straddling admission now blocks the freeze itself, so the refusal reports `applied: []` with the source flag still on. The earlier behaviour (freeze committed, then wait) was pre-D10. This is stricter and consistent with R117: bounded wait, then `open_transactions`, with nothing enabled and nothing audited.

**Tests.**
- `tests/g/ops/test_transition_pg.py::…an_admission_open_across_the_freeze_is_waited_for`:
  - the CLI now runs in a daemon thread with a hard `HARD_S = 30` join, so a regression fails instead of hanging (`pytest-timeout` is not pinned);
  - the assertions are now `applied == []` and `legacy_usd_admission` still true.
- New fake-level case `test_credit_cutover__a_flag_an_admission_holds_is_waited_for_within_the_bound` (`tests/g/ops/test_transition.py`). It checks that every flag write gets a finite bound ≤ the drain timeout, and that a locked freeze or a locked enable refuses with `open_transactions`, keeps what it applied and audits nothing. `ScriptedStore.set_flag` now takes `lock_timeout_s` and a `locked` set.
- Mutants (`tests/g/ops/mutants.py`):
  - new `flag_lock_unbounded` (the bound becomes `inf`) and `flag_lock_timeout_unmapped` (`FlagLocked` escapes; declared `dies_by`);
  - `freeze_skipped` and `freeze_only_still_enables` were re-anchored to the new code.
