# E3L-F1 — `/v1/models` projects the catalog's own listing version

Lane e3l-f1 (LW3, no plan entry: brief = coordinator notes + wave5-plan.md §2/§5 COMMON).
Branch `codex/w5-e3l-f1`, worktree `.claude/worktrees/codex-w5-e3l-f1`, base `ad828a2d`.
The defect (`E3L-BIND-bab9b18.md`, cell l05b): `infrx/gateway/routes/models.py:64` hardcoded
`LISTING_VERSION = 1`, so a consumer read `listing_version: 1` for every deployment
`GET /v1/models` served, even after a Lab publication or rollback moved the alias to a later
listing.

## Fix, at the root

- `infrx/state/catalog.py`: `PgCatalogDirectory.listing_version(deployment_revision_id)` —
  not part of the frozen `CatalogDirectory` protocol, read via `getattr` exactly like
  `usd_price` (G7 WR-3a). Backed by `max(catalog_listings.version)` for that deployment
  revision at the database clock: the newest listing naming it (R195 — an alias's listing is
  the newest one naming its deployment; a rollback relists an older revision at a new,
  higher version, so this is `max`, never the row's own version).
- `infrx/contracts/conformance/v2_fakes.py`: `FakeCatalogDirectory` gets the same method over
  a new append-only `listings: list[(alias, version, deployment_revision_id)]` log, mirroring
  `infrx.catalog_listings`. `move_alias` now appends the next version for that alias instead
  of only overwriting `aliases`, so a second `move_alias` on the same alias (a republish or a
  rollback) is listing 2, listing 3, ...
- `infrx/gateway/routes/models.py`: `catalog_rows`/`publish` thread the resolved
  `listing_version` through `pm.project` instead of the retired `LISTING_VERSION` constant.
  A catalog with no `listing_version` reader at all (not every stand-in has one) falls back to
  `_UNKNOWN_LISTING_VERSION = 1`, the pre-fix behavior, rather than crashing `/v1/models`; the
  real and fake directories both implement it now, so this only guards a caller this lane does
  not own.

No frozen contract changed: `CatalogDirectory` (`contracts/v2/ports.py`), `DeploymentRevision`
and `PublishedModel` (`contracts/v2/records.py`, `published_model.py`) are untouched. The
consumer-visible field name, type, and `/v1/models` ordering are unchanged.

## Fail-first

- `tests/g/test_catalog_truth.py::test_catalog_truth__discovery_reports_the_listing_version_it_serves`
  publishes the seeded model, asserts `listing_version == 1`, republishes the same deployment
  (a second `move_alias`, listing 2), asserts `listing_version == 2`. Verified RED against the
  base (`ad828a2d`)'s `models.py`/`catalog.py` (`assert 1 == 2`), GREEN after the fix.
- `tests/d/test_catalog_pg.py::test_credit_rate__listing_version_is_the_newest_listing_naming_the_deployment`
  (real PostgreSQL, `RigCatalog.publish` inserting a real `catalog_listings` row at
  `version + 1`, the same helper `credit_rate__a_rate_published_after_acceptance_does_not_move_the_job`
  already exercises against this adapter). Verified RED against the base (`AttributeError:
  'RigCatalog' object has no attribute 'listing_version'`), GREEN after the fix.
- `tests/g/mutants.py`: new mutant `listing_version_ignores_resolution` reverts the fix's
  `if resolved is not None:` guard to `if False:` (the constant wins again), named by the new
  `test_catalog_truth__...` case. Verified killed (below).
