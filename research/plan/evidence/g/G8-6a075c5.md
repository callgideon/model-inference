## What was built

**Point 1: trusted operations.** `account --user` (operator read) returns the verified individual's personal consumer account. It resolves from the v2 identity: the organization the individual created and owns, with the wallet read through its frozen binding. It never uses the first membership. The response carries exact CREDIT strings (`ledger_total`, `reserved_total`, `available`, `spent`), the holds, the per-unit usage totals (R73) and the suspension code. `statement --key-file` returns the credential's own view, the same DTO. `spent` is the CREDIT usage total. When `usage_records`' 500-row page is full, it answers `None`/`spent_complete: false` rather than a short sum (ponytail; D10.c's settled-debit read replaces it). Operator writes are audited under 0009's dedicated actions: `admin_key_issue`, `admin_key_revoke`, `admin_publish`, `admin_job_cancel`, `admin_reconcile` and `admin_adjust`. G6B had filed four kinds of write under `admin_set_entitlements`/`admin_grant`. Onboarding, key issue/revoke/rotate (plaintext shown once; a lost response means rotate), suspension, cancel and reconcile are G6B's, reused.

**Point 2: the transition** (`infrx/operations/transition.py`). Only three flags move: `legacy_usd_admission`, `credit_admission` and `signup_grant`.
- **Inventory**: one repeatable-read, read-only snapshot as `service_role`. It covers the flags, jobs in flight per regime, `held_unknown` counts per regime and held/unknown holds per unit. It reads every organization's legacy USD statement through C0's `console_legacy_usd_statement`, the USD wallets' `available`, the USD usage-event count, CREDIT wallets by kind, CREDIT ledger sums by kind and entitlements. It includes both reconciliation views' drift. It lists every rate card with its pinned-job count and `named_by_listing`, plus the effective listing of the public alias. It lists every API key's id, prefix, audience, org, created, revoked and last-used; never the hash or plaintext.
- **`apply`**: refuses hard blockers before any change. Otherwise it freezes the source regime's admission flag, then drains with a bound (`--drain-timeout-s`) until the source has nothing preparing, queued or running. It then enables the target's flags and rechecks. The run is audited once under its idempotency key (`admin_set_entitlements`, operation `transition`, target org NULL). A blocked run audits nothing, prints the report and exits 1. The freeze stays in place and a rerun continues.
- **`--to legacy_usd`** is the mirrored rollback. **`--freeze-only`** stops after the drain with both regimes paused: the window in which D10's runtime cutover wants admission paused.
- **Never**: a converted balance, a relabelled USD row, a rewritten card, or a job that changes regime. The report names the restart environment (`ACCOUNTING_REGIME`, `ACTIVE_RATE_CARD_VERSION`); the coordinator applies it.

**Point 3: approved rates (P-01).** Moving to `credit` requires `--card`, `--input-rate` and `--output-rate`. The card must be published and not provisional. The DB flag and the approval text are both checked: text containing `P-01`, `provisional` or `pending` is refused. The card must be the one the public alias's effective listing names (F2C-C's single public rate identity), at exactly the restated rates, compared as exact CREDIT. `publish-card` publishes an approved card additively for the deployment the listing serves and moves the listing to it. It never publishes a per-release minted id and refuses a provisional approval. `--dry-run` needs no operator key and writes nothing. It prints the inventory, `would_change`, `blockers`, `restart_with`, `public_card` and notes, and exits 0 only when activation would go through now. Fixture rates exist only in tests, labelled `FIXTURE-G8 … (not a launch price)`.

**Point 4: races and retries.** `_once` previously surfaced the audit relation's raw 23505 `Conflict` when a same-key twin had recorded first. It now answers the recorded result, or `idempotency_conflict` for a different request. The write itself is deduped by the deterministic operation id, and nothing is retried. Every other refusal is the store's typed error, unchanged.

## Wiring requests

1. **D10 (SQL): lock the flag an admission read.** `infrx.require_feature` reads `infrx.feature_flags` without a lock, so an admission that passed the check just before a freeze committed can commit a job after the drain measured zero. `apply`'s final recheck and the "rerun `--dry-run` before restart" step are the interim guard. Patch, as a new migration after D10's:
   ```sql
   create or replace function infrx.require_feature(p_name text) returns void
   language plpgsql volatile security definer set search_path = infrx, public, pg_temp as $$
   begin
     if not coalesce((select f.enabled from infrx.feature_flags f
                      where f.name = p_name for share), false) then
       raise exception 'maintenance: % is not enabled', p_name using errcode = '55000';
     end if;
   end $$;
   ```
   The body must be `volatile` for `FOR SHARE`; D10 must check the callers `resolve_admission_pins`/`jobs_admission_guard`, and the lock order places the flag first. Proving test (two connections): connection A starts `infrx.admit` and pauses after `require_feature` (an advisory lock, or `pg_sleep` inside a test hook); connection B's `update infrx.feature_flags set enabled=false where name='legacy_usd_admission'` must wait for A. After B commits, `transition.inventory()` counts A's job in flight.

## Proposed ruling text (numbers for the coordinator; F2C-C proposed R109)

- **Transition.** A regime transition moves only the admission flags. It freezes the source regime's flag, drains until no source job is preparing, queued or running (bounded; a blocked run keeps the freeze and audits nothing), then enables the target's flags, and is audited once under its idempotency key. The target is CREDIT only with an operator-approved card: not provisional, with no `P-01`, `provisional` or `pending` in its approval, named by the public alias's effective listing, at rates the operator restates exactly. No balance is converted, no USD row relabelled and no card rewritten; every job settles in its admitted regime and at its pinned card or price version.
- **Races.** An operator write whose idempotency key was recorded concurrently answers the recorded result, or `idempotency_conflict` for a different request, never the audit relation's unique violation. The write is deduplicated by the deterministic operation id, and nothing is retried.
