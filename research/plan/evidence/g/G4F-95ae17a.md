## Behaviour
`POST /v1/feedback` body `{request_id, name, value, comment?}` (frozen `wire.FeedbackSubmission`, R3/R43) + `Idempotency-Key`:
1. identity first (`AuthResolver`; unknown/missing key → 401 before any body parse); JSON content type; body bounded at 128 KiB (largest legal signal escaped = 96 KB).
2. `FeedbackSubmission` (extra=forbid): any provenance field (author_role/author_principal/channel/org_id/calibration_set/by_operator/rubric_version) → 400 before the service; `calibration_label` refused (R43).
3. `Idempotency-Key` required (400 `param=Idempotency-Key`), bounded/storable via `validate.idempotency`; scope `(key org, "feedback", key)`, payload digest = sha256 of the canonical (compact, sorted) submission incl. `request_id` (same signal re-spelled replays; another value or request conflicts).
4. `service.accept(auth_from_key, request_id, {name,value,comment}, idem)` — author/org are the key's (R31); ownership/suspension/replay/flag are D6F's SQL.
5. 201 `FeedbackAccepted` rendered from the returned row only after `accept` returned; every refusal is the typed error (503 flag off, 404 foreign/unknown, 409 conflict, 403 suspended); `Inference-Id` = this call's id. No financial logic.
