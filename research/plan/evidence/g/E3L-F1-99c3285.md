# E3L-F1 — `/v1/models` projects the catalog's own listing version

Supersedes [E3L-F1-c728ba9.md](E3L-F1-c728ba9.md) (kept as written; this directory is
append-only) — that head's design put the listing-version tracking in the frozen
`FakeCatalogDirectory`, which a full `make api-test` run showed breaks F3's freeze pin. This
file is the corrected, fully-verified state.

Lane e3l-f1 (LW3, no plan entry: brief = coordinator notes + wave5-plan.md §2/§5 COMMON).
Branch `codex/w5-e3l-f1`, worktree `.claude/worktrees/codex-w5-e3l-f1`, base `ad828a2d`. Code
head `99c32850`.

The defect (`E3L-BIND-bab9b18.md`, cell l05b): `infrx/gateway/routes/models.py:64` hardcoded
`LISTING_VERSION = 1`, so a consumer read `listing_version: 1` for every deployment
`GET /v1/models` served, even after a Lab publication or rollback moved the alias to a later
listing.

## Fix, at the root

- `infrx/state/catalog.py`: `PgCatalogDirectory.listing_version(deployment_revision_id)` —
  not part of the frozen `CatalogDirectory` protocol, read via `getattr` exactly like
  `usd_price` (G7 WR-3a). Backed by `max(catalog_listings.version)` for that deployment
  revision at the database clock: the newest listing naming it (R195 — an alias's listing is
  the newest one naming its deployment; a rollback relists an older revision at a new, higher
  version, so this is `max`, never the row's own version).
- `infrx/gateway/routes/models.py`: `catalog_rows`/`publish` thread the resolved
  `listing_version` through `pm.project` instead of the retired `LISTING_VERSION` constant.
  A catalog with no `listing_version` reader at all falls back to
  `_UNKNOWN_LISTING_VERSION = 1`, the pre-fix behavior, rather than crashing `/v1/models`.
- `tests/g/support.py`: a new `ListedCatalog(FakeCatalogDirectory)` test-owned subclass
  carries the `listing_version` reader and an append-only `listings` log for the test suite's
  fake catalog, and overrides `move_alias` to append to it (a republish or a rollback is the
  next version, mirroring `infrx.catalog_listings`). `support.catalog()` now builds one of
  these instead of a bare `FakeCatalogDirectory`.

No frozen contract changed: `CatalogDirectory` (`contracts/v2/ports.py`), `DeploymentRevision`
and `PublishedModel` (`contracts/v2/records.py`, `published_model.py`), and
`infrx/contracts/conformance/v2_fakes.py` itself are all untouched at this head (see the
correction below). The consumer-visible field name, type, and `/v1/models` ordering are
unchanged.

## A wrong turn, caught and corrected

`c728ba92` (this lane's first commit) put the `listings` log and `listing_version` directly on
`FakeCatalogDirectory` in `infrx/contracts/conformance/v2_fakes.py` — the file the brief calls
"the catalog port's fake", and the same file `usd_price` (G7 WR-3a) was once added to the same
way. That precedent turned out not to generalize: `tests/contracts/lab/frozen_contracts.json`
(F3's freeze, `test_lab_existing_frozen_contracts_are_byte_identical`) pins every file under
`infrx/contracts/` (`v2_fakes.py` included) byte-identical to the F3 base `9a6c3685`. `usd_price`
predates that pin; my edit did not. This was invisible to every check this lane ran except the
one that iterates the whole tree: `make api-test` at head `c728ba92` (1:26:33, contended) came
back **16 failed** — `test_lab_existing_frozen_contracts_are_byte_identical` plus 8
`tests/contracts/lab/test_mutants.py` cases (`broken_runner: pristine baseline fails`, all
downstream of the same pin mismatch), and 7 `tests/d/test_outbox_relay.py[valkey]` failures
(unrelated — see below).

Root-caused (the diff was exactly one file: `v2_fakes.py`'s new hash did not match the pin's),
reverted `v2_fakes.py` to byte-identical (confirmed: `git diff ad828a2d -- .../v2_fakes.py` is
empty, and the pin test passes again), and moved the same tracking into
`tests/g/support.py` — an owned path, never pinned — as a subclass instead of an edit to the
frozen class. `tests/contracts/lab/` went from 9 failed to **75 passed**; the fail-first case,
the PG case and the named mutant are unaffected (still red-then-green / killed) because nothing
about the fix's *interface* changed, only which file implements the fake's tracking.
