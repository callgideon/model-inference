## Fix round, 2026-09-28 (finding 1-LO-1; code at `9a5bf310`)

**Finding:** WR-I2L-1 as first written was incomplete. `lib.sh edge_install` validates each App
Caddyfile alone: it mounts only `$src/$f` at `/etc/caddy/Caddyfile`, so the Lab import glob
matches nothing during validation. The running edge mounts all of `$CADDY_DIR`, so an installed
`/etc/caddy/lab/lab-control.caddy` is loaded there. An App release or a `CADDY_IMAGE` bump that
conflicts with an installed Lab site would pass validation. It would then fail the reload, or,
after `docker rm -f caddy`, fail to start the new edge container, leaving App inference unrouted.

**Fix (tests first).** The new case is
`test_i2l__an_app_release_that_conflicts_with_the_installed_lab_site_never_replaces_the_edge`. It
runs the real `edge_install` in bash under a sandbox `INFRX_ROOT` that already has the Lab site
installed. A docker shim sends the validation to the real pinned Caddy and records the edge
calls. There are three scenarios:

- An App release that claims the Lab site's address, with the same image running (the reload path).
- The same release with a different image running (the `rm -f` + `run -d` path).
- A release that composes with the Lab site.

In the first two, the release must stop at exit 4 with no `exec`/`rm`/`run -d` call, and the
running edge files must be unchanged. The third must install and reload.

- Red against `lib.sh` as it stands: validation passed and `docker exec caddy caddy reload` was
  issued (`E3L-raw-fixround/i2l-edge-conflict-red.log`, exit 1).
- Green with WR-I2L-1's lib.sh half applied. Like `composed_main()`, the test applies the change
  in memory until the coordinator lands it, and it fails loudly if the anchors move.
