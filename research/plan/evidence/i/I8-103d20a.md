## Proposed rulings (next free R109)

- **R109 — service, not readiness.** A rollback, restore or replacement passes only when a
  fresh public in-cap video job is accepted, succeeds, returns content with authoritative
  usage and settles with no wallet drift, after the change and after its reversal. `/readyz`
  timings are labelled readiness-only and never reported as a cold start. A rollback target
  is chosen by its tree (preparation loop, applied migrations, config schema), its recorded
  evidence and its release bundle — never by the presence of a backup directory.
- **R110 — pooler discipline.** An install's knobs must PASS `pool_budget.py` for the pooler
  mode the runtime uses; runtime connections on the transaction pooler carry no session
  state (no SET/RESET, session advisory locks, LISTEN, temp tables) and no server-side
  prepared statements; migrations and dumps use the session port inside a maintenance window.
- **R111 — the env file is versioned.** A runtime unit starts only on an env file written for
  its image's schema (`# INFRX_ENV_SCHEMA`), with no name outside it.
