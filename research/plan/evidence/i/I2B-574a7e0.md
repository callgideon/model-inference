command, no hosted SQL. Row `O-FAILOPEN` still describes the box. The rollout is

   engine-pin refusal is live here; W3's pinned `serve.sh` passes this gate unchanged (command 7).
3. **The rehearsal is dev mode on a stand-in host.** It proves the scripts, units, image, edge,
   Valkey and migrations behave as specified with the real binaries; it does not prove systemd's
   own behaviour (a mini-systemd runs the Exec lines), host networking on the box, TLS/ACME,
   IMDS, the instance role, the GPU engine, or anything about hosted Supabase. `systemd-analyze
   verify` covers unit syntax only.
4. **Box facts assumed, to be confirmed by `10-inventory.sh`:** Docker with buildx
   (`--provenance`), root on SSM, the Caddy volumes named `caddy_data`/`caddy_config` (so the
   certificates survive the edge's recreation), and a `git fetch` that works from the box.

   resolves across processes, the worker may have to run inside the gateway; then
   `infrx-worker.service` goes and the gateway unit's stop budget becomes 330 s (a two-line change).

   engine container) therefore see `SUPABASE_SERVICE_ROLE_KEY`; splitting it needs a worker that
   validates without it (W3) — noted, not done.
7. **Valkey on loopback has no password.** Anything on the host can reach 127.0.0.1:6379; the
   index holds job ids and costs, no content.
8. **Budgets are `est.`**: memory/CPU/pid caps and the disk budget are engineering estimates
   (infra/README.md §2), ⚠️ TO BE VERIFIED by E1B/I3B measurement.
9. **The image id is reproducible per host, not across hosts**: the same commit on the same
   builder cache gives the same id (provenance off), but layer timestamps differ elsewhere; the
   box's id is recorded at rollout.

   (the CLI splits statements) and assumes the CLI's versions are the files' `NNNN` prefixes; a
   mismatch makes `plan` refuse, which is the safe direction, and is checked read-only first.

   (51 GiB free on the media path's filesystem).
