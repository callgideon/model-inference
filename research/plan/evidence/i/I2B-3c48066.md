**Deviation from the dispatch, stated:** FC-1 asked for the worker unit's
`TimeoutStopSec=330`. W3's proposal was for a host-process unit, where `TimeoutStopSec` *is*
the drain bound. This worker is a `docker run` client: the drain bound is `docker stop -t 330`
(one generation, 300 s, plus 30), and systemd must outlast docker or it kills only the client
while the container keeps running — the invariant
`test_ops_recover__every_container_unit_stops_later_than_docker_does` pins (`worker_killed_before_drain`).
So the unit keeps `docker stop -t 330` / `TimeoutStopSec=360`, and gains W3's
`KillSignal=SIGTERM` / `KillMode=mixed`. Also not done literally: "preflight TUNABLE gains
PROCESSING_CACHE_DIR" — it is already a **manifest** key (written with the default
`/opt/dlami/nvme/processing` in every mode); listing it as a tunable too would break the
schema partition `test_backend_deploy__the_config_schema_is_every_name_the_runtime_reads` pins.
