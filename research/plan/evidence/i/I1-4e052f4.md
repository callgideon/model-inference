Every classification below is one of exactly these five kinds. The first three are
the primary classes; `DERIVED` and `CORRECTED` are qualifiers on an observation and
always name their source. A row may carry **more than one** class where its parts
have different provenance — several do, among them `O-ISTORE`, `O-G6E`,
`O-SMTPUSER`, the §4 "Ledger, holds, wallets…" row and the §4 table's
"OBSERVED via unit" cells beside PROPOSED targets — and in that case the row
labels each part, never the row as a whole (no count is given, because any later
pass that splits a row would falsify it):

- **OBSERVED** — either a command in §Commands returned it at the stated UTC
  time, or it is directly readable in the checkout at `25b9829` and the row says
  so instead of a time ("OBSERVED in the checkout", "OBSERVED via unit",
  "OBSERVED in gateway"). The second form has no §Commands row by design: its
  reproduction is `git show 25b9829:<path>`, not an AWS call.
- **HISTORICAL CLAIM** — asserted in `HANDOFF.md` or `CLAUDE.md` and **not**
  re-observed here, or re-observed and contradicted; each row says which.
- **PROPOSED** — does not exist; a later task must create it.
- **DERIVED** — not returned by any command; concluded from named OBSERVED rows,
  which the row cites. It is never a fourth kind of fact: the underlying
  observation is in §Commands, the inference is the row's own.
- **CORRECTED** — a row that an earlier revision of this report stated wrongly
  and that has since been re-observed. It carries the new OBSERVED time, says
  what the old claim was and why it was wrong, and the §Verification log records
  the correction. Nothing is silently overwritten.

A row whose class changed because a later pass observed what an earlier pass had
not says so inline ("OBSERVED … — was HISTORICAL CLAIM"); that is a class change,
not a correction, and the §Verification log records it too. `est.`,
`meas.` and `⚠️ TO BE VERIFIED` are the separate `CLAUDE.md` labels for values,
not classes of fact, and are used as that file defines them.

**Row ids and the single source of truth.** Every row in §2, §3 and the §5 matrix
that either document cites carries a **stable id** in its first cell: `O-…` for an
observed-state row, `M-…` for a required-vs-existing matrix row. The id is the
citation handle and does not change when the row's wording does.
**All observed facts live here**, with a command and a UTC time in §Commands;
`infra/README.md` is the design and cites these ids instead of restating what a
command returned, so a value exists in exactly one place and the two documents
cannot drift on it. Where that file still names an identifier it is about to
operate on (an instance, ENI, role or parameter name), it names the id beside it.
