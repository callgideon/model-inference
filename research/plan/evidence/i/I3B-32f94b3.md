## What was built

**(a) `apps/infrx-api/infrx/observe/`** (stdlib only; the pinned env has no Prometheus or
OTel client):

- `metrics.py` - a per-process `Registry` rendering Prometheus text 0.0.4; 30 declared
  families covering the E1B phases (`infrx_phase_seconds{phase}` with exactly
  `retrieval, decode, prepare, queue, prefill, generate, journal, persist, settle`),
  saturation/rejections, accepted and terminal outcomes, settlements, lease loss, reaper
  actions, reconciliation, components, host/memory/disk/GPU, build revision. **Sanitized by
  construction:** every label is a closed vocabulary (contracts enums or a short pattern);
  anything else is written `other` and counted in `infrx_metrics_label_rejected_total`;
  `tenant` is always a 12-hex sha256 prefix, never the id; bad numbers are dropped and
  counted. `server_timing()` renders the header from the same mapping the histogram
  records. Wiring helpers for the owning tracks: `record_outcome`, `record_recovery`
  (distinguishes an aged unknown-usage release from a new terminalization), `record_queue`,
  `record_reconciliation`, `write_textfile` (for processes with no HTTP listener).
- `host.py` - CPU/load/memory/RSS from `/proc`, disks by configured mount name (an
  unreadable mount reports free ratio 0, towards the alert), GPU via `nvidia-smi`.
- `route.py` - `register(app, rt)` mounting `GET /metrics` for a **direct loopback** peer only
  (loopback address and no proxy header); anything else gets the byte-identical 404 of an
  unknown path.
- `alerts.py` - evaluator for rules-as-data (`python -m infrx.observe.alerts --rules ...
  --source URL|FILE --state FILE`): exit 1 when anything fires, an unreadable source is itself
  the `ScrapeFailed` alert.

**`infra/alerts/alerts.json`** - 20 rules, each with severity, runbook section and a
`threshold_status` saying where the number comes from (contract limits, E1B provisional
criteria, or `⚠️ TO BE VERIFIED (P-18)`). **`infra/alerts/dashboard.json`** - seven rows,
every family on a panel.

**(b) Drills** in `tests/integration/backend/recovery/` (the backend stage of
`run.py --layer 3` collects them; nothing forked): `recoverykit.py` (the world a drill runs in
and the `reconcile()` oracle), `test_recovery.py` (rc01-rc10), `test_restore.py` (bk01-bk04).

**(c) Runbooks** `infra/runbooks/{README,restart,restore,rollback,disk,index-loss,reconcile}.md`,
every box step an SSM-runnable, base64-wrapped `bash` block (they all parse: rb04), and
**`infra/runbooks/pgrestore.py`** - the backup/restore/check tool `restore.md` runs against
hosted and bk01/bk02 drill locally (same code, same flags, same pinned client image).

## Findings

1. **A plain `pg_restore` of a Supabase project widens browser privileges** (bk01, measured):
   the template's default privileges for `postgres` in `public` grant ALL to anon/
   authenticated/service_role on every new object, pg_dump writes grants as a difference from
   the built-in default, so the restored `public.api_keys` had `anon=arwdDxtm`. Also: the
   template's `public` schema breaks `--exit-on-error`, the signup trigger on `auth.users`
   and 0004's global function default are outside a schema-scoped dump, and a re-parsed CHECK
   deparses with its AND chain flattened. `pgrestore.py` handles all of them and bk01/bk01b/
   bk01c/bk01d prove the check catches each. **Anyone restoring hosted by hand without this
   would ship an open `api_keys` table.**
2. **`ProcessingCache.put` leaves `{path}.{pid}.part` on a failed write** (rc07: 1 file on the
   full disk) - M.
3. **`JobStore.recover()` returns an aged unknown-usage release as a `TerminalOutcome`
   indistinguishable from a new terminalization**, and a reaped preparation lease is
   outbox-only (not returned). A reaper that counts the return value double-counts terminal
   jobs; `record_recovery(released=...)` takes the caller's knowledge meanwhile - D3/D5.
4. **An interactive job's 10 s queue budget expires inside any restart**: a worker/host loss
   longer than 10 s fails queued sync/stream jobs `queue_wait_expired` (free). Correct per
   contract; the drills use async jobs and the runbooks say so.
