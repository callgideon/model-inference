## Failure drill

- **Injection point:** `services.failNext("usage", "dependency_unavailable")` and
  `failNext("ledger", "dependency_unavailable")` — the fake's documented pre-write injection.
- **Durable state before/after:** U1 has none. It performs read operations only; it creates no server
  action, no mutation and no migration. The drill's assertion is the read equivalent: after the
  injected failure, the same query returns a result deep-equal to the successful call before it
  (U1-T06), so the failed read changed nothing and the retry the page offers actually works.
- **Duplicate/retry behaviour:** the "Try again" affordance is a plain anchor to the current URL (a
  fresh server request) and "Back to the first page" is a link that drops cursor and trail; neither is
  a mutation, so a double-click cannot double-apply anything. The retry/restart choice comes from the
  error code (`recoveryFor`), tested in U1-T06 and U1-T05.
- **Cleanup:** nothing to clean. Each request builds a fresh fake; the mutation runner works on a
  temporary copy under `$TMPDIR` and removes it (`--keep` to retain), leaving the source untouched —
  `git status` is clean after a run.

## Limits

- **Fixtures, not a real service.** Every result above is "implemented", never "integrated". The
  pages read `createFakeConsoleServices()` through one seam

  is computed against `2026-09-20T12:00:00Z`. Owner: C1 (real services) + coordinator (the swap).
- **Session is the fixture owner session.** The pages do not call `getSession()`; tenant resolution
  through real auth is C1's, and until then no role, member or suspended-organization view is
  exercised against a real session. Owner: C1. The suspended-organization *read* path is available in
  the fake (`sessions.suspendedOwner`) but is not yet wired to a page, because the page has no way to
  choose a session — deliberately left for the integration, not silently faked.
- **Model filter options come from the visible page.** `ConsoleServices` has no model-catalogue read,
  so the model select offers the models on the current page plus the active selection. A filter for a
  model absent from the page must be typed into the URL. Marked in the code; the lazy alternative to a
  contract revision. Owner: U (revisit in U2) or C1 if a catalogue read is added.
- **The cursor trail rides in the URL.** A deep walk makes a long URL (~60 characters per page with
  the fixture's cursors, and a real implementation's signed cursors will be longer). Marked
  `ponytail:` in `view-model.ts` with the upgrade path (server-side page token). Owner: U.
- **No total page count**, by construction: an opaque keyset cursor knows neither the total nor the
  last page, and counting the table on every page view is the thing keyset pagination exists to avoid.
  The pager shows "Page N" with First/Previous/Next.
- **Browser behaviour is unverified here.** Keyboard traversal, focus order, screen-reader output and
  the absence of a payment control in the rendered DOM are asserted only at the view-model and markup
  level (links and native form controls, `aria-label` on each select, `aria-disabled` on a spent
  direction, `aria-busy`/`sr-only` on the loading state). No browser was started. Owner: E (see
  Handback).
- **`components/credits-card.tsx` and `lib/credits.ts` are now unused** by any page but were not
  touched — they are outside U1's owned paths. Owner: coordinator (see integration requests).
- **`make api-test` not run** (no Python change), `make bench-test` not applicable. Neither is a pass.

## Disposition

### B1 — prototype-chain crash at the trust boundary: **fixed**

`range in RANGES` was true for every `Object.prototype` member, so `?range=toString` produced
`now - <function>` = `NaN`, and `new Date(NaN).toISOString()` throws: one query parameter for a dead
page. Fixed at the root and swept:

| Lookup | Before | After |
|---|---|---|
| `parseUsageFilters` range allowlist | `range in RANGES` | `isRangeKey()` → `Object.hasOwn(RANGES, value)` |
| the range-table read itself | `RANGES[filters.range]` | `rangeMs()` → `Object.hasOwn` with the default as fallback, so a key from *any* caller (not just the parser) is safe |
| `explainError` hint table | `HINTS[code]` | `Object.hasOwn(HINTS, code)` |
| `recoveryFor` status table | `ERROR_CODE_HTTP_STATUS[code]` | `Object.hasOwn(...)`, and `undefined` is treated as "no status" |
| `ledgerKindLabel` (billing) | already `Object.hasOwn`-guarded in round 0 — unchanged, now asserted | |
| `settlementView` switch | exhaustive per the type; an out-of-vocabulary value returned `undefined` and crashed the markup | `default:` branch returning a row that says "Unknown … nothing is presented as charged" |

Swept and found clean: no other bracket lookup keyed by an untrusted string exists in either view
model or either page; `keyId`/`model`/`cursor`/`trail` are only ever compared or passed as values.

New cases: **U1-T13** asserts eight prototype keys (`toString`, `__proto__`, `constructor`,
`hasOwnProperty`, `valueOf`, `isPrototypeOf`, `propertyIsEnumerable`, `toLocaleString`) fall back to
the default range and produce a parseable `from`; that a *forged* range key reaching
`usageScopeQuery` directly does not throw (`assert.doesNotThrow`, because `RANGES.__proto__` is an
object and `now - object` is `NaN`); that an unknown error code yields the fallback message and
`recovery: "none"`; and that an unknown settlement state returns a view rather than `undefined`.

Route-level error states: `usage/error.tsx` and `billing/error.tsx` (client error boundaries with a
`reset` control, showing no text from the thrown error — a thrown error can carry internals) and
`billing/loading.tsx` to match the usage route's existing loading skeleton.
