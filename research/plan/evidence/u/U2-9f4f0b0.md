## Brief items → where

1. **Key issue/copy/revoke UI on C3A actions.** Create and revoke go through `@/app/actions` (C3A `consoleActions`: Origin check, server-resolved context, allowlisted input, fixed error text, revalidate only after an ok result). Creation is offered only to a `ready`, unsuspended individual. Each other state has its own reason: unverified, onboarding, unavailable, signed out, suspended. A suspended individual keeps the list and can still revoke (R33).
2. **Metadata.** Each row shows the name, the stored prefix plus `…` (never more of the key), created and last-used times in UTC ("Never" when unused), and a Revoked badge with its time as the title. Only active keys offer revoke.
3. **One-time plaintext and lost-key rotation.** The secret appears only for a first, non-replayed response (R16). A replay shows `REPLAYED_COPY` and never a secret, even if one were carried. The secret is never stored, logged, placed in a URL or sent anywhere. The copy tells the individual it cannot be shown again and gives the rotation steps: create a new key, switch, revoke the old one. The Models snippet's leftover `recallKey` read is WR-U2-2.
4. **Revocation must fail real admission within the documented bound.** This backend property is proven where it lives; U2 adds no second mechanism. The chain:
   - The App revoke sets `api_keys.revoked_at` on the individual's own `(id, org_id, audience=consumer)` row. C3A's real-DB case shows this through PostgREST v13 and real RLS (`tests/c/actions-postgrest.test.ts`).
   - Admission re-reads the key in SQL: `infrx.admission_checks` requires `k.revoked_at is null`, else `invalid_api_key` (`apps/app/supabase/migrations/0011_admission.sql`). The D-lane real SQL case is `tests/d/checks_admission.py` "a revoked key" → `invalid_api_key`.
   - Read routes stop within `KEY_TTL` = 60 s (R131). I ran `apps/infrx-api/tests/g/jobs/test_revocation.py` here: 1 passed.
   - The copy the individual sees is P-26's decided text verbatim (the same sentence A3 publishes). The confirm dialog says new requests are refused immediately. The old "Calls using it start failing within a minute" copy was wrong and is removed.
5. **Privacy wording reflects real serving retention.** The Settings "Serving retention" row says content (request body, source video, prepared frames, result, streamed output) is stored for limited periods and states "This is not zero data retention." It links to `/docs#retention`, where A3 renders each period from the published record (P-25 TTLs). The figures are not repeated here, so the two pages cannot disagree.
6. **No trace-sharing/annotation consent until the permission and deletion path exists (P-09).**
   - "Trace capture: Off" is stated as not available to turn on. It says capture does not change what serving stores.
   - "Sharing, annotation, evaluation and training: Not offered" says signing up grants none of these and no setting grants one.
   - "Data export and account deletion: Not available" points to support by e-mail.
   - None of these is a toggle, and `U2-S04` fails on any checkbox, switch, form, `onChange` or client/server-action directive in `settings/`.
7. **Keyboard, mobile and secret redaction.**
   - All controls are native buttons or links, and Base UI Dialog handles focus trap and Escape. Icon-only buttons have `aria-label`, and the name field has a `<Label htmlFor>` (`U2-S05`). The table container scrolls horizontally on narrow screens. Status and alert roles are used for unavailable and error states.
   - There is no DOM or browser test stack; the E2E console suite is pending under lane E (`tests/e2e/discovery.test.ts`). Keyboard and mobile access is therefore checked from source and by lint, not by a browser run. No screenshot was taken.
   - Redaction: `U2-S01` bans console logging, browser storage, URL or query use, `fetch`/beacon and analytics SDKs in the keys and settings sources. It also caps references to `secret` in the dialog. The app has no analytics or error-reporting SDK (grep over `app`, `components`, `lib`).
   - After `next build`, no `.next/static` chunk contains `SUPABASE_SERVICE_ROLE_KEY`, `CONSOLE_CURSOR_SECRET`, `claim_signup_grant` or `key_hash`.
   - The one plaintext-handling code left in the browser bundle is `recallKey` in `components/snippet.tsx`. It is a read-only leftover, and nothing writes that storage any more. WR-U2-2 removes it.
