## 7. Proposed rulings (coordinator numbers them)

The handoff §9 texts stand (readiness one-phase; a refusal binds no idempotency key; PostgreSQL decides deletion; discovered orphans; persisted expiry is the only read authority; dedicated logins). Added this round:

- **Pre-admission refusal / idempotency (restated for the rulings list):** any refusal raised before the admission transaction commits - validation, readiness, capability, price, wallet, capacity, regime flag - leaves no job, hold, reservation, outbox or idempotency row; the same key may be retried after the cause is fixed and then replays that job; a keyless or late-key retry of a committed request UUID is `state_conflict` (409) in BOTH regimes.
- **Discovery prices what admission charges:** a published USD price is read through the same resolve-then-price rule (`infrx.usd_price`) admission uses at the same database instant; a model string admission would refuse shows no price.
- **Object keys have no dot segments:** a content key containing a `.` or `..` path segment is refused by the database (retained and reported, never registered), whatever the store's normalisation.
