## Design
- **D7.a (DATA-IMMUTABLE, DATA-RIGHTS).** `lab_records`: every referable F3 record (dataset, harness, run, checkpoint, annotation, external_run, policy, variant) stored as its RFC 8785 bytes; the CHECK `lab_records_content_addressed` re-derives the sha256 from the stored bytes, so the stored ref is `records.ref_of` (asserted) and changed bytes can never redefine a ref. One row per (kind, provider, object, version): same bytes = same ref (replay), other bytes = `state_conflict`; the unique index serializes racing publishers. Every declared ref (keys `*_ref`/`*_refs` outside OPAQUE, walked in SQL) must be immutable (`invalid_request` otherwise) and resolve for the caller's provider: records/sources/grants by their rows, serving/evaluator/rubric/payer (no Lab table yet) by their provider segment; otherwise `not_found` (FakeLabCatalog's answer). `lab_sources`: a source ref (`lab:source:<provider>:<source_id>@sha256:<content hex>`) registered under a CURRENT grant of the provider. A grant ref pins ONE 0027 version: digest = sha256 of JCS `{"grant_id":…,"version":n}` (SQL `lab_grant_ref`, Python `grant_ref`, parity proven by registering with the Python ref). `lab_dataset_samples`: membership + split written with the manifest in one transaction (a killed publication leaves nothing); a composite FK binds each sample to its source's grant. Harness revisions are `lab.harness_revision.1` records (published = frozen; retire is not persisted here).
- **Rights are read at use time, never carried:** `lab_accessible_samples` and the scheduling gate in `lab_create_run` read each sample's grant at its LATEST version (revoked/expired/purpose); a manifest keeps resolving as audit evidence and confers nothing (R160).
- **D7.b (EVAL-DURABLE).** `lab_eval_runs` (created from a run record; `run:<id>` replays; one `eval_run` outbox event), `lab_eval_cases` (one per sample, first `max_cases` by id), `lab_eval_attempts` (a lease = one attempt; `attempt:<run>:<case>:<n>` key). `lab_fence` (0016's pattern): run of the lease's provider (`not_found`), attempt live + same worker + run live + unexpired on the DB clock (`stale_lease`). `lab_recover` (no caller time, SKIP LOCKED) expires lapsed leases and puts cases back. `lab_finish_attempt`: one result per (run, case, evaluator) (PK), unit-tagged cost (CREDIT | PROVIDER_USD, summed per unit, never converted), replay by a digest of the finish (same → stored answer, other → `idempotency_conflict`). `lab_checkpoint_receipts`: redelivery = the same receipt and no second event; another artifact under the id = `idempotency_conflict`. `lab_outbox`: pending/claim, ack only by the claimant, release, error — the store half of D2's `OutboxRelay`, driven in the relay drill.
- **State moves** are exactly `states.TRANSITIONS` for run/case/attempt/checkpoint (`lab_may_transition`, parity asserted over every pair), enforced by a trigger on each state column.
- **D7.c.** RLS enabled on all 9 tables, revoked from public/anon/authenticated/service_role, service_role SELECT only; writes only via SECURITY DEFINER RPCs (EXECUTE service_role only, 0004 defaults). Partial indexes `lab_eval_cases_pending`, `lab_eval_attempts_expiry`, `lab_outbox_pending` proven on 20 000-row relations by EXPLAIN (plus the samples PK).

## Proposed rulings (coordinator numbers them; next free R166)
1. A Lab grant ref names ONE version of an 0027 grant: `lab:grant:<recipient>:<grant_id>@sha256:<sha256(JCS {"grant_id","version"})>`; a source ref's digest is its content digest's hex. Rights (access, scheduling, source registration) always read the grant's CURRENT version; a pinned version is audit evidence only.
2. Lab kinds with no Lab table yet (serving, evaluator, rubric, payer) resolve by their provider segment only until their owning lane adds a table; D8/D9/R lanes tighten this in their migration.
3. A Lab eval case id is its sample id (one case per sample per run); the first `max_cases` samples by id are the run's cases until B1 asks for seeded sampling.
