## 2. The migration's contract

`infrx.put_result(jsonb) returns text`, SECURITY DEFINER, `search_path = infrx, public, pg_temp`: the signature, return type, owner and definer of 0014, so `create or replace` keeps 0014's and 0021's grants (`service_role`, `infrx_runtime` EXECUTE; `anon`/`authenticated` none). Proven on both images by `test_0026_is_re_runnable_and_keeps_the_grants` (definition md5, ACL and `prosecdef` unchanged by a second apply; the four roles' EXECUTE), by `test_upgrade_d10` (0026 in the upgrade set: `redefined_acl == set()` - no redefined function's grants changed - and the set re-applied is a no-op), and by the `credit_schema` oracle (`test_credit_schema.py`: every seam's callers match the catalog).

| Arguments | Answer |
|---|---|
| `{job_id, text, lease, limits}` from the job's live inference generation (the worker) | 0014's body after the fence: stored once, `infrx-result:<job_id>`; the same text replays; another text `state_conflict` |
| a lease naming another job, `"lease": null`, a non-object lease | `invalid_request`, before the fence |
| a lapsed generation (requeued and claimed again, by the same worker id or another), a foreign worker at the live generation, a preparation token or a live preparation lease (R46), an expired lease | `stale_lease` (0016 `fence_lease`), nothing stored - also after the live generation stored its text: the fence runs before the comparison |
| an ended job | `already_terminal` |
| an unknown job | `not_found` |
| past R29's instant | the fence terminalizes the job (`deadline_exceeded`), which commits (R39); the answer is NULL and nothing is stored; the port raises `AlreadyTerminal` |
| `{job_id, text}`, no `lease` key | 0014's write, unchanged |
| a lease without `limits.unknown_usage_reconcile_s` | `invalid_request` from 0016's `lease_limit`, which is evaluated before the fence (by construction; not a door of its own) |

Lock order: the job row FOR UPDATE (the fence) before the result row, as 0016/0017. The lease-less path locks what 0014 locked. ROLLBACK is 0014's `create or replace` re-run (grants kept); stored results stay (immutable).

## 3. Decisions

1. **A call without a lease keeps 0014's write; it is not refused.** The brief's default was to refuse it unless a committed caller other than the worker needs it. The grep found such callers:
   - the known-good rollback targets `4226315` and `bda1586` (P-25, `infra/rollout/known-good.json`): their `PgJobStore.put_result` sends `{job_id, text}` (`git show 4226315:apps/infrx-api/infrx/state/jobstore.py`, line 344; `bda1586`, line 347). Refusing it would turn every success of a rollback after 0026 into `platform_error` (their runner does that with a failed result write), and their schema proof could not reach 0026: its probe completes through `pgtesting.WorkerResults`, which writes lease-less;
   - `infrx/state/pgtesting.WorkerResults` (not owned), the D conformance rig: it writes the builder's text lease-less before each `complete`, identical replays after the job ended included (a fenced write there would answer `already_terminal` before `terminalize`'s replay);
   - rigs outside this lane: `tests/g/ops/pgworld.py:136`, `tests/m/test_retention.py:669`, I3B's restore drill (`tests/integration/backend/recovery/test_restore.py` bk01h, SQL `{job_id, text}` after a restore).

   Measured: both targets' own result-writing suites and the probe pass on 0001-0026 (`schema_proof.py <target> --candidate HEAD --task d4`, section 8, WR-D10F-4).

   The worker of this tree always sends its lease (the World writer is fenced: `result_written_without_the_lease` is killed by the happy path). `d10_result_leaseless_refused` pins the compatibility. Refusing the lease-less call is a one-line later migration once no known-good target predates 0026 (proposed ruling text, section 9).
2. **R29's committed terminalization answers NULL** and the function keeps `returns text`. A `jsonb` answer needs drop, create and re-grant (a SECURITY DEFINER surface change, E2 layer 3) and changes the type an old runtime reads. NULL is new (0014 never returns it) and unambiguous (an inference fence's only committed refusal is `already_terminal`). Killed defects: `d10_result_r29_refusal_raised` (raised, the terminalization rolls back, R39), `d10_result_writes_after_r29`.
3. **The lease must name the job**: a lease whose `job_id` is not the argument's is `invalid_request` before the fence, or one job's live lease would fence another job's result (`d10_result_fence_any_job`).
4. **The runner treats a refused result write as a refused `complete`.** `_settle` passes `state.lease`, the token `complete` uses. A `StaleLease` or `AlreadyTerminal` from the write records the refusal (`cancelled` for `already_terminal`), stores and settles nothing, makes no `complete` call and keeps the proposal `completed`: no `platform_error`, no "result store failed". Basis: W2's fence rule (attempt.py, "a `stale_lease` means stop, the winner is somebody else, and settles nothing"), R29, R39, R46, R147. R132 (run-profile spend units) and R133 (E4C criteria) do not bear on it. Before, the end state was the same, since `complete`'s fence refuses the same token, but the attempt reported a platform error of ours and made a settling call that could only be refused. Any other result-store failure is still `platform_error` (R30). Killed defect: `refused_result_write_is_a_platform_error`.
5. **No fake or conformance change.** Nothing under `infrx/contracts` models `put_result`: `ports.JobStore` declares none and each world injects its own writer. tests/w's World writer is fenced by the fake store's own `_fence`, the fence `FakeStreamStore.append` runs. No record or wire change.
