### Design decisions worth reviewing

1. **The terminal event is a trigger, not a wrapper.** `jobs_terminal_journal_event` fires `AFTER UPDATE OF settled_at` `WHEN (old.settled_at IS NULL AND new.settled_at IS NOT NULL AND new.journal_reserved_bytes > 0)`, so 0012's `terminalize_unstarted`, 0016's `terminalize_no_usage` (cancel, R29 inside the fence, every `recover_job` cause) and D5's future `terminalize` all get exactly one event without redefining a 0012/0016 function (their D2/D3 mutants stay armed). The payload is `{state, cause, settlement_state}` of the **new** row; it lands after the newest chunk (highest generation's last sequence), else at the last inference generation (else 1) just past a prune watermark; its TTL is the newest chunk's, else the frozen default 3600 s. It adds its bytes to `journal_stored_bytes` (a nested UPDATE that does not list `settled_at`, so the trigger does not re-fire). The 24 h release (`held_unknown → released_platform_absorbed`) leaves `settled_at` alone: no second event.
2. **"No reservation, no journal."** `journal_reserved_bytes > 0` is in the WHEN clause: every admitted job reserves (0011), and an append into a zero reservation is refused by the ceiling anyway. Without it, D1's volume fixture (raw jobs moved to `succeeded` before their chunks are inserted, `checks.py` `seed_volume`) would collide with the event at (1, 1).
3. **The settling write's room is checked against the WIDEST terminal payload** (107 bytes over every state × cause × settlement, the fake's `check_terminal_capacity`): a terminalization whose held-back bytes cannot fit it is refused `journal_capacity_exhausted` and rolls back whole (cancel refused, the reaper reports the job `unsettleable`), and settles after pruning. At production sizes 1024 bytes are held back, so it never fires; with the conformance case's 180-byte reservation it does, which is why `dur_settle__one_unsettleable_job_does_not_stop_the_sweep` passes. `check_append_job_ceiling` computes the widest from the Python enums and pins the literal at the boundary (reservation 2·107 fits, 2·107−1 is refused).
4. **Append order, one transaction:** argument shape → the fence (`fence_lease(lease, ['inference'], reconcile_s)`; a returned refusal is returned as `{"refusal": …}` so the R29 terminalization and its terminal event commit, R39) → the job row (locked by the fence) and the next sequence = max(generation's max, the watermark if in this generation) → R30 type check (only progress/delta/usage/error with an object payload, anywhere in the batch) → sizes measured in SQL (`octet_length(payload::text)`; one event over the store's `journal_event_max_bytes` refuses the whole batch `journal_write_failed`) → empty batch returns `[]` having written nothing → per-job ceiling `reserved − least(1024, reserved/2)` (`journal_capacity_exhausted`, retry 30) → INSERT … RETURNING the rows (`committed_at = infrx.now()`, `expires_at = committed_at + the store's journal_chunk_ttl_s`) → `journal_stored_bytes += Σbytes, published = true`. Only `jobs.published` is written as a marker (`attempts.published`/`first_token_at` have no reader).
5. **Committed rows only.** The adapter returns chunks built from the rows `infrx.append` returned; in autocommit psycopg returns a statement's result only after ReadyForQuery, which follows the commit (module docstring). A caller must not wrap `append` in its own transaction (G2 request below).
6. **Pruning is a prefix, the watermark only grows.** Per job, `expire_journal` deletes everything at or below the newest expired chunk (a straggler committed earlier on a later clock goes with it), stores that cursor as the watermark, and decrements the bytes of exactly the deleted rows. "Expired" is not a flag: a watermark and no chunk left. A later append or terminal event lands past the watermark and is readable from it (a delta from the fake, see Limits 4).
7. **Replay reads the client's cursor as numeric** (`Last-Event-ID` is client input): any magnitude is `invalid_cursor` past the head, never an integer-overflow 500. `read_journal` is STABLE, so its head, gap and page reads share one snapshot.
8. **`finalize_in_transaction` is a read-back keyed by the committed outcome** (unknown `not_found`; not terminal or a different outcome `state_conflict`; expired `journal_expired`; else the one terminal chunk), in Python over one query, like the fake's.
9. **Watermark storage:** two nullable columns on `infrx.jobs` (`journal_pruned_generation`, `journal_pruned_sequence`, CHECK both-or-neither and ≥ 1), which `jobs_guard` does not freeze; no new relation.

## Limits

1. **D5 owns the settlement.** 5 StreamStore and 23 JobStore strict-xfail cases need `complete`; D5's `infrx.terminalize` gets its terminal event from this trigger and must not write a second one.
2. **Terminal-event TTL without chunks** is the frozen default 3600 s (the trigger sees no store limits); with chunks it is the newest chunk's TTL, so a job's chunks expire in cursor order.
3. **The widest-payload literal (107)** in `journal_terminal_event` must follow the vocabularies; `check_append_job_ceiling` fails when a longer state/cause/settlement is added (it recomputes the widest and pins 2W / 2W−1).
4. **Delta from the fake (not in conformance):** a journal fully pruned while its job still runs — the fake answers `journal_expired` for ever and restarts its sequence at 1 below its own watermark; 0017 continues past the watermark and the new chunk is readable from it. Unreachable at the default limits (1 h TTL > any job's deadline).
5. **Byte measure** is `octet_length(payload::text)` (0003's CHECK binds `bytes` to it): one byte more than the fake's `compact_bytes` per `": "`/`", "` separator. W's engine must size a delta against the stored measure near `JOURNAL_EVENT_MAX_BYTES` (pinned: 1048576 accepted, 1048577 refused; the same payload is 1048575 on the compact measure).
6. **ponytail:** `expire_journal` is bounded per pass by jobs (1000), not chunks; `journal_usage` counts chunks with `count(*)` on every call (G2's probe cadence decides whether `pg_class.reltuples` is needed).
7. **`append` must run in autocommit.** The "committed before relayed" guarantee rests on one-statement transactions; a pool that wrapped `append` in a caller's transaction would return rows before that transaction commits (G2 request).
8. **`JOURNAL_*` limits are provisional** (08 §5; P-18/E4B validates them under load). No LISTEN/NOTIFY (the returned chunks are the in-process notification).
9. `make check` was red only in `tests/q` (shared-Valkey interference, owner Q3/coordinator) and stopped there; its remaining targets were run one by one: `api-mutants` red only in one load-sensitive W3 mutant (owner W3, killed alone), `bench-test` red once in one signal-timing case (green on rerun), console targets needed `pnpm install` in this worktree.
