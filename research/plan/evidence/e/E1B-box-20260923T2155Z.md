## L8 — caption-event parity against `reference.py` (provisional, P-18; parity is not accuracy, P-07)

**Method.**
- **Reference side.** With the engine unit stopped, `models/marlin2b/reference.py <clip>` ran, which is the vendor `.caption()`. Setup on the box: transformers 5.17.0, torch 2.12.1+cu130, `flash-linear-attention` absent so the reference PyTorch fallback is used, `HF_HUB_OFFLINE=1`. The vendor helper uses the canonical caption prompt and **the processor-default video budget**: on transformers 5.17, `modeling_marlin.py`'s env defaults only affect qwen-vl-utils (results/notes.md finding 2). Wall per clip was 8.9–23.3 s, peak 5.55–6.35 GiB.
- **Served side.** `smoke.py <clip> --max-tokens 2048` ran on the restored engine: the same canonical prompt (read from `modeling_marlin.py`), greedy, c = 1, at two budgets. `--mm-kwargs ''` is the processor default, the same preprocessing as the reference, so this is **the parity pair**. `auto` is profile v1, the budget the API sends.
- **Comparison.** Events are the `<start - end>` spans, extracted in order with `decide.py`'s `EVENT` regex after the leading `<think>` block is stripped, as `smoke.py` does. Wording is not compared.

**Result (`meas.`, provisional criterion).**
- Caption events match the transformers reference on **2/2 of the 10 s samples** and on **0/3 of the 120 s sop-synth-v1 clips**, at the same prompt and the same (processor-default) preprocessing.
- At profile v1 the installed engine refuses the 120 s clips. That is the P-20 limit: W4 decision B caps admission at 82 s.
- The spans are listed per clip in `L8-compare-20260923T214244Z.txt`. On sop09, for example, the reference gives 1 s marks around each step change (`(0.5, 1.5), (1.5, 8.5), (8.5, 9.5), …`), while the served side gives one span per step (`(0.0, 8.5), (8.5, 17.5), …`).
- **The cause is not diagnosed.** Candidates, all unverified: the video decoder and frame sampling (transformers decodes with torchcodec, vLLM with its own loader), the reference's PyTorch fallback kernels against vLLM's kernels, and bf16 numerics over 12K-token prompts.
- Under §4's provisional parity criterion (events and order must match), the 120 s synthetic clips **fail**. The synthetic fixture has no scene richness (marlin-sop.md §3.8), so this is a parity finding for the serving stack, not a quality statement.
