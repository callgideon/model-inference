## What each slice delivers

1. **Upload conformance (RV-07).** `bench.upload` now uses the mounted contract:
   - create with `max_bytes/bytes/accepted_mime/digest` (`sha256:`), answered 201
     `upload_handle`, and `destination_ref` must equal `infrx-upload:<handle>`;
   - an authenticated PUT to `{--base-url}/uploads/{handle}`, whose URL is built from the
     base URL and the allowlisted handle and never from the answer. A planted `url`, or
     planted headers, reach no one;
   - an empty completion, whose handle, bytes and digest must match ours.

   The fake gateway speaks the same contract. `test_the_fake_gateway_answers_the_upload_probes_like_the_real_router`
   holds it to G4U's router probe by probe (status, error code and answer keys), so the fake
   suite can no longer pass an incompatible client.
2. **Dataset recipe** (`dataset.py run|export`). The JSONL manifest is streamed through a
   bounded queue. A stable id maps to the SOP `item_key` and then to the `Idempotency-Key`. A
   SQLite journal records state `sent` **before** the request leaves. Upload and inference
   concurrency are bounded separately.
   - A staged handle is re-staged only if the item was never sent.
   - `result_expired` is terminal and is never re-billed automatically.
   - An item that changed after it was sent is refused. It is never re-keyed.
   - A resume under another model, base URL or dataset version is refused.
   - Output retention is declared (`--retain-output text|digest`).
   - The results export records whether each answer was fresh or a replay, plus its usage.
     The failures export is taken back by `run --only` as an exact subset.
3. **Validity (RV-08).**
   - Each row records `resend` (first, transport_retry or resume), `served` (fresh or replay),
     `served_model` and upload start/end stamps.
   - Capacity numbers use **fresh answers only**. `accepted` keeps its old meaning; replays
     are counted separately and have their own denominator.
   - `validity()` marks a cell INVALID for any of these reasons:
     - an unexpected replay (a resume excuses only its own resumed keys);
     - missing attempts or an interrupted run;
     - open-loop driver lag above `--max-driver-lag` (default 1 s);
     - a served model that differs from the declared one;
     - counters that do not reconcile;
     - no profile (`unprofiled`).
   - The summary also carries `parser_version` `e1c.1`, `stages_s` and `output_lengths`
     (see below).
   - `--validate-raw` re-derives an old raw file read-only.
4. **Profile + `--validate-only`.**
   - Versioned schema `infrx.run-profile/1`, covering every §1 group. It also carries the
     coordinator's additions: `target.path`, `target.test_key_ids` and `measurement.profile_class`.
   - `runprofile.py` interprets the schema subset and cross-checks the profile against the
     run's own flags and schedule. It checks:
     - the host allowlist;
     - the manifest digest and the item ids;
     - that every over-cap item is declared in `expected_invalid`;
     - every bound;
     - projected spend, including outstanding holds;
     - that no value has a secret's shape. Offending fields are reported by path only.
   - Missing rates, holds or the key inventory block a **paid** run but not a local fixture.
   - `--profile` refuses to start unless the profile is runnable. At run time it then enforces
     `max_duration_s` and `max_drain_s`.
   - The summary's `measurement` block carries the §6 fields with named denominators. Cost per
     successful video-hour is `unavailable`, or `estimated (source, date)`, whenever the price
     is not sourced from `cloud-pricing.md`.
5. **Coordinator update 1 (S3 F5, F8/P-24).**
   - A P4 profile must set `target.path = public-edge`.
   - A P4 cell that saw no 429 or 503 is INVALID.
   - `measurement.overload_by_target_path` reports 429 and 503 counts, `Retry-After` presence
     and transport losses by path.
   - `--key-inventory` takes the sanitized list of active key-id prefixes. It refuses the run
     when any active key is outside `target.test_key_ids`. Without an inventory, a paid run is
     blocked.

### Proposed ruling text (amends R109)

A resource-consuming run against a non-local target refuses to start without a runnable
`infrx.run-profile/1`. The only exception is an explicit, logged opt-out
(`bench --unprofiled smoke`: at most 4 requests of at most 512 output tokens; `--unprofiled
certify` until E2C wiring), and an opted-out summary is INVALID. `target.path` must agree with
the run: engine ⇔ `--target direct`; public edge ⇔ https on its default port of a non-loopback
host.

### Open issues (added)

- `--unprofiled certify` has no cap of its own. It is logged and INVALID, and it exists only
  until wiring request 2 lands.
- A dataset profile must list every item id (`workload.item_ids`), and validation holds one small
  dict per item (a `ponytail:` note in `dataset.check_profile`). A very large dataset needs a
  manifest-digest-only identity mode. This is not needed for v1.
- Cancelling in flight at the drain bound is a client disconnect, billable per R21, for bench
  and dataset alike. The dataset keeps the item `sent`, so a rerun replays it and never bills a
  second inference.
- The closed-loop drain wait is real time (`asyncio.wait`) while `past_deadline` reads `CLOCK`.
  They agree in production. No test combines a virtual clock with a profile.
