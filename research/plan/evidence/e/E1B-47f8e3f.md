## Limits

1. **No measurement of anything on a GPU.** Slices E1B.b's paired direct/gateway
   measurement, all sweeps, the soak and the parity run are **pending P-04** (allocated
   target), **W3** (pinned serving version and image digest) and **I2B** (the refactored
   gateway). They are recorded in `results/E1B-protocol.md` §3 with a status each. No
   number in this report describes the model's behaviour.
2. **Every invariant above is proved against a fake gateway**, `httpx.MockTransport` in
   process. The fake implements the idempotency scope and the payload digest as the
   client needs them, not as `validate.py` implements them; the real behaviour is F/G's
   to demonstrate. This is "implemented", not "integrated".
3. **Phase timing is unexercised against a real target.** The current deployed gateway is
   the pre-refactor monolith with no `Server-Timing`, no `/metrics` and no `/readyz`
   (coordinator inventory), so every declared phase would report as `declared_missing`
   today. The **settlement** phase in particular has no source at all until the usage
   resource exists; the client does not fetch a usage resource and does not pretend to.
4. **GPU, device-memory and device-I/O sampling are not implemented**, only the pluggable
   hook and a host CPU/RSS/load sampler. On the measurement host a `--sampler` module
   supplies them; this host has no device library and none was installed.
5. **The `upload` form still cannot pass a real ingress**: the upload routes do not exist
   (`marlin-sop.md` §2.1). Only the reference *form* and the handle *grammar* are now
   correct; the handshake shape remains unverified until M3/G4.
6. **`sop-synth-v1` deviates from `marlin-sop.md` §3.8 in one respect, deliberately**: the
   pinned ffmpeg build has no `drawtext` filter (494 filters, none of them `drawtext`;
   ffmpeg 7.0 requires libharfbuzz and this static build ships only
   libfreetype/fontconfig). The step is identified in the pixels by a part colour and a
   tally instead of a text overlay. Re-pinning the encoder would invalidate the licensed
   corpus's verified hashes. Owner of the doc update: S2M (integration request below).
7. **§3.8's "two steps ≤1 s apart" is not an exclusive property** at 8 s with four steps —
   ordinary spacing already satisfies it. The validator's exclusive threshold is therefore
   one profile-v1 frame period (0.5 s at 2 fps), which is the resolution that matters;
   §3.8's looser wording is still satisfied.
8. **The fixture's clip hashes were produced on this host.** They are reproducible with
   the pinned binary (proved by a byte-identical re-render) but have not been reproduced
   on a second machine.
9. **`sop-synth-v1` is not a quality benchmark and a score on it is not an accuracy
   claim** (P-07). No rubric, tolerance, ground-truth split or threshold exists.
10. **Console and integration targets were not run** (see the `make check` table);
    neither absence is a pass.
11. **`tests/d` was not run** under the interim harness rule; this branch is at `ec6c548`
    and has not been rebased onto `c23d804`.
12. The `--resume` state is the previous run's raw JSONL. A run whose raw file is lost
    falls back to the idempotency key being the only backstop, exactly as
    `marlin-sop.md` §3.5 step 2 describes; the client does not keep a second journal.

### Unresolved findings

- The deployed monolith's `usage.jsonl` (`ttft_s`, `wall_s`, tokens, `video_seconds`,
  `status`, `stream`) is not a phase source and cannot substitute for one. Any baseline
  taken on it would be a latency-and-throughput sketch, not the envelope E1B owes, which
  is why the protocol puts the baseline after I2B.
- The engine's primed caches (prefix 74.6 %, MM 88.2 %) mean the existing single-clip
