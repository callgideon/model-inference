## Findings for the coordinator

1. **Port collision introduced by `bfb3a8af`/`efad43e0`.** `tests/d/test_pgharness.py` gives
   each D task a decoy PostgreSQL at its port + 40 (d2 55473, d3 55474, d4 55475, d5 55476, d6
   55477, d10 55482) and asserts none is reserved. The patch reserved g8 valkey 55473, e2c valkey
   55474, e2c S3 55475 and i8 valkey 55476 → the case fails on every run (`('d2', 55473)`), and a
   D3/D4/D5 drill would bind a decoy on those lanes' ports. Moving them to 55483/55484/55485/55486
   passes the case (measured in-process). Wiring request 2.
2. **Task-local ports are inside the kernel's ephemeral range** (32768–60999;
   `ip_local_reserved_ports` empty). Measured three times today: the head `make api-test` lost
   `infrx-d1-postgres` (`failed to bind host port 127.0.0.1:55432/tcp: address already in use`,
   54 D failures); consumer-local run 3's layer-2 preflight reported 55500/55532 busy with no container
   publishing them; E2C's own 55510 was the source port of a connection to 55448 (seen in `TIME_WAIT`). A collision can
   only yield spurious BLOCKED/FAIL, never a pass. Host fix (not applied, needs root):
   `sysctl -w net.ipv4.ip_local_reserved_ports=55400-55999,56700-56999` persisted in
   `/etc/sysctl.d/`. Preflight now reports the exposure as a `risk`.
3. **D harness leaves a `Created` container when `docker run` fails to bind** (`infrx-d1-postgres`,
   state `created`, after the bind failure above); I removed mine after checking its label. D's
   owner may want `ensure()` to remove a container it created but could not start.
4. Mutant copies of DB-backed lists do not inherit `INFRX_D_TASK` (`Runner.env=()`), so they
   fall back to D1's 55432 under its lock even inside a gate that uses the e2c namespace.

## Proposed ruling (R109)

> **R109 (E2C, VERIFY-REPRO).** Local gates are certified only on the Linux environment pinned
> in `tests/integration/environment.json`. A gate verdict is PASS, FAIL, BLOCKED, NOT RUN or
> INVALID (exit 0, 1, 3, 3, 4); the worst stage decides; a pytest stage that passed with any skip
> or strict xfail is BLOCKED (an xfail is a quarantine and names owner, reason and expiry); a
> collision on a task-local port is reported as a risk, never as a pass. Cases that execute box scripts are `LINUX_USERLAND`: a BLOCKED skip
> off Linux, always run on Linux. Task-local ports come only from `tasklocal.py`.
