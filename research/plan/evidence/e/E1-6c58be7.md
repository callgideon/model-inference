## Review findings and root-cause fixes

### Blocking finding (round 2): the finding-3(b) regression test was vacuous, and one truncate-before-redact path remained

The reviewer's claim is **confirmed in full, with a reproduction**, and both parts are
fixed.

| Part | Root cause | Fix |
|---|---|---|
| The regression test could not fail | `FakeGateway.echo_key_in_long_body` put the key at offset ≈605 of the body (`"x"*590 + " rejected key: " + KEY`). Round-1 code cut the body at `[:600]` **and** `[:200]`, so the key was past every cut and never leaked there either — the assertion held on the unfixed code | the fake now uses `"x"*170 + " rejected key: " + KEY`, putting the key at offset 185 so it **straddles** the 200-character cut. The test also asserts the field really is 200 characters long, so the shape cannot silently stop being a straddle |
| A truncate-then-redact path survived | `bench.py` redacted the raw body before parsing, but a `\uXXXX`-escaped key is invisible in the undecoded body; `json.loads` decoded it, and `error.message[:200]` / `error.code[:120]` then cut it, leaving a prefix no sink could match any more | the parsed strings are redacted **again** before they are cut (`redact(err.get("message") or body, key)[:200]`, same for `code`). `redact()` is idempotent, so the double pass costs nothing |

Measured longest leaked key prefix, four hostile shapes × three revisions (canary key,
27 characters; the same scratch probe driving `bench.main()` against each tree):

| Hostile shape | `1c7d96d` | round 1 (`f702fc0`) | now (`19b96d3`) |
|---|---|---|---|
| non-JSON body, key straddling the 200-char cut | **15/27** | 0 | 0 |
| `error.message`, key `\uXXXX`-escaped, straddling 200 | 0 | **20/27** | 0 |
| `error.code`, key `\uXXXX`-escaped, straddling 120 | **27/27 (full key)** | **10/27** | 0 |
| `error.message`, key literal, straddling 200 | 0 | 0 | 0 |

So the three straddle shapes now in the suite each fail on at least one earlier
revision, and the round-1 code fails two of them. Running the **current** tests
against earlier `bench.py` (whole `models/marlin2b` copied to scratch, `bench.py`
replaced): `1c7d96d` → 7 failed / 14 passed; `f702fc0` (round 1) → 2 failed / 19
passed, the leak test failing at the escaped-`error.message` assertion and the retry
test at `schedule_lag_s` samples 5 ≠ 4.

Also from the same finding's "related residual": a canary key containing `/` is
covered, because the fake escapes every character of the key (`/` included), which
subsumes the PHP-style `\/` variant.
