## The state this task started from

`make integration` **failed** at base. The rls stage reported exactly the five cases audit
carryover 16 predicted, and the measured messages are what the repair encodes:

| Case | Expected at base | Observed at base (measured, `e2r-baseline.json`) |
|---|---|---|
| E2-RLS-01 | `value=0` | `42501` · `permission denied for table organizations` |
| E2-RLS-02 | `value=0` | `42501` · `permission denied for table api_keys` |
| E2-RLS-03 | `value=0` | `42501` · `permission denied for table credit_ledger` |
| E2-RLS-04 | `value=0` | `42501` · `permission denied for table models` |
| E2-RLS-44 | `error=42501` msg `not a member of organization` | `42501` · `permission denied for function org_balance` |

The cause is migration `0004` ruling R59-4: `revoke all ... from anon, authenticated` on
every existing `public` relation, then grants back only what the console needs, plus
`revoke all on function public.org_balance(uuid) from public, anon`. So `anon` is refused by
the **absent grant** before any policy runs, and `E2-RLS-44`'s refusal moved one layer
earlier — from the function body's membership check to the function grant. Both are 42501,
which is why the repair makes the message part of the expectation and names the relation in
it.

## The PostgREST 13 measurement (deliverable 2, "do not let a shim prove it")

Both ends were measured on real software rather than reasoned about, and they **disagree**:

| Measured | Result |
|---|---|
| `auth.uid()` in `supabase/postgres@sha256:7768d0…` | `select nullif(current_setting('request.jwt.claim.sub', true), '')::uuid` — the LEGACY per-claim GUC only. `auth.role()` likewise reads `request.jwt.claim.role` |
| legacy GUC alone | `auth.uid()` = the principal |
| JSON `request.jwt.claims` alone | `auth.uid()` = **NULL** — nobody |
| `PostgREST 13.0.4`, authenticated request with an HS256 JWT | sets `request.jwt.claims` = `{"exp":…,"role":"authenticated","sub":"<uid>"}` and **does not set** `request.jwt.claim.sub` or `.role` at all (`current_setting(..., true)` → NULL); `current_user` is `authenticated`; `auth.uid()` is therefore **NULL** |
| the same, unauthenticated | `request.jwt.claims` = `{"role":"anon"}`, `current_user` = `anon`, legacy GUCs NULL |

So on this pinned image, in front of this PostgREST, **every** policy that reads `auth.uid()`
would deny everybody. What a *hosted* Supabase project's `auth.uid()` reads is **not measured
here** and this report makes no claim about it — the r1 review's note that hosted Supabase and
PostgREST >= 10 use the JSON form is what made the harness set both, and the half of it this
task could measure locally is the table above. The consequence for the harness is the one the r1 review already
required — set both forms, and assert the identity on every principal-bearing case, which is
what makes a deny-case a measurement rather than a vacuous pass. The consequence for the
product belongs to C0/C2 and I2B and is filed as an integration request below, because it is
a real route-level question (which PostgREST version the deployment runs, and whether its
`auth.uid()` reads the claim form that version sets) and not something a SQL matrix can
answer. The probe container was removed and the probe function dropped; no service was added
to the harness (that is P-03 / E3B).

## Limits

1. **The ownership label is a path, in both harnesses.** A process that sets
   `INFRX_E2_CHECKOUT` / `INFRX_D1_CHECKOUT` to another checkout's root is mis-classified as
   the owner. It stops the accident it exists for — two checkouts of the same repository
   racing for one name and one port — and the D harness's port lock refuses such a process
   anyway while the first run is alive. A per-run random id in a state file is the upgrade if
   forging ever matters. Owner: E.
2. **One port per task means concurrency is refusal, not parallelism** (08 §8). A second
   `tests/d` run raises `HarnessBusy` rather than skipping, because a skip would hide a real
   collision. Lanes that need to run `tests/d` at the same time need a second allocated port,
   which is a coordinator decision, not a harness change. Owner: coordinator / D.
3. **PostgREST is not in the E2 stack**, so no case here proves what a browser session
   actually sends. The two measurements above show the pinned image and PostgREST 13.0.4 use
   **different** claim forms, which is a route-level question for C0/C2/I2B; adding a pinned
   PostgREST service to the stack is **P-03**. Owner: C, I, E3B.
4. **`service_role` bypasses RLS** (measured, `E2-RLS-05`), so tenant safety for the gateway
   is route-side and no SQL case can prove it. Owner: G, C, E3B.
5. **The production barrier on the clock is proved by D's suite, not here.** This harness
   proves no migration installs `infrx_test` and that its own database matches the
   `infrx_%` gate; that `infrx.now()` *ignores* an installed offset in a non-`infrx_`
   database is `tests/d/test_schema_postgres.py::test_database_clock_moves_only_in_a_task_local_database`,
   which runs on both images. E does not duplicate a module's own unit test. Owner: D.
6. **The cancellation race is still a race.** `CANCEL_GAP_S` is 0.2 s, so the client's cancel
   POST has 800 ms for a round trip; at 0.02 s it had 80 ms and failed on this host at load
   average 14.5 (`assert 5 < 5`). If it ever fails again the answer is a longer gap, not a
   weaker assertion. Owner: E.
7. **`apps/app/node_modules` was absent in this worktree**, so `make console-test` first
   reported `# pass 254 / # fail 1` — `lib/utils.test.ts` cannot import `cn`, which is a
   declared dependency. `pnpm install --frozen-lockfile` fixed it and changed no tracked
   file; a fresh worktree needs that step next to `make api-env`. Owner: coordinator (an
   environment note, not a code defect).
8. **Fake, not vLLM; no PERF, no live, no GPU.** `HttpEngine` passing the exported suite
   proves the wire format and the decoder agree over a real socket and nothing about vLLM.
   Nothing here measures latency, throughput or cost. Owners: W, E1B, E4B.
9. **A reverse-order failure in D's own suite, diagnosed and deliberately NOT patched here.**
   `pytest` with the 19 ids of `tests/d/test_schema_postgres.py` reversed gives
   `1 failed, 18 passed`: `test_dur_rls__the_console_read_surface_is_tenant_scoped` reads

## Handback

**What E3B may assume from this harness**

- `run.py` provisions four digest-pinned services, creates `infrx_e2` as a template copy owned
  by `postgres`, applies migrations 0001–0005 in order and seeds two tenants, a shared member
  and a platform operator **through `auth.users`**, so `handle_new_user` (not the harness)
  creates the profiles, personal organizations and owner memberships.
- `pgstate.ROLE_MATRIX` is a list of `Check`s: D1R's new relations are added as rows, not by
  rewriting a runner. Four expectation kinds (`value`, `rows`, `rowcount`, `error`), every
  42501 qualified by the message that distinguishes its cause, and every principal-bearing
  case asserting `auth.uid()` first so no deny-case can pass vacuously.
- `pgstate.install_test_clock` / `set_clock_offset` / `advance_clock` / `clock_delta_s` /
  `probe_clock` are the shared clock helpers. **Use these, not a private clock**: they drive
  `infrx.now()`, the function D1's migrations default every timestamp to. Remember the two
  measured facts: `advance()` returns the pre-move time (STABLE), and the offset is committed,
  so reset it or roll the transaction back.
- `harness.Faults` (kill / pause / disconnect, each namespace-checked with an undo),
  `harness.owned/foreign/assert_ours/assert_nothing_foreign`, and the fake vLLM's fault set
  (`prefill_stall`, `midstream_stall`, `malformed_usage`, `missing_usage`,
  `cancellation_race`, `abrupt_exit`, `split_reasoning_delimiters`).
- `tests/d/pgharness` can be driven safely alongside E's stack: different container, different
  port, its own lock. `pgharness.foreign()`/`assert_ours()` are reusable if another track ever
  needs a task-local container.
- Exit codes are contractual: 0 all passed, 1 something failed, 3 a service-backed stage could
  not run (PENDING). Layer 1 success is never Layer 2, and a `make check` skip is never either.

  `outbox`, `feedback`, `consent_history`, `judge_*`) exist in the schema after 0003–0005 but
