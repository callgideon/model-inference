## How it works

- **Namespace e3c** (tasklocal block 56900–56999): containers `infrx-e3c-{postgres,valkey,
  clickhouse,s3}`, PostgREST `infrx-e3crestj-postgrest` (E3B's naming rule), database
  `infrx_e3c` + template `infrx_e3c_tmpl` + per-case clones, ports PG 56932 / Valkey 56979 /
  S3 56900 / fake vLLM 56980 / PostgREST 56931 / gateway 56940 (+1 for a second gateway).
  `harness.NAMESPACES` has no `e3c` row (WR-1): `world.load_harness()` adds exactly that row
  at load and nothing else; inert once WR-1 lands.
- **A scenario** = `world.composed()` (E3B's `provision_two_tenants` on a fresh clone,
  PostgREST over it, the fake engine, `Box` processes) → actions through the public API and
  the headless operator CLI (`python -m infrx.operations.cli` as a subprocess, key in env
  only) → faults → assertions on API output AND durable rows / objects / ledger.
- **Faults are real.** `INFRX_E3C_BARRIER=<point>` holds a box process at a named step of the
  real code path (`world.POINTS`: upload, admission, readiness, attachment, prep, outbox,
  claim, output, settle; candidates so F2C-L R110's `admit_ready` is held where it exists);
  the test SIGKILLs the process group its own `Box` started, or releases the hold. Container
  faults via `harness.Faults` (pause / SIGKILL + compose up), namespace-checked. Nothing is
  killed by name.
- **Verdict** `<out>/verdict.json`: per scenario and per negative control PASS / FAIL /
  BLOCKED / INVALID / NOT RUN with per-case statuses, reasons, JUnit properties, the
  reproduction command, raw evidence refs (`scenarios.xml`, `scenarios.log`, `cases/<case>/`
  box logs and barrier markers), head at start and end, deviations, resource usage. Gate =
  worst (FAIL > INVALID > BLOCKED > NOT RUN > PASS); exit 0/1/3/3/4 = E2C's `gates.py`.
  `BLOCKED[<lanes>]` names the lanes a case waits for; any other skip is NOT RUN; a stack
  that cannot provision makes every scenario BLOCKED.
- **Negative controls** count only over the case they guard passing in the same run (else
  NOT RUN: the control is absent, removing it proves nothing). Revert-type controls run the
  scenario from a scratch tree with the lane's fix reverted: `--control NC=<tree>`.

## Oracle corrections made while building (failed-then-fixed in the harness, not the product)

- **Database-clock moves are not lease lapses.** A worker crash after `claim` with the clock
  moved +121 s left the requeued job unclaimed for 90 s: the Valkey index schedules a
  candidate at its database `available_at`, which the processes' wall clocks reach only 121 s
  later (diagnosed from the job/attempt/outbox rows the failure message now prints). The crash
  matrix uses short real leases (`LEASE_TTL_S=8`, `LEASE_HEARTBEAT_S=2`,
  `PREPARATION_LEASE_TTL_S=6`); clock moves remain only where nothing in Valkey depends on
  them (expiry reads, reaper deadlines, relay redelivery).
- **After publication a crash fails the job by design.** s05[output]/[settle] first expected
  success; 0016 `recover_job` terminalizes a published job `lost_after_publication` (never
  regenerate, 02 §6). The oracle now asserts that invariant (one generation, no charge, no hold
  held). Flagged below as a product note, not a defect.
- **A reconcile of a settled job answers `state_conflict`** (typed, exit 1): accepted as the
  brief's "typed conflicts".
- **s05[readiness] premise** (commit `8406c798`): see command 7/8.
- **Bind collisions**: the e3c block lies inside the kernel's ephemeral range (E2's documented
  limit); a just-stopped server's connections held 56940/56980 for seconds on this busy host.
  `world.bind_retried` retries the start (≤ 10 × 2 s) on `address already in use` only.

## Open issues / product notes for the coordinator

- **Unbounded waits** (s08): a paused PostgreSQL or object store leaves `POST /v1/jobs`
  unanswered for > 60 s. The declared bound here is 45 s (proposed ruling below); I8/G7 own
  the fix (client-side timeouts that survive a stalled server).
- **Crash after publication = failed job, no charge** (s05 output/settle): correct per 02 §6,
  but a worker crash mid-stream costs the customer the request; worth stating in the public
  retention/recovery docs (A3/G7).
- **Video preparation claims before the attach** (s04 video): not a charge risk today, but R110
  says `claim_preparation` refuses `not_ready`; W5 should not claim-and-wait.
- `record_property` needs `junit_family=xunit1` (the runner sets it); E3B's backend stage emits
  the same warning for its own properties.
- Proposed rulings (next free number per the coordinator; F2C/E1C also proposed R109+):
  - *BACKEND-LOCAL verdict*: a scenario is PASS only if every case ran and passed; a case
    skipped as `BLOCKED[<lanes>]` names the unmerged lanes, any other skip is NOT RUN, an
    unprovisionable stack is BLOCKED for all; a negative control counts only over its guarded
    case passing in the same run; the gate is the worst status, exit codes as E2C's gates.
  - *Stalled dependency bound*: an acceptance whose PostgreSQL or object store stops answering
    returns a retryable 503/504 within 45 s, and a same-key retry after recovery yields exactly
    one job.
