## The ruling, and what replaced the blocklist

The design is now: **nothing untrusted is emitted, so there is nothing to scrub.**

| Untrusted input | Old (filter) | New (allowlist) |
|---|---|---|
| A URL used as a label | `basename()`, then a regex tried to reduce the URL | `urllib.parse.urlsplit` → `hostname` + `"/"` + `posixpath.basename(path)`, emitted **only** if host fullmatches `[A-Za-z0-9.-]{1,253}` and basename `[A-Za-z0-9._-]{1,128}`; otherwise the literal `url-input`. Query, fragment, userinfo, port and intermediate segments are never read. No regex is applied to the URL |
| `error.code` / `error.type` | redacted then cut at 120 | kept only if it fullmatches `[a-z0-9_]{1,64}`, else the literal `unrecognized` |
| An error body | redacted then cut at 200 into `error_message` | **field deleted.** Recorded as `body_sha256` + `body_bytes`, which still correlates with the gateway's own log |
| `Inference-Id` | copied verbatim | `[A-Za-z0-9-]{1,64}` or `unrecognized` |
| `Retry-After` | copied verbatim (string) | numeric only (`float`), else `None` |
| `Server-Timing` | names copied verbatim | names `[a-z0-9_-]{1,32}` with float durations; anything else counted in `dropped_metrics` |
| `finish_reason` | copied verbatim | `[a-z0-9_]{1,64}` or `unrecognized` |
| `usage.*_tokens` | copied verbatim | `int` only (a `bool` is not an int here), else `None` |
| An exception | `redact(str(e))[:200]` | `type(e).__name__` only. Upload failures carry `row["upload_status"]` and a text-free `UploadFailed` |
| A top-level crash | redacted `traceback.format_exc()` | class + frames as `file:line:function`, no message, no locals |
| asyncio / httpx logging | not covered at all | loop exception handler prints the class only; `asyncio`, `httpx`, `httpcore`, `hpack` get a name+level-only handler at WARNING, `propagate=False` |
| An argv value or `--out` path | redacted if it reached output | the run is **refused** (exit 2) when it carries any 8-gram of the key, case-insensitively and after slug folding; the message names the flag, never the value |
| `--label` | copied verbatim into the summary and file name | slugged into `[a-z0-9-]{1,64}` |

`redact()` remains only as defense in depth on the already-serialised line: it removes
any key substring of **8 or more characters** anywhere (not just prefixes — an echoed
`key[9:]` used to pass) and blanks anything still shaped like a query string. The
docstring, this report and `corpus/README.md` no longer claim that every URL is reduced.

## Failure drill

Injection is `FakeGateway` (in-process) with a `chat_override(request)` knob that may
return any response or raise any transport exception, a `hostile_fields` knob that
plants one server-controlled string in `finish_reason`, both `usage` counts and the
`Inference-Id`/`Retry-After`/`Server-Timing` headers at once, plus real process signals.

| Injection point | Durable state before | Behaviour | Durable state after |

| Hostile `finish_reason`/`usage`/headers (200) | `--out` absent or holding earlier lines | `finish_reason` and `inference_id` → `unrecognized`, `retry_after` → null, token counts → null, `server_timing` → `{"queue": 2.5, "dropped_metrics": 1}`; still `accepted` | one `--out` line + 1 raw row per attempt, canary-free |

## Limits

- The guarantee is now structural — an allowlist per field, a label rebuilt from parsed
  parts, no exception text, muted library logging, refusal at argv — and it is measured
  over 176 matrix cells, 5 adversarial URL shapes and 24 generated cases. It is still
  not a proof. Specifically: the allowlists let through anything that **matches** them,
  so a gateway that puts a secret in a field whose value is `[a-z0-9_]{1,64}` (a 64-char
  lowercase token as `error.code`, say) would have it recorded. Narrow the pattern, or

### B6 (blocking): a URL label still recorded URL-derived text

`video_label()` emitted `host + "/" + basename`. Both can BE the secret: a capability URL
of the form `https://cdn.invalid/v/<token>.mp4`, or a tunnel subdomain
`https://<token>.trycloudflare.invalid/clip.mp4`. On the success path that reached stdout,
`bench.jsonl`'s `video` and every raw `clip_id`. Confirmed on `5f72fce`:
`text(url) / 200_stream: r3-bucket.invalid leaked into stdout`, label
`r3-bucket.invalid/clip.mp4`.

**Ruling applied: no URL-derived text at all.** A URL input is labelled
`url-<first 12 hex of sha256(whole URL)>` plus the container extension, and only when that
extension is in `{.mp4,.m4v,.webm,.mov,.mpeg,.mpg}` (case-folded; anything else, including
`.exe`, `.mp4.sh` and a signature-shaped suffix, yields no extension). `HOST_OK` and
`BASENAME_OK` are deleted, together with the false docstring claim that `BASENAME_OK`
"drops a token embedded in the file name" — it only ever dropped unusual characters. Local
files keep their historical basename.

Distinctness for E4 now comes from the digest: stable across runs (asserted), different for
every distinct URL including a changed query, and reversible only by someone who already
holds the URL. Recorded in `models/marlin2b/corpus/README.md` ("Benchmark client: labels
and trust assumptions") and here.

### Limits added in round 5

- A URL label is a digest, so an operator reading `bench.jsonl` can no longer tell which
  clip a URL run used without the URL list that produced it. That is the intended trade;
  keep the URL list beside the run, not in it.
- 48 bits of digest: collisions are ~1 in 2^24 at 4,000 distinct URLs. Enough for E4's
  distinctness counts, not a cryptographic identifier.
- `Inference-Id` residual above.
- `KEY_PUBLIC_PREFIXES` is a fixed list. A pilot key with a different public prefix falls
  back to fail-closed behaviour (more refusals, never fewer), which is the safe direction
  but may need the list extended.
- `sigint_deferred()` only defers; `SIGKILL` still ends the process with whatever was
  already flushed, and a signal arriving in a non-main thread is not deferred at all.

### Round-5 correction (`18e6746`): the n5 deferral had to cover the whole tail

The first n5 implementation deferred SIGINT around the two write calls only. Running the
suite repeatedly (under load) it failed, and the failure was **real, not flaky**: a second
SIGINT landing between `summarize()` and the `--out` append hit the restored default
handler and killed the process — observed `returncode -2` (killed by the signal) with the
summary only partly emitted, which is precisely what n5 exists to prevent.

The whole post-run tail now runs inside `sigint_deferred()`: `summarize()`, the stdout
line, the suppressed-percentiles note and the `--out` append. It is bounded work over data
already in memory, so holding the signal costs nothing, and the exit code stays 130.
The subprocess test no longer sleeps a guessed interval: it waits (30 s cap) for real rows
to appear and asserts the process is still alive before signalling, so it cannot pass or
fail on timing.
