**Root cause (not order and not kept-stack state: a race inside the case).** o09's box-worker case starts a worker,
SIGKILLs it at once and (pristine) starts another. `start` returns once the worker is ready, and that worker can
claim *and finish* the queued job before the kill lands. With the restart removed (the mutant), two things can happen:
(a) the kill caught the job mid-phase, `terminal()` waits `leases + 90` s and the case dies by AssertionError (the
385 s "alone" kill, and this round's first driver run: `not within 240 s … running`); (b) the job already succeeded,
`terminal()` passes, and `app_serves`' **sync** call reaches a gateway with no worker behind it and hangs until the
client's 120 s `ReadTimeout` (the 131 s broken_runner). Probe on the kept stack: a sync request after the only worker
was killed → `ReadTimeout` (15 s client timeout). Which branch runs depends on timing, so the full list is not the
cause; it only changes how often (b) happens.

**Fix (owned test code only, `3e8d0365`).** `scenarios_trace.py` o09 box-worker case: right after the restart, before
anything waits, `assert worker is not None and worker.poll() is None, "premise: the worker came back"` (`worker =
trip.box.processes.get("worker")`; a killed role is popped from `processes`). The mutant's invariant is this premise,
so it now dies at that line by AssertionError in both branches. `dies_by` unchanged (no ReadTimeout added); the
mutant's anchor still matches once.
