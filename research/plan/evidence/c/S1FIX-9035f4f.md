## Limits

- **Not a DOM render test.** B1(d) is checked at source level. `node --test` cannot load a `.tsx`
  module at all — verified: `TypeError [ERR_UNKNOWN_FILE_EXTENSION]: Unknown file extension ".tsx"` —
  because Node strips types but does not transform JSX, and the console's dependency set is frozen
  (no test renderer may be added by this lane). The case therefore asserts the three files' source the
  way `client-boundary.test.ts` asserts the import graph: it catches money formatted in the
  composition root and copy that states an amount, but it does not prove the rendered DOM. A real
  render test needs a renderer dependency — an integration_request, below.
- **`getBalance`'s `catch` is not covered by a case.** It answers `unavailable` when the Supabase
  client or transport throws instead of returning an error row. `lib/credits.ts` cannot be imported
  under `node --test` (R48), so no case exercises it; the guard is three lines and the alternative is
  a 500 on every console page (there is no `error.tsx` above the console layout). Its sibling
  behaviour — every error *row* answering unavailable — is covered by `CREDITS-02`/`CREDITS-03`.
- **No hosted verification.** Nothing was run against a Supabase project or the pilot host, so "the
  sidebar shows Balance unavailable on a pre-D1 deployment" is proven at the unit boundary and in the
  bundle, not in a live console. C0 owns the real query context.
- **`loaded`/`spent`/`ledger_total` figures are gone**, with `getCredits`, the `Credits` type and
  `creditsFromLedgerPage`. Nothing imported them after `credits-card.tsx` was deleted (the brief's
  first nonblocking item), and dropping them also removes the `MAX_PAGE_LIMIT` ledger page read the
  sidebar was paying for on every console render. `/billing` gets its figures from
  `ConsoleServices.balance`/`ledger` (`lib/services/console.ts`), which is hold-aware and untouched.
- The two pre-existing eslint warnings in `lib/contracts/` are not this lane's and were not touched.
