Design (brief 09:87-93, handoffs/C-console-services.md C2):
- **Signed ref** = an opaque `tc_` handle (R54 grammar, 256-bit random); only its SHA-256 reaches the database.
  The RPC row binds it to the grant (rights always read from the grant's CURRENT version, R166), the recipient
  provider AND the issuing user, and an expiry = least(TTL ≤ 900 s, grant `expires_at`, job `created_at` +
  grant `retention_days`). `redeem` re-checks every rule at every read: an existing ref fails closed on
  revocation, a narrowed grant (purpose, category, model), a revoked membership, its own expiry or retention.
- **Never a raw storage path**: a non-`tc_` string is `not_found` before any lookup; the object key comes from
  the grantor's own T2I row under the grantor's prefix (`Retention.read_content` → `ship.read_content`).
- **Model and grantor are server-derived**: the grantor from the named grant ref (`lab_grant_of`: a forged,
  foreign or digest-mismatched ref is `not_found`); the model from the grantor's own `infrx.jobs` row; a request
  not the grantor's own job is `not_found`.
- **Content needs both** `request_content` and `response_content` (the R47 body carries both).
- **T3 honoured**: deleted → `expired` (no object read), past `TRACE_CONTENT_MAX_DAYS` → `expired` despite
  physical presence; `holds` is `Retention(holds=...)` - a live ref keeps the object from the sweep; expired
  or unredeemable refs hold nothing.
- **States, never a crash** (CONSOLE-FLOWS): `pending` (not projected), `metadata_only`, `lost` (never stored,
  object gone, or not a valid `TraceContentBody`), `expired`, `available`.

## Schema request WR-C2-SQL-1 (to lab-sql: C2-RPC) — proposed contract

Table `infrx.lab_content_refs` (append-only: 0027's `forbid_update_delete`/`forbid_truncate` triggers; no browser
grant): `handle_sha256 text primary key check (~ '^[0-9a-f]{64}$')`, `grant_id uuid not null`,
`grantor_org_id uuid not null → public.organizations`, `provider_org_id uuid not null → infrx.provider_orgs`,
`user_id uuid not null → public.profiles`, `request_id uuid not null`, `purpose text not null` (the four
purposes), `categories text[] not null` (non-empty ⊆ the five), `issued_at timestamptz not null default
infrx.now()`, `expires_at timestamptz not null check (expires_at > issued_at)`; index `(grantor_org_id,
request_id, expires_at)`. Clock: `infrx.now()` only (R7) - no `now` input.

Named RPCs (SECURITY DEFINER, service_role, `{...}` jsonb in / jsonb out, refusals `<code>: detail`):
1. `infrx.lab_content_ref_issue({handle_sha256, user_id, provider_org_id, grant_ref, request_id, purpose,
   categories, ttl_s})` → `{grant_id, grant_version, grantor_org_id, request_id, purpose, expires_at}`:
   `invalid_request` (ttl ∉ 1..900, no/unknown category, unknown purpose, malformed digest) →
   `not_found` (`lab_grant_of(grant_ref, provider_org_id)` is NULL, or no `infrx.jobs` row with
   `org_id = grant.grantor_org_id` and this `request_id`) → `forbidden` (the pair's CURRENT grant version not
   current at `infrx.now()`, or `jobs.model_id::text ∉ model_ids`, or any category ∉ categories, or purpose ∉
   purposes; or `user_id` not a current developer/administrator of `provider_org_id`) → `result_expired`
   (least(now + ttl, grant.expires_at, jobs.created_at + retention_days) ≤ now) → `state_conflict` (digest
   exists). Returned `grant_version` is the CURRENT version.
2. `infrx.lab_content_ref_redeem({handle_sha256, user_id, provider_org_id})` → the same shape, `expires_at` =
   least(row.expires_at, jobs.created_at + current retention_days): `not_found` (no row, or another provider or
   user) → `result_expired` (now ≥ row.expires_at) → `forbidden` (rule 1's current checks with the row's purpose
   and categories) → `result_expired` (past the current retention).
3. `infrx.lab_content_ref_held({org_id, request_id})` → `{held: bool}`: a row for the pair with now <
   expires_at whose redeem checks pass.
4. `public.lab_content_ref_issue(p_handle_sha256 text, p_provider_org_id uuid, p_grant_ref text, p_request_id
   uuid, p_purpose text) returns jsonb`: the authenticated session door (R171 pattern) - user = `auth.uid()`,
   categories = {request_content, response_content}, ttl 300; the same answer as (1). No redeem door: content
   is read only by the platform's content service.
5. Adapter `infrx/state/lab_content.py` `PgContentRefs` implementing `infrx.content.ContentRefs`.
Proof requested: `tests/content/test_content.py`'s `w` fixture gains a `pg` param (`INFRX_D_TASK=lab-c2`,
57505) so the same 22 cases run on the RPC; a role matrix (anon/authenticated refused the infrx RPCs; the
public door answers only for `auth.uid()`); the 34 mutants rerun with a `pg` copy list (L2 pattern).

## Proposed rulings (unnumbered)

- Content refs: a `tc_` handle whose SHA-256 alone is stored; bound to grant (rights from its current version),
  recipient provider and issuing user, expiry least(TTL ≤ 900 s, grant expiry, job age + retention_days);
  every redeem re-checks; trace content needs request_content AND response_content; the model is the job's; a
  non-handle string is not_found before any lookup; T3's logical state decides availability.
