## `tasklocal.py` duplicate keys

In a dict literal, a repeated key keeps its **first** position but takes the **last** value, so
the first four rows had been dead since the later rows were added. `git log -L17,35`:

| Key | Kept (live) entry | Dropped (dead) entry | Ports: dropped → kept |
|---|---|---|---|
| `d2` | `{"postgres": 55433, "valkey": 55463}` (cd4b30b5, 2026-09-22, "D2's relay drills need both") | `{"postgres": 55433}` (0cd274ae R48, 2026-09-21) | pg 55433 → pg 55433 + valkey 55463 |
| `d3` | `{"postgres": 55434, "valkey": 55464}` (d57e04ec, 2026-09-23) | `{"postgres": 55434}` (0cd274ae R48) | pg 55434 → pg 55434 + valkey 55464 |
| `d4` | `{"postgres": 55435, "valkey": 55465}` (9c1c6ed8, 2026-09-23) | `{"postgres": 55435}` (0cd274ae R48) | pg 55435 → pg 55435 + valkey 55465 |
| `d5` | `{"postgres": 55436, "valkey": 55467}` (a237d6f3, 2026-09-23) | `{"postgres": 55436}` (0cd274ae R48) | pg 55436 → pg 55436 + valkey 55467 |

Why the later rows are the intended ones: each later commit registered a lane's Valkey. It
repeated that lane's R48 PostgreSQL port unchanged, next to a comment explaining the addition. Each
dropped row is a strict subset of its kept row, with the same PostgreSQL port, so **no reservation is lost**.
The dropped rows reserved nothing the live rows do not.

Checked against the base (a session-scratch script that was not committed. It loads the base file from
`git show 6c390bda:` and the edited file with `runpy`):

- `TASK_PORTS` is equal: 31 tasks and 47 task ports.
- `local_services(t)` is equal for every task, compared with `dataclasses.asdict`.
- `all_host_ports()` is equal: 449 ports.
- No port is reserved twice among task ports.
- The only difference is the dict's **iteration order**: `d2`..`d5` now follow `q3`/`g2`
  instead of `d1`. The only code that iterates it is `all_host_ports()`, which returns a mapping
  keyed by port, and `tests/d/test_pgharness.py:201`, which builds a list and then a dict and only
  runs set and `in` checks. Neither depends on the order.
