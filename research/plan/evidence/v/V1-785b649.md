  honestly. The copy says "On this page". Contract-revision request below.
- **The time filter is the shared `RANGES` set** (5 m … 30 d) reused from Usage so the two pages

- **`model` has no allowlist**: nothing in `ConsoleServices` enumerates the served models, so the
  filter offers the models present in the current page and the parser only bounds the value. A
  model id from another tenant's traffic would produce an empty page, never another tenant's rows
  (the service binds the tenant).
- The `size` change drops the cursor although the contract's cursor is deliberately *not* bound to
  `limit`; that is this page being conservative, not a contract requirement.
- Performance is unmeasured: 07-console-spec §4.1's "first page < 1 s p95 over 10k rows" is a

## Disposition per item

### B1 — "Start from the first page" looped on the same URL — **fixed**

Confirmed as described. `withPatch` computed the cursor as
`changesFilter ? null : (patch.cursor ?? filters.cursor)`, so an explicit `cursor: null` fell
through `??` to the cursor already there, and `clearHref` — which asks for exactly that — got the
forged cursor back whenever no *filter* also changed. On `?at=…&cursor=Zm9yZ2Vk` with no filters set,
the way-back link was the URL the reader was already stuck on.

- `withPatch` now tests `"cursor" in patch`, which is the only way to express "leave the walk".
- `clearHref` and the new first-page link also pass `pinned: false`, so the pinned window is
  released with the cursor; without that the way back still froze the reader to an old anchor.
- `V1-V10` is the regression, and it is end to end against the fake: build the dead URL, confirm the
  service answers `invalid_cursor`, take the rendered action href, assert it carries no `cursor=` and
  no `at=` and differs from the dead URL, then **follow it and require a page of rows**.
- `V1-V07` now asserts `action.href` for every error code (it previously asserted only the label,
  which is why a href-level defect survived), including that the way back is not `traceHref(filters)`.
- Mutants: `HREF-02` (the `??` form restored) and `CLEAR-01` (drop `pinned: false` from the way
  back) — both killed by `V1-V10`; `HREF-01` and `FIRST-02` cover the neighbouring clauses.

Two mutants written for this item **survived and were deleted rather than kept green**: they mutated
clauses that turned out to be redundant once `"cursor" in patch` existed (a `leaves` disjunction, and
a `left` clause releasing `pinned`). The redundant code was deleted and the invariant is now carried
by the clause that actually decides it. Worth stating plainly: a surviving mutant found dead code,
which is the other thing R32 is good for.

### B2 — `at=` unbounded and leniently parsed — **fixed**

- `parseAnchor` is strict: RFC 3339 UTC shape, then a bounds check against
  `[now − MAX_ANCHOR_AGE_MS, now + MAX_ANCHOR_SKEW_MS]` (403 days ≥ 13 calendar months of retained
  metadata, 08 §5; 5 minutes of forward skew), then round-trip equality of the first 19 characters.
- **`Number.isFinite` is gone, deliberately.** `NaN` fails both bounds comparisons, so
  `?at=2026-13-45T99:99:99Z` is refused by the same check as an out-of-range date and never reaches
  `new Date(ms).toISOString()`. There is no longer a separate guard whose removal turns a refusal
