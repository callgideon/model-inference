## Design (one line each)

- `port.ts`: `PipelinesPort` (labels, disagreements, imports, exports, importLabels, assign, review, adjudicate, exportLabels; runs, checkpoints, bundle, prepare, submit, finish, cancel, importCheckpoint, approve), `Result<T>` refusals `denied|not_found|invalid|conflict|gone|unavailable`; `holds` mirrors `contracts/v2` (P1/P3 need `run_evaluation`, assign needs `manage_members`; a viewer runs and reads nothing: label values are content). `pipelinesPort()` is **unavailable** unless `LAB_PIPELINES_PREVIEW=1` outside production (each page labels the preview itself; the layout is not touched).
- `fake.ts`: what P1/P3 enforce: provider scoping (foreign dataset/run = not_found), role (denied), write-once ids (replay = stored record, other body = conflict) for import/export/run/checkpoint, row refusals `missing_evidence|grant_not_current|forged_ground_truth|bad_mapping`, correction = reject + human label, adjudication = disputed rejected/superseded + human label, train-only export with `validation|holdout|grant_not_current|disagreement` omissions and lineage, foreign payer invalid, expired export gone, manual bundle reserves nothing, ambiguous submit only looked up, revoked grant stops submit, checkpoint `run_<state>|missing_artifact|digest_mismatch` before any evaluation, redelivery = first outcome, approve only on a succeeded evaluation. Reviewer identity is not modelled (the route derives the user).
- `view.ts`: labels show kind (synthetic / imported / human review) and ground truth only for a human review; import receipts list every rejected row (unknown reason not echoed); exports show lineage `sample ← labels (methods)` and omissions; runs show config, data, holdout pin, `limit … USD · reserved … USD` + payer, state copy (ambiguous = unknown, held, never resubmitted), cost (manual: nothing reserved; unsettled; unknown never estimated; as reported); actions submit/finish/cancel from the record, none on ambiguous or for a viewer; checkpoints show lineage run → dataset · export · config · holdout pin, rejection reason (never evaluated), approvable only on a succeeded evaluation of exactly the run's pinned holdout, held-out comparison link `/evaluations?run=`.
- `actions.ts` ("use server"): actor = session workspace; payer/dataset/rubric/annotation refs must be this provider's; USD = R159 Amount shape; ids are UUIDs minted **at form render** (`randomUUID()` hidden inputs), never by the action; the connector is never read from the form (always the manual bundle); capability then shape refused before the port; the port's refusal → `?refused=`; success = plain redirect back to the records.

## Ruling proposal (unnumbered)

LAB-PIPELINES-UI: the Lab reaches P1/P3 only through `/lab/v1/pipelines` as the signed-in user; every write-once id (label import, label export, external run, checkpoint) is minted when the form renders and is the idempotency key end to end; the Lab never chooses a training connector (manual bundle only until P-11); a paid or budgeted run always shows its PROVIDER_USD limit, reservation and named payer; an ambiguous submission, an unsettled or unreported cost and a rejected checkpoint are shown as such and are never resubmitted, estimated or evaluated; only a Lab human review is shown as ground truth; a candidate is approvable only on a succeeded evaluation of the run's pinned holdout, and approval makes it eligible, never public.
