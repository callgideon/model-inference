## Behaviour (each decision killed by a named mutant)

- **Manifest (P2.a):** the N2 version's train+validation samples in id order, cut into chunks of 1..200 (J1's scan bound); the holdout is never teacher-labelled (evaluation truth and training labels stay apart). Run id = `uuid5(batch_id, ",".join(chunk samples))`: a resume addresses the same runs and chunk boundaries never move with the rights, so a sample that left is never re-sent. Dry run: no rate needed (unpriced = `None`), no ledger, no egress; lists `not_permitted` as of now.
- **Rights:** a sample leaves only with BOTH `external_judging` (egress to an external model) and `training` (the label's use), read at plan, per chunk before egress, again inside `send`'s recheck, and at collect.
- **Live (P2.b), J2's protocol:** exactly `live` mode (R57); a current developer+ member (viewer 403, non-member 404); this provider's own `lab:payer:` (PROVIDER_USD, never CREDIT); an approved rate; one D6J reservation per chunk at its worst case; one submit intent per run (`begin_submit`); egress only through `judge.submit.send` and J2's `HttpJudgeProvider` (local hosts only until P-10).
- **Budget stop:** the first chunk the budget cannot cover stops the batch; it and every later chunk are `unsent` (never reserved).
- **Revocation mid-batch:** a sample revoked before its chunk leaves is skipped (the rest of the chunk leaves); a revocation between that check and egress makes `send` release the chunk's hold and stops the batch (`stopped="permission"`); a label for a sample no longer permitted is `grant_not_current`, never imported.
- **Ambiguous submit:** an unknown outcome is quarantined with its hold; a resume never re-sends; `judge.submit.reconcile` adopts the provider's evidence by submit key.
- **Collect (P2.c):** per-item failures (`not_sent`, `duplicate`, `grant_not_current`, `malformed_label`); valid labels (`{"label": text<=4000, "confidence"?: 0..1}`) go to P1's `import_labels` as method `model` (P1 publishes `synthetic`, never `human`/ground truth) with `method_version`/`prompt` = the prompt pin and `model` = the teacher; settle once when the provider is done; a completed run is a no-op.
