## What was built

1. **Engine pin** (`models/marlin2b/serve.sh`, `models/marlin2b/serving-version.json`). The
   image is pulled by registry digest; the engine is published on `127.0.0.1` only and takes
   no `--api-key`; `--max-num-seqs` comes from `ENGINE_MAX_NUM_SEQS` (default 8, the pilot
   setting, ⚠️ the box ran 32) and `--allowed-local-media-path` from `PROCESSING_CACHE_DIR`
   (mounted read-only at the same path); a second command-line value for either, or an
   `--api-key`, is refused (exit 2) before docker runs. The record carries the model pins,
   the image resolution, every flag as served, both EOS ids, profile `v1` and an
   `engine_options_digest`.
2. **One media root.** `VllmEngine`'s root is `PilotSettings.processing_cache_dir`
   (`PROCESSING_CACHE_DIR`) — the value M2's `ProcessingCache` and serve.sh read.
   `LOCAL_MEDIA_ROOT` is deleted; an unset root refuses every video `dependency_unavailable`.
3. **Drain** (`WorkerService.stop`, `WorkerLoop.drain`): stop claiming, wait up to the bound
   (default: the generation budget), cancel the rest — released, never settled — and record
   per job what ended (job, cause) and what was released. A drained loop stays drained.
   `serve()` maps SIGTERM/SIGINT to the drain, and returns by itself if every runner dies.
4. **Protected readiness/liveness**: `GET /readyz` and `GET /livez` on a loopback-only
   listener (any other bind refused at construction). `/readyz` is 200 only for an engine
   that answers ready and a pool that is running and not draining; its body names
   `engine` (`up`/`down`) and `loop` (`idle`/`busy`/`draining`/`stopped`). Counts only.
5. **The `recover` reaper** (worker side): `JobStore.recover()` once at start-up before the
   pool claims, then every 10 s; every `IndexEvent` returned is enqueued; a failing
   `recover` or `enqueue` is counted and retried. **PERF-PILOT hook**: `AttemptResult.timings`
   (`prefill`, `generate`, `journal`, `persist`, `settle`, ms on the injected clock, absent
   when the phase did not happen) and `server_timing()`, which `bench.parse_server_timing`
   reads back unchanged.
6. **Measurement scripts** for the coordinator: `models/marlin2b/measure/inventory.sh`
   (read-only), `capability.sh` (inference requests only), `concurrency.sh` (E1B cell L1;
   loads the engine).

## Failure drill

| Injection point | Durable state before → after | Duplicate / retry behaviour | Cleanup |
|---|---|---|---|
| Worker dies holding a lease (claim, no run, clock past TTL) | `running` → reaper: `queued`, `attempt=1`, one index event | the next claim is generation 2; the dead lease is never resumed | `reaped` counts it |
| Worker dies after publishing | `running` (published) → `failed`/`lost_after_publication` by `recover` | nothing enqueued, never regenerated | — |
| `recover` raises (store down) | unchanged | retried next tick; the process lives | `reap_errors += 1` |
| `enqueue` raises after `recover` requeued | `queued` durably, index missing it | Q's reconciler / next rebuild repairs; never lost | `reap_errors += 1` |
| Drain bound passes with an attempt in flight | `running`, lease held → unchanged (nothing settled), stream closed | past the TTL the next start-up reap requeues it; it completes once as generation 2 | `released_jobs` records it |
| SIGTERM to a serving process | as above per attempt | exit 0; the in-bound attempt settles `completed` | report printed |
| Stop immediately after start | pool not yet running | the drained loop stays drained; the pool stops | — |
| Engine process SIGKILLed | readiness `down`, pool live; a new attempt settles `failed`/`engine_error`, debit 0 | a restarted engine is `up` again | fake server stopped by the fixture |
| Every runner dies (index unreachable) | pool stops; `/livez` 503; `serve()` returns | the service manager restarts the process | `failures == 1` |

## Limits

1. **Fake-only / local-process-only, so `implemented`, not `integrated`.** No PostgreSQL,
   Valkey or real vLLM held one of these leases; the integration engine is E2's fake vLLM.
2. **Every measured number is pending (P-04):** image equality with the box, `/version`, KV
   capacity, the four capability answers, the concurrency sweep and therefore
   `ENGINE_MAX_NUM_SEQS` (stays 8, ⚠️) and `WORKER_CONCURRENCY`.
3. **`file://` cannot be probed on the engine as it runs today** (started without
   `--allowed-local-media-path`); step 2b needs I2B's pinned restart.
4. **`mm_uuids`:** the adapter sends a top-level `mm_uuids`. If `capability.sh` reports it
   `accepted_but_ignored` and the per-part `uuid` `known`, the adapter moves to the per-part
   form (a W follow-up on `engine.py`); until then vLLM's multimodal cache keys by content.
5. **A released job waits for its lease.** There is no `JobStore` release operation, so a
   drained job is requeued only after `LEASE_TTL_S` (120 s) plus one reap interval; a
   sync/stream job's cumulative queue budget (R5) may expire meanwhile (→ `queue_wait_expired`,
   not lost), and a published one becomes `lost_after_publication`. The default drain bound
   (the 300 s generation budget) makes a release rare, at the cost of a stop that can take
   5 minutes in the worst case.
6. **Readiness is loopback-protected, not authenticated.** Anything on the host can read
   counts; nothing else can reach it. The gateway's own tenant-authenticated `/readyz` (G)
   is separate.
7. **Liveness sees a dead pool, not a partly dead one**: one runner of several dying shows
   as `failures`, not as 503.
8. **Timings are in-process.** A worker in another process cannot hand its `AttemptResult`
   to the gateway; the transport is integration request 9.
9. **The reaper does not dispatch lost preparation leases**: `recover` returns them only as
   outbox rows (integration request 7).
10. **Reap cadence is a fixed 10 s** (`ponytail:` in the code).
11. **`tests/d` not run** (see Commands); no file under `infrx/state` or the migrations changed.
