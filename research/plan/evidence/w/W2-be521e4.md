## What was built

`infrx/worker/attempt.py` (`AttemptRunner`) executes one fenced attempt: `claim` →
`load_work` → `prepared_request` → `generate` → journal `visible` deltas through the
StreamStore → relay only what committed → heartbeat inside the TTL → one `complete`
derived from the stream's own facts. `infrx/worker/loop.py` (`WorkerLoop`) claims
inference candidates from the Scheduler, acknowledges every candidate it consumed, runs a
pool of sequential runners and drains by *releasing* — never settling — what is still in
flight at the bound.

The engine is used through `ports.Engine` alone, so the shared `FakeEngine` and W1's
`VllmEngine` are interchangeable. W1's `EngineStream.terminal_cause` is read as a **hint**
and re-checked; an iterator without one gets an outcome derived from the canonical events
and the lease's persisted instants.

Two adapter changes from S2M's pinned profile are in a separate commit (`3972c80`).

## Failure drill

Every injection is deterministic: the shared fakes' `FailurePlan` (by operation name and
call ordinal) or a scripted engine. No sleeps except the two real-clock bounds noted.

| Injection point | Durable state before → after | Duplicate / retry behaviour | Cleanup |
|---|---|---|---|
| Engine dies mid-stream (`abrupt_exit` on the real adapter; `EngineExited` on the shared fake) | `running` with committed chunks → `failed`/`engine_error` (adapter) or `platform_error` (untyped exit), debit 0, reservations released | no retry: the attempt settles, so nothing is regenerated after publication | stream closed in `finally`; no intent left in the engine's map |
| `append` refused (`JournalWriteFailed` before commit) | `running`, journal empty → `failed`/`journal_write_failed`, journal still empty | none: relay never saw a chunk, so there is nothing to reconcile with the customer | reservation and journal reservation released by the settlement |
| `append` committed then the answer lost (`crash_after_commit`) | `running` → `published=True` with chunks, then `failed`/`journal_write_failed` | the loop does **not** re-append; the chunks it cannot prove are not relayed | the customer has no result object and no debit |
| `complete` committed then the answer lost (`crash_after_commit`) | `running` → `succeeded` with one debit | the identical proposal is retried once and replays the committed outcome; one `usage_projection`, one ledger movement | idempotency tombstone and reservations handled by the store's settlement |
| Lease expired (FakeClock past `expires_at`) | `running` → unchanged (`outcome is None`) | the worker stops; `recover` requeues (prepublication) or fails it (published) | no append, no relay, no `Engine.cancel` |
| Superseded generation (expiry → `recover` → new claim) | generation 1 token vs generation 2 winner | generation 1 appends nothing and settles nothing; only generation 2's chunks exist | the store cleared the old lease at requeue |
| Duplicate claim (two runners, one job) | `queued` → `running` for one worker | the loser is `not_claimable` and runs nothing | one settlement, one projection |
| Customer cancel before the claim / before `load_work` / mid-stream / before `complete` | non-terminal → `cancelled`/`client_cancelled` by the store's own transaction | the worker settles nothing in any of the four; mid-stream it calls `Engine.cancel` with the current lease and stops reading | stream closed; nothing after the cancellation is journalled |
| `Engine.cancel` answers `False` | as above | the worker stops the task itself (it owns it) | stream closed |
| Queue deadline passed | `queued` → `expired`/`queue_wait_expired` (at `recover`), claim refused `not_claimable` | the engine is never started | hold released free |
| Generation deadline passed mid-stream | `running` → `failed`/`deadline_exceeded` inside the worker's own `append` (r1 R29) | the worker settles nothing on top | hold released platform-absorbed |
| Engine silent for ever (no chunk at all) | `running` → `failed`/`deadline_exceeded` by the attempt's own `asyncio.timeout` | none | stream closed; the case's own 2 s bound never fires |
| Usage arriving with a platform deadline | `running` → `failed`/`deadline_exceeded` with the count recorded | none | debit 0 |
| Restart between claim and first delta (claim, no run, clock past TTL) | `running` → `queued` with `attempt=1` and a new index event | the new attempt is a **new generation**; the old lease is dead | the pool claims the requeued candidate |
| Drain with an attempt in flight | `running` → unchanged (nothing settled) | the task is cancelled; the store's `recover` decides | stream closed by the cancelled generator's `finally` |
| Result object store fails | `running` → `failed`/`platform_error`, `result_ref is None` | none | debit 0 |
| Tokenizer raises / reports an impossible count | `running` → `failed`/`platform_error` | none; the engine is never started | reservation released |

### The three things the mutation run changed in the implementation

1. **Dead code deleted.** `_State.cancelled` and the `client_cancelled` branch of
   `_derived_cause` could not both be reached: a cancellation this worker discovers raises
   before any settlement, and a cancellation the *engine* was told about is reported by
   W1's `terminal_cause`. Two unkillable mutants became a deletion.
2. **`append` is fenced through the same path as the heartbeat.** The drills found that a
   mid-stream cancellation discovered by `append` did **not** reach the engine, because
   only the heartbeat went through `_fenced`. Fixed in `c818055`.
3. **A media refusal settles `invalid_media`.** The adapter refuses at the first
   `__anext__`, not when `generate` is called, so `UnsupportedMedia` arrived in the
   generation handler and was settled `platform_error`. Both handlers now classify through
   one function.

### One W1 mutant was masked, and is killable again

`storage_ref_tenant_trusted` (W1's list) stopped dying when the new local-path containment
check was added: a foreign-tenant key was still refused, but by the *other* check. The
reference case now asserts `check_storage_ref` on its own, and W1's list is 149/149 again.
This is the defence-in-depth trap R32 exists to catch, and it is why both checks stay.

## Limits

1. **Fake-only, and therefore `implemented` and not `integrated`.** Every result here is
   the shared in-memory fakes plus `httpx.MockTransport`. No PostgreSQL has fenced one of
   these leases, no Valkey has handed out one of these candidates, no vLLM has parsed one
   of these bodies, and no GPU was involved. The integration gates are D5 (the real store),
   M2 (preparation and media) and Q3 (the real index), with P-03 for local services and
   P-04 for a GPU target.
2. **Two required collaborators have no production implementation in this tree.**
   `count_prompt_tokens(work) -> int` (preparation's **exact** count — `02` forbids an
   estimate, and W1 limit 7 makes it an argument) and
   `put_result(job_id, visible_text) -> result_ref` (`02` §7's immutable result object,
   which r1 R30 requires for a `succeeded` outcome). Both are constructor arguments with no
   default on purpose: no code path can invent a count or a dangling reference. Integration
   requests 3 and 4.
3. **The cancellation poll's granularity.** While output is flowing, a customer
   cancellation is discovered by the next `append` — within one batch (50 ms of clock).
   With no output flowing it is the heartbeat that discovers it, so up to
   `LEASE_HEARTBEAT_S` (40 s) can pass. A notification channel (LISTEN/NOTIFY) or a
   cancel-intent read on the JobStore port would tighten it; marked `ponytail:` in the code.
4. **The heartbeat is event driven.** It renews when an event arrives, so it relies on the
   adapter's own bounds being shorter than the lease TTL (TTFT 60 s and stall 20 s against
   120 s). If W3 ever configures a phase that can outlast the TTL without producing an
   event, a background renewal task is required. Stated in the code beside the check.
5. **The task-level deadline mixes two clocks.** The remaining seconds come from the
   injected clock (so they agree with the store's instant) and the waiting is
   `asyncio.timeout`'s real time. On a real clock the two agree; under a FakeClock they do
   not, so the proof is a 50 ms real bound plus the case that shows an attempt with budget
   left is not cut short. Two cases therefore sleep on the wall clock (≤ 150 ms in total).
   A related consequence: `except TimeoutError` is first in the handler chain, so a
   **builtin** `TimeoutError` escaping an engine adapter would be read as our own deadline
   rather than as an engine failure. W1's adapter lets nothing untyped escape, and the
   misreading is in the safe direction (`deadline_exceeded` is platform-absorbed, so it
   never bills), but another adapter should wrap its socket timeouts as W1 does.
6. **Preparation is not executed here.** `claim_preparation` is untouched: the pool claims
   `inference_dispatch` candidates only, because preparation is M's fenced attempt sequence
   on its own lease kind (r1 R46/R52). A preparation worker is M2's, not this loop's.
7. **Trace capture is not wired.** The loop never hands `raw` to a `TraceCapture`; T and G
   own opening the capture. So the unfiltered model text is available on the stream and is
   deliberately dropped by the worker — a trace of it does not exist on this path yet.
8. **Drain releases rather than settles**, which is correct (`02`: a worker that did not
   finish has no outcome to propose) but means a drained job is finished by the store's
   reaper. There is no reaper loop in this tree: something must call `JobStore.recover()`
   on a timer (I/E own the service), or a drained job waits for its absolute deadline.
9. **`BATCH_MAX_EVENTS = 32` and the relay's swallow-and-count are engineering choices**,
   not measured ones, like every number in 08 §5. E's load run is what would justify a
   different batch bound.
10. **Causes this loop never produces:** `client_disconnected` and `sync_deadline` are G's
    (the transport's), and `lost_after_publication`, `retries_exhausted`,
    `queue_wait_expired` and `preparation_failed` are the store's. A **billable**
    `client_cancelled` (a non-zero debit) is unreachable with these fakes: the adapter's
    cancel path reports either an authoritative zero (nothing ran) or an unknown count
    (truncated mid-stream), so R21's cancellation debit branch is proven only for zero.
11. **The `R58Engine` shim exists because the shared fake still emits `content`.** It is
    the pending F2R item 2 written down; when the shared fake emits `{visible, raw}` the
    shim and W1's `content` alias both go (integration request 2).
12. **The `file://` path form is unverified against a real engine, and against M2's real
    `MediaPreparation`.** That the pinned image accepts `file://<path>` with
    `--allowed-local-media-path` is W3's fact. M2's `prepare.py` is on `claude/backend-impl`,
    not on this branch (no merge, per the brief), so the resolver in the tests is
    `fakes.m2_local_uri`, a stand-in for M2's layout; the adapter checks what any resolver
    returns, so a drift in M2's layout is a refusal, not a wrong file. The adapter fails loudly (a
    refusal or an engine error) if the layout differs; it cannot fail silently.
13. **`stop_token_ids` acceptance is unverified too.** vLLM documents the field; whether
    the pinned image honours both ids is W3's capability probe, and the profile's own
    `serve.sh` discrepancy D13 is W3's.

## Migration / rollback

No schema change, no migration, no deploy. The worker is not mounted anywhere: no router,
no service unit, no composition-root entry, so rollback is removing the two modules.
Feature-disabling a worker pool must stop claiming (`drain`) rather than killing it, so
in-flight leases expire and `recover` decides — durable state and retention obligations are
untouched either way.
