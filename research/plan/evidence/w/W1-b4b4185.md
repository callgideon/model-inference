## Failure drill

The adapter holds **no durable state** — no journal, no wallet, no lease row — so "durable
state before/after" is not applicable to W1; W2 owns every durable mutation. What is
injected, and what is observed, per fault:

| Injection point | Injected by | Observed before / after |
|---|---|---|
| Connection refused before any response | `FakeUpstream(fault="transport_error")` | before: no request recorded past the handler; after: `EngineTransportError(stage=pre_headers)`, no event yielded, no partial output |
| HTTP 500 with a 2 kB error body | `engine_error_pre_headers` | after: `EngineError(stage=pre_headers, status=500)`, `stream.started is False`, `deltas == 0`, detail truncated to 500 chars, nothing relayed |
| SSE error object after one delta | `engine_error_post_headers` | after: `EngineError(stage=stream)` with `deltas == 1` already yielded — the caller knows output was published and must not regenerate (02) |
| Connection dies mid-stream (engine process exit) | `abrupt_exit` | after: `EngineTransportError(stage=stream)`, one delta already yielded, not a `DomainError` |
| Prefill silence with keepalives | `prefill_stall` | after: events are exactly `[progress]`, `stall == "first_token"`, usage unknown, `0 < pings < 40` (the adapter stopped waiting; the script had 33 more keepalives to send), elapsed > `TTFT_TIMEOUT_S` and < `GENERATION_TIMEOUT_S` |
| Mid-stream silence with keepalives | `midstream_stall` | after: deltas present, no usage event, `stall == "inter_event"`, elapsed > `TPOT_STALL_S` |
| Post-header read timeout | `read_timeout` | after: `stall == "inter_event"`, no exception raised into the caller |
| Cancellation mid-generation | `cancellation_race` + `cancel(lease)` | before: stream open, 2 deltas seen; after: upstream stream **closed** and not completed (the engine is told to stop), one usage event with unknown usage, `engine.cancelled` empty again |
| Cancellation before start | `cancel(lease)` then `generate` | after: `upstream.requests == []` (nothing was ever sent), one authoritative zero usage event |
| Usage missing / null / string / non-additive | `missing_usage`, `malformed_usage`, `string_usage`, `inconsistent_usage` | after: usage explicitly unknown in every case; no number is derived from the deltas |
| Usage or delta count past the ceiling | `over_ceiling`, `missing_usage` with `max_output_tokens=2` | after: `EngineProtocolViolation` carrying `TerminalCause.platform_error` |
| Junk data line | inline `MockTransport` | after: counted in `malformed_lines`, never relayed |

Duplicate/retry behaviour: `generate` is a fresh stream per call and holds no cross-call
state except the cancellation intent, which is discarded when the stream ends (asserted).
A repeated `cancel` for a lease that is not running leaves an intent that the next
`generate` for that lease consumes — noted under Limits.

Cleanup: every case runs in-process with `MockTransport`; no file, container, port or cloud
resource is created, so there is nothing to clean up. The mutation runner writes only
inside `tempfile.TemporaryDirectory` and the worktree is left clean (`git status` empty,
output above).

## Limits

1. **Fake-only.** Every result here is `httpx.MockTransport` against a scripted script.
   No real vLLM has parsed one of these bodies. `cache_salt`, `mm_uuids` and
   `mm_processor_kwargs` are sent under the field names `CACHE_SALT_FIELD` /
   `MM_UUIDS_FIELD` / vLLM's documented `mm_processor_kwargs`; **whether the pinned engine
   accepts those first two names is unverified** and is W3's capability probe (owner: W,
   with E on the allocated GPU). If a name is wrong the engine may ignore it, which would
   silently lose the tenant namespacing — so the probe must assert acceptance, not just a
   200.
2. **Read-timeout backstop untested at the transport layer.** `MockTransport` ignores
   `httpx.Timeout`, so the coarse read timeout is configuration only here; the stall bound
   that *is* proved is the injected-clock one plus a scripted `httpx.ReadTimeout`. A real
   hang is a Layer-3 case (owner: W3/E).
3. **Cancellation granularity.** `cancel(lease)` stops the stream at the next event and
   closes the connection. A stream blocked on a read notices only at its next event or at
   the read timeout; cancelling *instantly* means cancelling the asyncio task, which W2
   owns because W2 owns the task. Recorded in the code as a `ponytail:` note.
4. **Cancellation intents can accumulate** for leases that are cancelled and then never
   executed (a plain `set`). Bounded in practice by W2 cancelling only leases it holds;
   a bounded structure is the upgrade path if that stops being true.
5. **Inter-event budget comes from configuration**, not from the job's R4 `budgets`
   snapshot: `Lease` carries `first_token_deadline_at` and `generation_deadline_at` but no
   per-event stall instant. If a job's snapshotted `stall_s` ever diverges from the running
   configuration, W2 must construct the engine with the matching `limits` (or a contract
   revision must add the instant). Flagged for W2, not worked around here.
6. **Unclosed reasoning is dropped**, which differs from F1's non-stream regex (it keeps
   the remainder). Deliberate — reasoning must not reach a customer — and G owns retiring
   the F1 path; if product wants the remainder shown, that is a contract decision.
7. **`prompt_tokens` is an argument** to `prepared_request` because `Work` carries no exact
   prompt count; the caller (W2, from preparation) must supply the exact number. A wrong
   number changes only the zero-output cancellation usage and the context check, never a
   billable count, but it is an unverified interface until M2/W2 meet.
8. **Canonical messages must carry one media part per prepared ref, in order**, or the
   adapter refuses the request rather than guessing. G1's normalizer and M2's preparation
   must preserve that correspondence (integration request below).
9. `terminal_cause` on `EngineStream` is **advisory**: the store decides the real outcome
   (a `completed` cause with unknown usage is `engine_incomplete` at the store, R21/R30).
10. The mutation runner is a second copy of the machinery in `tests/contracts/mutants.py`,
    because that file hardcodes its pytest target and is not this track's to parameterise.
    Marked `ponytail:` with the factor-out as the upgrade path.

## Limits, revised

Round 1's limits 1-10 stand except as noted, plus:

1. **Unchanged and still the biggest one:** no real vLLM has parsed one of these bodies.
   The `cache_salt` and `mm_uuids` field names remain unverified (W3's probe must assert
   acceptance, not a 200).
2. **New, from the allow-list:** `storage_ref` is sent with **no URL scheme**
   (`media/<org>/v1/source`). Real vLLM needs a resolvable reference - `file://` plus an
   allowed local media path, or an equivalent - so M2/W3 must decide the exact form; the
   adapter's rule is only that the customer's own value is never used.
3. **New:** the engine must **not** be started with `--reasoning-parser`. This adapter
   reads `delta.content` only, so a parser that moves reasoning into `reasoning_content`
   would drop it - and `raw` is what trace capture keeps, so the trace would lose it
   silently. Named in the code beside the read; W3 owns the engine flags.
4. **New (`est.`):** the accumulated-output bound is 64 code points per output token, and
   one event carries at most an eighth of `JOURNAL_EVENT_MAX_BYTES` in characters. Both
   are provisional engineering limits like every number in 08 §5, chosen with ~16x
   headroom over real text; E's corpus run is what would justify tightening them.
5. **Withdrawn:** round 1's limit 8 ("canonical messages must carry one media part per
   prepared ref, in order, **or the adapter refuses**") is no longer a limit but the
   contract (R58), and G1 enforces the same shape before admission.

## Handback additions

**Integration requests added by this round:**

6. **Coordinator: the shared fake and the exported engine cases must emit `visible` and
   `raw`** (R58 says so explicitly). They currently read `payload["content"]` and assert
   the *unfiltered* text there, so this adapter keeps `content` as a transitional alias of
   `raw` to pass the suite unchanged. The alias is marked in `_delta_payload` and goes in
   the same change that updates `contracts/fakes/engine.py` and
   `conformance/services.py`. Until then, **no relay may read `content`** - a relay that
   does leaks the reasoning block.
7. **G1 owns sampling-parameter ranges.** The adapter's allow-list decides which knobs
   exist (`temperature`, `top_p`, `top_k`, `min_p`, `seed`, `stop`, the three penalties);
   it does not check that `temperature` is in `0..2`. That validation belongs at admission,
   with the token-ceiling range checks R55 already gives G1.

**Notes for W2, beyond round 1's:**

* `terminal_cause` returns `completed` only when `finish_reason ∈ {stop, length}` **and**
  the usage is authoritative; a finished stream with unknown usage is `engine_incomplete`,
  which is what D does with a delivered success that has no count.
* **Stamp TTFT at the first RAW nonempty delta**, not the first visible one: a reasoning
  block can make the first customer-visible character arrive seconds after the engine
  started producing, and TTFT is an engine measurement.
* A stall never raises: read `EngineStream.stall` (`first_token` / `inter_event` /
  `generation`) and `terminal_cause`. `generation` is `deadline_exceeded` (platform's own
  deadline, R21), the other two are `engine_incomplete`.
* Cancellation intents are keyed by `(job_id, generation)`: never call `Engine.cancel`
  with a lease of another generation to stop the current attempt - it will not stop it,
  and it must not.
* Per round 1's carried note, now confirmed in `apps/infrx-api/infrx/contracts/README.md`
  ("Notes per track", rows **W1/M1** and **W1**): `already_terminal` means the store
  terminalized the job in that same call - acknowledge the index event and stop;
  `stale_lease` leaves the state unchanged for `recover`.
