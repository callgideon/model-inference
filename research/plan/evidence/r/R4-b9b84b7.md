## Design (one line each)

- Port `ReleasesPort`: `releases(actor)` = D9 rows (+ R1 `Live` progress with assignment counts, + R2 latest verdict), D9 decisions, proposals; `variants(actor)` = R3 `lab.optimization_variant.1` + both `Identity` scopes + `infrx.variant_comparison.1`; `propose(actor, expand|rollback, policyRef, fence)`. Actor/Result/refusals/`holds` reused from L4's `lib/services/control/port.ts`.
- Fails closed: `unavailable` until the adapter is wired; `LAB_RELEASES_PREVIEW=1` (exactly) and not production = the in-memory stand-in, labelled on both pages.
- Promotion: `expand` is offered only on a running release whose R2 verdict is `expand` (R2 only returns expand on a bound accepting B2 report); a `report_inconclusive` hold names the inconclusive evaluation. Proposals need `propose_publication` (administrator) and carry the fence the page showed; stale fence, pending proposal, non-expand verdict, rolled-back release = conflict (fake = the WR-R4-1 contract).
- Rollback is displayed only from D9 state `rolled_back` + decision records (who, when, reasons, evidence); a proposed rollback reads "awaiting operator approval". Operator decides via R2 `approve`/`emergency_rollback` (fake `decide`); a stale approval is rejected untouched.
- Spend in another unit than the budget is named, never converted; empty/idle metrics render `—` (no division by zero).
- Optimizations: scope = engine version + hardware + quantization + capabilities for base and variant; performance is "measured" only when every source is `<exp>/results/...@<sha>` (R3's `RESULTS`), else "synthetic fixture, not a measurement"; claim and release eligibility only for an `equivalent` comparison.
- No launch/cohort/allocation/budget form (public shadow/canary waits on P-12); ponytail: preview starts empty (no demo seed); add one if a visual review needs it.
