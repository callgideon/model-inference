## What `submit` does, in order (each step is a named mutant)

1. mode exactly `live` (R57) — `live_mode_not_required`;
2. the payer is a `lab:payer:` ref of **this** provider (R159) — `any_payer_pays`, `any_ref_is_a_payer`;
3. L2 `authorize_content` for `external_judging` over **both** `request_content` and `response_content` (current developer+ membership and current grant, store clock); its (grant_id, version) is the run's consent snapshot — `permission_not_checked_first`, `any_purpose_judges`, `questions_alone_send_answers`;
4. the rate effective on the ledger's clock; unpriced refuses (APPROVED_RATES stays empty) — `unpriced_model_reserves`;
5. D6J reserve of the worst case over **every** sample, PROVIDER_USD — `reservation_is_one_sample`;
6. D6J `begin_submit`: only the call that created the intent egresses (double click, restarted worker) — `any_caller_egresses`;
7. content from T2I `read_content` by durable request id, grantor's org bound; no content = skipped; nothing left = released — `content_read_as_the_provider`, `missing_content_sent`, `empty_batch_sent`;
8. L2 again immediately before egress; a withdrawal releases the hold — `no_recheck_before_egress`, `revoked_run_keeps_its_hold`;
9. one provider call, never retried: `SubmitRejected` releases, anything else quarantines `ambiguous` with the hold kept — `rejection_is_ambiguous`, `unknown_outcome_released`.

`reconcile`: only `ambiguous`; lookup by submit key → adopt (`submitted`) or release (`failed`), never a second submit — `evidence_ignored`, `no_record_keeps_the_hold`, `submitting_run_reconciled`. `collect`: `validate_json` per item with the run's media set, `ScoreLedger` drops foreign samples, D6J stores once per (run, sample, rubric version), settles once when done — `foreign_sample_projected`, `every_sample_has_media`, `no_sample_has_media`, `settled_before_done`, `completed_run_collected_again`. HTTP: loopback `http` only, no environment proxy, 4xx rejected, any non-200 ambiguous (even carrying an id), 404 lookup = no record, the run's own key — `any_host_egresses`, `tls_to_loopback_accepted`, `proxy_from_the_environment`, `http_rejection_is_ambiguous`, `a_5xx_with_an_id_is_submitted`, `lookup_404_raises`, `lookup_by_the_wrong_key`.

## Schema request SR-J2-1 (D6J, lab-sql-lw2) — the port J2 consumes (`submit.JudgeLedger`)

Tables (additive, Lab-only): `infrx.lab_judge_budgets(payer_ref text pk, provider_org_id uuid, limit_value numeric(20,8) >= 0, unit 'PROVIDER_USD')`; `infrx.lab_judge_runs(run_id uuid pk, provider_org_id, payer_ref fk, grant_id uuid, grant_version int, sample_ids uuid[] (unique elements), media_ids uuid[], price_version text, reserved numeric(20,8), actual numeric(20,8) null, state in external_run states {prepared, submitting, submitted, ambiguous, failed, cancelled, completed}, submit_key text unique = 'submit:'||run_id, external_id text null, created_at/updated_at infrx.now())`; `infrx.lab_judge_results(run_id, sample_id, rubric_version, accepted bool, result jsonb, primary key (run_id, sample_id, rubric_version))`; `infrx.lab_judge_audit` append-only (run_id, event, reason, at). Service-role RPCs, each `jsonb` in / row out:

| Port method | RPC | Rule |
|---|---|---|
| `db_now()` | `select infrx.now()` | the only clock |
| `reserve(...)` | `lab_judge_reserve` | `FOR UPDATE` on the payer row; committed = Σ reserved over {prepared, submitting, submitted, ambiguous} + Σ actual over completed; refuse (BudgetExceeded) when committed + max_cost > limit; payer's provider = run's provider; idempotent per run_id (another provider's run_id = no_data_found) |
| `begin_submit(run_id)` | `lab_judge_begin_submit` | `update … set state='submitting', submit_key=… where state='prepared' returning` → `(run, created)`; otherwise `(run, false)` |
| `record_submission(run_id, id)` | `lab_judge_record_submission` | submitting/ambiguous → submitted; same id idempotent; a different id conflicts |
| `quarantine(run_id, reason)` | `lab_judge_quarantine` | submitting → ambiguous, hold kept, audit row |
| `release(run_id, state, reason)` | `lab_judge_release` | declared transitions only; the hold stops counting |
| `record_results(run_id, results)` | `lab_judge_record_results` | `on conflict do nothing`; returns rows inserted |
| `settle(run_id, actual)` | `lab_judge_settle` | submitted → completed once; actual ≤ reserved (else refuse and audit) |
| `run(run_id)` | `lab_judge_run` | the row |

Plus: a lease/expiry sweep that moves a `submitting` run whose worker died to `ambiguous` (J2 never reconciles `submitting`, see open issues). JUDGE-BUDGET "real DB contention" is proved only by this SQL: the fake's race case runs in one event loop.

## Open issues

1. D6J is fake; the coordinator reruns `tests/j/submit` against lab-sql's repository after it merges (the port may need renaming to its RPCs; the behaviour cases stay).
2. A `submitting` run left by a crashed worker needs D6J's sweep (above) before `reconcile` can resolve it.
3. `reconcile` releases on "no provider record": sound for the local fake (keyed, synchronous); a P-10 adapter must prove its lookup is authoritative for the submit key or never release on absence.
4. ClickHouse not exercised (no CH port on the j2 key): T2I's `read_content` is real, its projection is in memory.
5. `settle` with actual > reserved is refused by the fake; D6J should record and alert rather than leave the run `submitted`.

## Proposed rulings (unnumbered)

- *J2 egress:* only the call that created a run's submit intent may send; an unknown outcome is `ambiguous` with the reservation held; reconciliation is by provider lookup of the submit key only; the HTTP judge adapter is loopback-`http` only, ignores environment proxies, until P-10.
- *Lab judge consent/budget:* the consent snapshot is the (grant_id, version) of the grantor's current `external_judging` grant covering `request_content` **and** `response_content`, rechecked immediately before egress; the reservation is PROVIDER_USD against a named `lab:payer:` ref of the same provider.
