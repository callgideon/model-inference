## Behaviour
- H1.a: `revision_ref(payload)` = the F3 ref of a `lab.harness_revision.1` (prompt template, processor profile, input mapping, tool schemas with effect read_only/network_mutation/actuator, reference output); any content change is a new identity; no code field and only the three built-in adapters (text/finite_video/structured) exist.
- H1.b: `Replayer(harness, deployment, model, recordings, Bounds, clock)` refuses a non-dev deployment (`Forbidden`, before any call); tools are never executed: a declared read_only tool is answered only from `recording_key(name, arguments)`; network_mutation/actuator -> `blocked`; undeclared tool, missing recording, missing input, video over 82 s -> `unsupported`; blocked/unsupported are not comparable, `coverage()` counts every reason. Requests/bytes/seconds bounded per run: first breach raises `ReplayBoundExceeded` (typed `BudgetExceeded`) and the run stays stopped. The harness is re-derived before each case: an edit mid-run is `StateConflict`.
- H1.c: `bind(run, harness_ref, rights=)` validates the pinned run via F3 (mutable or cross-provider ref refused before any rights read) then asks the rights port at `Gate.schedule`; `compare(a, b, multifactor_tag=)` -> rerun / single_factor / multifactor (tag required); different provider/dataset/evaluator/environment/max_cases is not comparable.
