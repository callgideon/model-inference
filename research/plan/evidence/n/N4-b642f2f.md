## What exists
- `lib/services/datasets/port.ts` — `DatasetsPort` and `httpDatasets({baseUrl, token})`: every call goes to `/lab/v1/providers/<provider, URL-encoded>/datasets/...` with only `Authorization: Bearer <the user's own session token>` and `cache: no-store`; HTTP refusals become named failures (403 denied, 404 not_found, 400/413/422 invalid, 409 conflict with `leaks` / rejection `report`, 410 gone, anything else unavailable); every 2xx body is parsed field by field (unknown import state, unknown split, negative count, published-without-dataset → `unavailable`, never success); network error → unavailable; `offlineDatasets()` when unconfigured or tokenless; `failureStatus` for the download routes (a failure is never a 200).
- `lib/services/datasets/flows.ts` — the server actions' decisions, pure: a viewer is refused before any call; the provider is always the guarded workspace's (a submitted `providerId` is ignored); a spec that is not a JSON object, a missing/empty file, an upload over `MAX_UPLOAD_BYTES` (1 MB: the server-action body - ponytail, WR-N4-1 upgrade path), a non-UUID dataset id, bad or >10000 basis points, a derivation with no parent, an export TTL outside 1 s..7 d never leave the Lab; the preview sends only the first 64 KiB; a backend failure is an error state with its copy, leaks and report.
- `lib/services/datasets/views.ts` — success copy only for a published job with its dataset; running jobs poll; rejected/failed say how to resume (same import id); rejected-row JSONL download of line/reason/detail only; split summary with restricted counts; restriction explanations (unknown reason still restricted); leakage warnings (leaks, near-duplicate review families, holdout relatives).
- `lib/services/datasets/server.ts` — the request's port: server-only `LAB_DATASETS_API_URL` + the Supabase session's access token (no service key exists in the Lab).
- `app/(provider)/datasets/` — `page.tsx` (versions list with empty/error/denied states + import wizard), `forms.tsx` (client: wizard with preview then import, derive, export; pending states; `role=alert/status`; labelled controls, keyboard-native forms), `actions.ts` (four guarded server actions; import redirects to its job), `[ref]/page.tsx` (splits, samples, provenance incl. trace request and content bound, restriction explanations; a foreign/unknown ref is a 404; derive over this version as frozen base; export), `imports/[id]/page.tsx` (backend job; meta refresh while running; rejected-rows link), `imports/[id]/rejected/route.ts`, `exports/[id]/[part]/route.ts` (the part through the backend's gate; the browser never gets a storage URL or credential).
- Real N1/N2 (N4.c): `tests/n/backend.py` `router()` = the proposed backend route (WR-N4-1) over the real `imports`/`versions`/`lineage` + `PgLabDataStore` + `LabAccess(PgAccessStore)`; long imports run as backend tasks (POST answers `running`); `main()` (test-only) seeds the D7 world on the n3 key, uses the bearer token as the user id and honours `_crash_after_puts`. `tests/n/journey.test.ts` drives the flows and the real HTTP port through it.
