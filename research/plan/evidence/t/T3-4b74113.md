## Design

- **Logical at once.** `Retention.delete(org, request, reason)` writes a `request` tombstone to `trace_deletions`
  (ClickHouse, `ReplacingMergeTree(state)`, 1 pending / 2 cleaned, FINAL, key `(org_id, request_id, scope)`, no TTL) and
  returns it: the **deletion receipt** (`receipt()` reads it back, with `cleaned_at` once physical cleanup completed).
  From then `find_traces` / `find_feedback` return nothing and `read_content` None, while rows, objects and spool bytes
  still exist. Org-bound: another tenant deleting the same request id hides nothing of this one's.
- **Logical expiry**, independent of any TTL: content unreadable from `started_at + trace_content_max_days` (at the
  instant it has passed - 02 §4's rule), metadata and feedback from 13 calendar months (`add_months`). The 13-month
  ClickHouse TTLs on `trace_envelopes`/`feedback_events` are physical cleanup only.
- **Physical after.** `expire()` writes one `content` tombstone per stored object past its bound (anti-join, so once);
  `sweep()` works pending tombstones: deletes the request's objects - only keys under its own org's `trace/{org}/`
  prefix - then, for `request` scope, lightweight-`DELETE`s its `trace_envelopes` and `feedback_events` rows, then marks
  the tombstone cleaned. Idempotent; a failure leaves the tombstone pending (`failed`) for the next sweep (OPS-RECOVER).
- **Kept:** content a live grant or export references (`holds(org, request) -> bool`) is not physically deleted; its
  tombstone stays pending (`held`) - still logically deleted for the owner's reads - until the reference ends.
- **No resurrection.** The shipper asks `verdicts(envelopes)` per segment: a deleted (or metadata-expired) record is
  dropped and the object a previous attempt may have written at its derived key is deleted; a content-deleted or
  content-expired one ships metadata only. So a lost-ack replay, a record still in the spool when deleted, and an object
  whose row never landed all end with nothing, and the segment is acked away (the spool is reached). The feedback
  projector drops a deleted/expired request's rows and acknowledges them. Tombstones are never TTL'd.
- **Gauges and alarms.** `gauges(retention, spool=, outbox=)`: `infrx_trace_eligible_{full,minimal}`,
  `infrx_trace_lost_{mode}`, `infrx_trace_content_bytes_{mode}` (off has no rows, so it is in no denominator),
  `infrx_trace_loss_ratio`, `infrx_trace_deletion_backlog` / `_held` / `_backlog_seconds` (held excluded),
  `infrx_trace_spool_bytes`, `infrx_trace_spool_unacked_records`, `infrx_trace_capture_dropped`,
  `infrx_feedback_projection_backlog`, `infrx_feedback_projection_lag_seconds`. `RULES` (infra/alerts shape):
  TraceDeletionBacklogOld (> 86400 s, derived O3), FeedbackProjectionLagging (> 900 s, est. ⚠️ TO BE VERIFIED),
  TraceLossHigh (> 1%, est. ⚠️ TO BE VERIFIED), TraceSpoolFilling (> 80% of TRACE_SPOOL_MAX_BYTES, derived). I2L-OBS
  deploys them (WR-T-5). No copytruncate path: the spool deletes only whole acked segments (`ack` unlinks), T1/T2I.

## Found defect (fixed in owned files)

`tests/integration/harness.apply_trace_schema` (T2I WR-1, merged) splits `schema.sql` on `;`; `ship/schema.sql` carried
`;` inside comments (`No content here; it is …`, `Additive; …`), so the harness would send a comment fragment as a
statement. On the base (`c9578fda`) the splitter yields 2 fragments, neither valid SQL (`'it is an object at
`content_key`.\n-- Additive'`, `'the E2 stack applies it only through coordinator wiring (T2I…'`), so
`harness.wait_all()` → `apply_trace_schema()` raises on any E2-stack bring-up that reaches it (E3L/E5L gates). The
three schema files now carry no `;` outside the statement terminator (3 statements for the three files, command 5).

## Open issues

- **Schema request (lab-sql, not this lane):** a deletion reaches the feedback *projection*, not PostgreSQL's
  `infrx.feedback` rows (0028 makes them immutable; D6F's evidence already names "retention/scrub of feedback text
  (T3) will need its own path past the immutability trigger"). Proposed: an additive `infrx.scrub_feedback(org,
  request)` SECURITY DEFINER that nulls `comment`/`value_text` under an audit row, called by `sweep` for a `request`
  tombstone. Until then the durable feedback text outlives a trace deletion.
- Per-org owner-selected retention (≤ 90 d) is not read: the bound is the platform's `TRACE_CONTENT_MAX_DAYS` (consumer
  capture is OFF in v1, R140; the consent source is P-09). A `content_days` per org is a constructor argument away.
- Tombstones are ClickHouse-durable, not PostgreSQL: a PostgreSQL deletion ledger (receipts under RLS) is a lab-sql
  migration if the receipt must be customer-visible.
- A shipper insert racing a sweep can leave a physical row after `cleaned`; every read still filters it (tombstones
  are permanent) and the 13-month TTL removes it.
- Backlog gauge scans at most 10,000 pending tombstones (`ponytail:` note).
