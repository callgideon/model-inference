* `infrx/media/probe.py` — duration, frame size and codec read **from the bytes**, for
  ISO base media (MP4/M4V/MOV) and Matroska/WebM. No ffmpeg, no ffprobe, no PyAV: this
  host has none (CLAUDE.md) and the pinned environment has no media dependency, so both
  containers are parsed directly. Written for hostile input: an explicit stack instead of
  recursion, every declared length compared with what is really there, a depth bound, an
  element budget, no allocation from a number the file chose. A container with no parser
  is `unsupported_media`, never a guess.
* `infrx/media/prepare.py` — `MediaProfile` (the one constants table), `ProcessingCache`
  (versioned, tenant-scoped, digest-keyed, 7-day) and `MediaPreparation`, a subclass of
  M1's `MediaStaging` that adds `prepare_request(org_id, request)`, the port's
  `prepare(job_id, profile)` and `local_uri(ref)`.
* `infrx/media/store.py` — the `facts(data, mime)` hook `materialize` now consults before
  it writes (M1 answers "the declared type, no duration"; M2 answers with the probe), and
  `ObjectStore.get`, which preparation needs because it runs later and possibly in another
  process than intake.

### The two naming decisions a reviewer should check first

1. **`prepare_request`, not `prepare(org, request)`.** The task brief names
   `MediaStaging.prepare(org, request)`; the frozen port
   (`contracts/ports.py` `MediaStore.prepare`) and the exported conformance suite say
   `prepare(job_id, profile)`. They are two different operations — one runs at admission
   before a job exists, the other inside a preparation lease — so the port operation keeps
   its signature and the admission-time one is `prepare_request`. Renaming either is a
   coordinator decision (integration request 4).
2. **`local_path` is derived, not carried.** `MediaRef` is `extra="forbid"`, so the
   coordinator's `local_path` field cannot be added from here. `local_uri(ref)` rebuilds
   the path from the ref's tenant, digest and profile version through the cache, which
   means there is nothing on the record to forge; when F2R adds the optional field,
   filling it is one line in `prepare` (integration request 1).

## Failure drill

The table in "Deliverable 5" above is the drill register: injection point, durable state
after, and the mutant that proves each one. The four that matter most for durable state:

1. **Store put failure mid-batch.** Injected in the object store's second
   `put_if_absent`. Before: nothing staged. After: the typed `dependency_unavailable`
   propagates, `by_job` and `prepared_by_job` are empty, at most one object exists, and
   because every object is content-addressed and write-once the client's retry reuses it
   rather than duplicating it. Cleanup: none needed — no job, no hold, no attachment.
2. **Probe deadline.** Injected as a probe that awaits a future nobody resolves. After:
   `deadline_exceeded` (platform-side, so R21 makes it unbilled), no object, no cache entry.
   Known residue: `asyncio.to_thread` means a *synchronous* probe that hung would keep its
   worker thread (limit 4 below).
3. **Object vanished / content changed between `attach` and `prepare`.** Injected by
   removing or replacing the object behind the staged key. After: `not_found`, no cache
   entry, and the counting store shows the body was never downloaded when HEAD already
   said no.
4. **Cache expiry and a file deleted behind the index.** Injected by moving the cache clock
   past 7 days, and by removing the file. After: the entry is unreadable, the file is gone
   from the disk, `local_uri` is `not_found`, and the next preparation re-materializes from
   the durable object.

## Limits

No inferred pass. What is **not** demonstrated:

1. **`video/mpeg` is refused.** `ALLOWED_VIDEO_MIME` lists it, and an MPEG-1/2 program
   stream carries no duration in a header (it is derived by scanning presentation timestamps
   to the end of the file), so there is nothing to read cheaply and the probe refuses it
   rather than guessing. This **narrows the accepted set** against S2M §2.5. Owner:
   coordinator — either drop `video/mpeg` from the setting (integration request 3) or accept
   that it is refused as `unsupported_media`. Not a silent pass: it has a test.
2. **No real decoder has ever agreed with this probe.** Durations, geometries and codecs
   are read by a parser proved against containers this repository builds. A clip produced by
   a real encoder has not been probed, and no engine has decoded a prepared artifact.
   **Pending** a host with ffmpeg or PyAV (the measurement half of **P-06** — exact Marlin capabilities and finite-video launch limits — and an input to **P-18**; `models/marlin2b/corpus/`
   has real clips and a pinned ffmpeg build the corpus builder fetches, which is a network
   download this session was not authorized to make). Owner: M or E at the first GPU host.
   The check that matters is `models/marlin2b/tokens.py` on a real clip versus this probe's
   duration.
3. **`local_path` is not on the record.** W2/W3 cannot read it from a `MediaRef` yet;
   `local_uri(ref)` is the only way to it. Integration request 1.
4. **A synchronous probe that hangs keeps its thread.** `asyncio.wait_for` abandons the
   *wait*, not `to_thread`'s worker. The shipped parser cannot hang (`MAX_ELEMENTS` bounds
   it), so this is reachable only through an injected probe — the same limit M1 recorded for
   `getaddrinfo` (its limit 3). Owner: M, if a real decoder is ever called here.
5. **No transcode.** Profile `v1` re-encodes nothing: the prepared artifact is the source
   bytes and the frame/pixel budget is applied by the engine from the measured duration
   (the pinned Path A). "No-upsize aspect-preserving even dimensions" from the original M2
   brief is therefore **not implemented** — there is no ffmpeg to do it with, and at the
   pinned profile it would cost quality for nothing (S2M §1.5). CRF23/CRF28 parity and the
   distinct-clip MEDIA-PARITY numbers the brief asks for are **pending** the same GPU/ffmpeg
   host as limit 2. `_prepared_bytes` is the one method a transcoding profile replaces.
6. **No real object store.** Only `InMemoryObjectStore`. `get` was added to the port for
   preparation, so the S3 adapter now needs `HeadObject`, `GetObject` and `PutObject` with
   `If-None-Match: *`. **Pending** (M1's limit 2, unchanged).
7. **The processing cache is a local filesystem with an in-process index.** It is not
   shared between processes: a second preparation worker re-materializes rather than
   reusing, and its expiry only runs while a process is alive. For the single-host pilot
   that is the coordinator's decision; for more than one host the index belongs in the
   database or the cache in a shared mount. Owner: I/D after the pilot. There is no
   `PROCESSING_CACHE_DIR` setting yet, so the root is a constructor argument (integration
   request 2) and an unset root means `prepare` produces refs with no local copy and
   `local_uri` raises.
8. **Cache capacity is unbounded.** Nothing caps the cache's total size; only the 7-day
   expiry and `MAX_PREPARING_JOBS` bound it. At 64 MiB per object that is a disk-fill risk
   on a small NVMe. Owner: M3's GC (it owns orphan collection) or I2's host sizing.
9. **One conformance case is blocked** on F2R item 4 (above). M2's adapter is therefore not
   conformance-proven for the shared `prepare` case, only for its invariants.
10. **Upload-kind refs are untested through `prepare`.** `prepare` rebuilds the source key
    as `media/<org>/<profile>/<digest16>/source`; if M3 stores finalized uploads under a
    different key, `prepare` will not find them. Owner: M3, with a case in the M suite.
11. **`prepare_request` discards `NormalizedRequest.media` silently** rather than refusing a
    request that carries one. Safe (the forged ref cannot survive, and there is a test), but
    it would hide a G2 bug that passed media in. Owner: G2 at the cutover, if it wants the
    stricter version.
12. **Three container behaviours the probe does not read**, measured and recorded in its
    module docstring rather than assumed: `edts`/`elst` edit lists are ignored (an edited
    clip is reported at its untrimmed `mvhd` duration); a version-0 `mvhd` duration of
    `0xFFFFFFFF` ("unknown") is read as 4,294,967.295 s and then refused by the **duration
    cap**, not by the probe; and a fragmented MP4 (`mvhd.duration = 0` with `mvex`/`mehd`)
    is refused as `no-duration`, so fMP4 and DASH/CMAF segments are not served. Owner: M,
    if a customer needs fMP4 — `mehd` is a hint rather than the real sum of fragments, so
    the cap would be enforced against a number the file may understate.
13. **`sop-synth-v1` was not built.** S2M §3.8's corpus needs the pinned ffmpeg build the
    corpus builder downloads; no network fetch was made. The adverse-media fixtures here are
    synthetic containers instead, which cover the *parser* cases that corpus does not
    (a box shorter than its header, `inf` durations) but none of its decode cases.
