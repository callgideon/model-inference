## Failure drill

Both drills are committed tests, so they are rerunnable rather than described.

1. **Storage fault at the payload write** (`test_a_fault_at_the_payload_write_stages_nothing_and_the_retry_completes_it`).
   Injection: an object store that raises `DependencyUnavailable` for any `payloads/` key,
   after one source has already been materialized.
   Durable state before: one media object (`media/<org>/v1/<digest16>/source`), one indexed
   ref, no payload. After the refused `stage`: **unchanged** — no new object, no second ref
   indexed (the fresh reference in the same request is not left behind), no payload
   recorded, so acceptance cannot proceed on half a request. Retry once the store recovers:
   one payload object added, both refs returned, no second media copy
   (`len(objects) == before + 1`). Mutant `index_before_the_payload` proves the ordering is
   what makes this true.
2. **Crash between the object write and staging** (`test_a_crash_between_the_object_and_the_index_leaves_a_retryable_orphan`).
   Injection: the process is replaced by a new `MediaStaging` over the same bucket after
   `materialize` and before `stage`.
   Durable state before the restart: exactly one object, keyed by its own digest, with no
   index entry — an orphan M3's collector can identify from the key alone. After the retry:
   the same key and the same handle (content-addressed), byte-identical bucket contents, and
   one staged request. Duplicate/retry behaviour: idempotent, no second copy and no second
   handle.
   Cleanup: no cleanup needed — every drill runs in memory in the test process; no
   container, temporary directory or cloud resource was created by this task at all.

## Limits

No inferred pass. What is *not* demonstrated:

1. **TLS verification against the pinned address is not exercised end to end.** The pin is
   proved at the request level (URL host = validated IP, `Host` and `sni_hostname` = the
   original host, and httpcore uses `sni_hostname` as `server_hostname` for the handshake).
   No test opens a real TLS connection, so certificate validation against a pinned IP is
   **pending** a layer-2/3 case with a real server and a real certificate. Owner: E or M at
   G1/G2.
2. **No real object store.** Only `InMemoryObjectStore` exists; the S3-compatible adapter
   (`head`/`put` map to HeadObject/PutObject, task-local port 59100 per 08 §8) is an
   integration request below and its conformance run is **pending**.
3. **Seven of nine exported conformance cases did not run** (skips listed above). M1's
   adapter is not conformance-proven for uploads (M3) or preparation (M2).
4. **No real DNS.** `resolve_all` (the default `getaddrinfo` resolver) is never executed by
   a test; every case injects a resolver. A scoped literal such as `169.254.169.254%eth0`
   is refused, but real dual-stack answer ordering is unverified. Owner: M at G1.
5. **Nothing is integrated.** No gateway route calls `materialize`/`stage`; the legacy
   `prepare_video` path is still what the running app uses. This report claims
   *implemented*, never integrated.
6. **`http://` sources are still accepted** (F1 behaviour, validated and pinned per hop).
   Refusing plaintext outright is a policy decision for G1, not a silent change here.
7. **The whole body is held in memory** (bounded by `MAX_MEDIA_BYTES`, 64 MiB), as the F1
   path does. M2 needs a file for ffprobe/ffmpeg; if a streaming sink is wanted instead of
   `bytes`, that is M2's call and a one-parameter change.
8. **The mutation runner copies the package per mutant** (51 subprocesses, ~45–85 s
   wall-clock depending on host load), which is why the default suite runs a five-mutant
   subset.
