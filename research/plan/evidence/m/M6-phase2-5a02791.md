## What was built

**(1) Writers register before they write; the collector is D10's.**

- `MediaStaging` (store.py) now owns `content` (a `ContentLifecycle`, D10's `PgLifecycle` in the pilot) and `_register`. Every object the runtime writes gets its row, `origin=written`, before its bytes:
  - upload destination before the PUT's write (M5, unchanged);
  - verified upload source before the copy (M5, unchanged);
  - **fetched source** (`materialize`, new);
  - **staged envelope** (`stage`, new; `kind=payload`, `job_id` = the request id);
  - **prepared artifact** (`prepare`, new; `kind=prepared`, `job_id`).
- Database content (`jobs/<id>`, `job_results/<id>`) is registered by D10's triggers; the collector scrubs it through `acknowledge_delete`.
- The upload/stage-versus-delete race is the tombstone's `content_retiring`: a writer re-creating a key under delete gets a retryable 503 (`retry_after_s` 5) before it writes a byte.
- `gc.py` is deleted. Its upload-destination sweep is D10 candidates/claim/tombstone over the destination rows (a closed ticket's destination is unreferenced and goes after its grace). Its object deletion was the RV-03 defect. Its cache half moved into `ProcessingCache`.
- `DraftLifecycle`, `PgLifecycleStandIn` and the `fake`/`pg` worlds are deleted. The suites run on `f2c` (F2C's reference adapter) and `d10` (D10's `PgLifecycle` on real PostgreSQL, a fresh migrated database per case).
- **The collector deletes the key the writer wrote** (`tombstone.object_key`). `generation_key` is removed. Writers write the bare key (MediaRef, D10 admission and `content_referenced` all match on it), so `key.g<n>` named an object nobody wrote: a re-created key's deleted row would have leaked its bytes. The delayed-delete guarantee rests on the tombstone plus D10's lease rule (below).

**(2) Bounded, restart-recoverable maps and cache.**

| Map / cache | Phase 2 |

| `idle_since` | deleted with `gc.py`'s object deletion |
| `MediaUploads.uploads` | M5: no process state; property kept for `ProcessUploads` tests |
| `ProcessingCache.entries` | `Recent` memo; **the disk is the index** |
| `ProcessingCache.sweep()` | walks the root: a file past mtime + TTL, a file dated in the future, a `.part` past `PART_GRACE_S` (1 h); never a pinned file |
| high water | `max_bytes`: a put that would cross it evicts the oldest unpinned files down to `LOW_WATER` (0.8); a `.part` in flight is never evicted |
| admission under pressure | all remaining files pinned: the put raises retryable `dependency_unavailable` (30 s) before writing; `prepare` has already written the durable artifact (the record), so correctness holds and the job re-prepares |

## Proposed ruling text (revised; the coordinator numbers it)

> Content deletion is authorized only by a committed tombstone of a fenced, unexpired claim on one `(content_id, generation)`.
>
> - The external delete names the key the writer wrote. It runs after that commit, outside every lock, and is idempotent. It is sent only while the claim has at least one object-store request timeout left, measured from before the claim was requested; otherwise the content stays tombstoned for a later claim.
> - A tombstoned key refuses registration (`content_retiring`, a retryable 503) until its delete is acknowledged, and none is acknowledged before its delete returned. A delayed delete therefore never reaches a later generation.
>   - The residual is a request the client abandoned that lands more than (claim TTL − request timeout) later.
>   - Generation-keyed physical names are the upgrade. They need the generation on `MediaRef` and in D10's key matching.
> - Every object the runtime writes is registered (`origin = written`) before its bytes: destinations, sources (uploaded and fetched), staged envelopes and prepared artifacts. Database content is registered by D10's triggers, and its deletion is the acknowledgement's scrub.
> - A pass stops on `DependencyUnavailable` from either store (retain and report). Only keys under `media/`, `uploads/` and `payloads/` without a `..` segment are ever deleted. The reference recheck runs inside the tombstone's transaction under the row lock admission takes.
> - Process maps are bounded caches of durable records. The local cache's disk is its index: expiry by file mtime, the high water down to the low water, and never a file under a pin. A full cache refuses retryably after the durable artifact is written.
