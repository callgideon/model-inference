## Design (one line each)

- `port.ts`: `ControlPort` (models, deployments, proposals, aggregates; register → model revision + private dev deployment; smoke; propose publish|rollback) with `Result<T>` refusals `denied|not_found|invalid|conflict|unavailable`; `holds(role, cap)` mirrors `contracts/v2` `ROLE_CAPABILITIES` (viewer: health; developer: + manage_dev_deployment; administrator: + propose_publication); `Aggregate` = L2's `DeploymentAggregate`. `controlPort()` is **unavailable** unless `LAB_CONTROL_PREVIEW=1` outside production (labelled in the layout).
- `fake.ts`: what L3 must enforce — provider scoping (foreign id = not_found before any role check), capability (denied), digest shape (invalid), smoke before publish, one pending proposal per revision, rollback only with an earlier prod revision (conflict). `decide`/`discoverable` stand in for the operator boundary and App discovery; the Lab never calls them.
- `view.ts`: rows show model, `serving@label`, runtime, schema, rate card (or "unpriced"), `env · visibility`; actions derive from record + role; a pending proposal reads "awaiting operator approval" and blocks another; health rows copy named fields only; `?refused=` becomes fixed copy only for a known reason.
- `actions.ts` ("use server"): actor = the session workspace (never form fields); capability then shape refused before L3; L3's refusal → `?refused=<reason>`; success = plain redirect back to the records (no success flag anywhere).

## Wiring requests

- **WR-L4-1 (interface request → lab-access-lw2 L3; ruling proposal)** The Lab reaches L3 as the signed-in user, never with a service key (the Lab holds none). Proposed: an infrx-api router `/lab/v1/control` (mounted by the coordinator behind `LAB_CONTROL`, default off) that authenticates the Supabase access token the Lab forwards, resolves membership through `LabAccess` (foreign workspace 404, missing capability 403), and exposes: `GET models|deployments|proposals|aggregates?provider_org_id=`, `POST register {name, artifact_digest, schema_version, runtime}` (→ the model revision and its private dev deployment revision), `POST deployments/{id}/smoke`, `POST proposals {kind: publish|rollback, deployment_revision_id}`. Records as `port.ts` (snake_case on the wire); errors map 404→not_found, 403→denied, 422→invalid, 409→conflict, 5xx/transport→unavailable. Operator approval stays outside the Lab. The adapter (`lib/services/control/http.ts`, replacing `UNAVAILABLE` in `controlPort()`) is ~40 lines in lab-app's paths once the route exists; acceptance = `tests/l/ui/journey.test.ts` J01/J02 against it on `l4` with a real registry and fake engine.
