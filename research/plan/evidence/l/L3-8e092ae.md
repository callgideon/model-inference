## Design (what L3 decides, what it leaves to the store)
- **No parallel catalog.** Rows are written only through A3's `operations.ports.Registry.put`
  (`PgRegistry`: serving revision, dev deployment revision, internal card) and read only through
  A3's `CatalogDirectory` (`PgCatalogDirectory`), the same resolution admission and `/v1/models` use.
- **Authorization** is L2's `_member` (current membership + role on the store clock): register /
  create_dev / validate / issue_dev_key / events need `manage_dev_deployment` (developer+),
  propose needs `propose_publication` (administrator). A foreign or unknown row is `not_found`.
  Operator operations take the `OperatorSession` that `Operations.operator(secret)` builds; its
  principal is the audit actor and the card's `approved_by`.
- **Validation** (`unsupported`): `runtime_image_ref` must be `<repo>@sha256:<64 hex>` with repo in
  `{vllm/vllm-openai}` (no moving tag, no uploaded image); `(input_schema_ref, output_schema_ref)`
  must be `(infrx.request.chat.v1, infrx.response.chat.v1)`; the serving row names the caller's
  provider and one of its own models. Artifact digests are the frozen record's (F2P).
- **Dev revisions**: private `dev` endpoint of the provider, `draft` → `validating` → engine smoke →
  `ready_private` or `retired` (a failed validation never becomes public); a provider_dev key only for
  a `ready_private` revision, scoped to its endpoint, stored as a hash; an internal card only on a
  private revision (a preview is never unmetered: unpriced → `invalid_request` at `pin_admission`);
  the dev wallet opens at 0 CREDIT and is funded only by operator allocations
  (operation id = `stable_id("lab_fund", idempotency_key)`).
- **Publication** = a NEW public `proposed_public` prod revision the administrator proposes from a
  `ready_private` dev revision of the same serving version; an operator approves it at a card as
  listing version + 1 (CAS on the expected version); a rollback adds version + 1 repeating an
  earlier version whose deployment is still active (CAS). The previously listed revision stays
  active, so a queued job's pins stay servable.

  ready_private, audited to the member) — smoke_skipped, smoke_inverted, key_before_validation,
  transition_without_cas, transition_unattributed, proposal_of_unvalidated.
- no dev revision reaches App discovery (consumer pins unchanged; dev names not_found for a consumer;
  the endpoint's own provider_dev credential resolves it, another endpoint's does not; a public id is
  no dev revision; an operator cannot publish it; an internal card never prices a public revision;
  unpriced dev is refused) — dev_revision_of_any_environment, card_not_the_operators,
  internal_card_on_public, publish_any_revision.
- dev credential scoped to its endpoint, hash only — key_stores_the_secret.
- dev wallet opens at 0, operator allocation only, once per key, audited to the operator —
  fund_new_operation_each_call, operator_unnamed, dev_wallet_opens_with_a_grant,
  allocation_replayed_twice.
- alias switch while a job is queued keeps its pins (publish → rollback) — publish_retires_previous,
  listing_overwritten.
- publication and rollback are CAS — listing_without_cas.
- rollback targets an earlier, still active version only — rollback_to_any_version,
  rollback_to_retired.

## Wiring requests
- **WR-L3-1 (schema request to lab-sql, L3-SQL)**: `infrx/state/lab_control.py: PgControlStore(connect)`
  implementing `infrx.lab.control.ControlStore` exactly (typed refusals via `jobstore.domain_error`;
  every write one transaction with its audit event; clock `infrx.now()`; service_role only, anon and
  authenticated 42501):
  - `db_now()` = `select infrx.now()`.
  - `model_provider(model_id) -> str|None` = `public.models.provider_org_id` where `model_uuid = $1`.
  - `deployment(id) -> DeploymentRevision|None`, any visibility (state/operations.py `_DEPLOYMENT`).
  - `endpoint(provider_org_id, name, environment, actor) -> endpoint_id`: 0007 `endpoints`, get or
    create (unique (provider, name, environment)).
  - `transition(id, provider_org_id, *, expected, to, actor, reason) -> DeploymentRevision`:
    `update … set state = to where id and provider_org_id and state = expected` (0007's guard keeps the
    graph); absent/foreign → not_found, another state → state_conflict; event `lab_transition`
    `{before: {state}, after: {state, reason}}`.
  - `propose(proposal: DeploymentRevision, *, source_revision_id, actor)`: lock the source; foreign →
    not_found; source not a `dev` private `ready_private` revision of the proposal's serving version →
    state_conflict; proposal not `proposed_public` → invalid_request; insert; event `lab_propose {source}`.
  - `issue_dev_key(*, provider_org_id, endpoint_id, user_id, key_hash, prefix, name) -> key_id`:
    endpoint must be the provider's `dev` endpoint (else not_found); `public.api_keys` row with
    `audience='provider_dev'`, `provider_org_id`, `endpoint_id`, and `org_id = provider_org_id`
    (`auth.context.auth_context` requires it; 0009 has no CHECK and `api_keys.org_id`'s FK target
    must admit a provider org — lab-sql's call); event `lab_dev_key {endpoint_id, prefix}` (never the hash).
  - `publish(public_model_id, card: RateCardSnapshot, *, expected_version: int|null, actor, reason) -> Listing`:
    serialize on the alias; current max version ≠ expected → state_conflict; the card's deployment
    not `proposed_public` → state_conflict; card of another model/serving → invalid_request (FKs);
    insert the card, `proposed_public → active`, `catalog_listings` version + 1 (`approved_by` actor,
    `effective_at` now); the previously listed revision is NOT drained/retired; event `lab_publish`
    `{before: previous listing, after: new listing + reason}`. Name ≠ `infrx.lab_publish` (0029, D7).
  - `rollback(public_model_id, *, to_version, expected_version, actor, reason) -> Listing`: CAS as
    above; `1 ≤ to_version < current` else not_found; target deployment not `active` → state_conflict;
    version + 1 repeating the target's (model, deployment, serving, card); event `lab_rollback`.
  - `fund_dev_wallet(provider_org_id, amount, *, operation_id, actor, reason) -> CreditLedgerEntry`:
    insert the `provider_dev` wallet at 0 if absent, then `infrx.grant_credit` kind
    `operator_allocation` (replay by operation id; nonpositive → invalid_request); event `lab_fund`
    with the provider's id (grant_credit's own `admin_adjust` row has no provider target).
  - `events(provider_org_id) -> [ControlEvent]` oldest first: {action, actor, provider_org_id,

## Proposed rulings (coordinator numbers)
- Lab control writes: `LabControl` writes registry rows only through A3's `Registry.put` and reads
  through `CatalogDirectory`; each state move, proposal, listing version, dev key and dev-wallet
  allocation is one L3-SQL call that compare-and-sets and writes its audit event in one transaction.
  Publication is a new `proposed_public` prod revision an administrator proposes from a
  `ready_private` dev revision of the same serving version and an operator approves at a card the
  operator approves; approval and rollback compare-and-set the listing version, never retire the
  previous listing's revision, and a rollback targets an earlier version whose revision is active.
- Provider runtime allowlist: a provider-registered serving revision runs `<repo>@sha256:<hex>` with
  repo in `SUPPORTED_RUNTIMES` and serves `SUPPORTED_SCHEMAS`; widening either is a reviewed change
  shipped with the G/W runtime adapter.
