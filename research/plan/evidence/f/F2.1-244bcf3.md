### C — R46 work loading, preparation fencing, job-id addressing

**Choice made:** the TS type literal is **parsed** rather than compared against a JSON
shape manifest exported from the console tests. A manifest is a generated artefact
that can drift from the type it was generated from with nothing noticing; the parser
compares against the type the console compiles, and fails on any member it cannot
read rather than skipping it. Nullability is read through `typing.get_args` — the
obvious `"NoneType" in str(annotation)` test calls every `X | None` field non-null and
would have made the whole comparison pass by accident — and `null` must be a
top-level union member, not one nested inside an object type.

### Breaking changes for consumers

These are source-incompatible and are why the README's per-track notes were rewritten:

1. `JobStore.prepared(job_handle, media)` → `prepared(lease, media)`, with
   `claim_preparation(job_id, worker)` before it.
2. `MediaStore.prepare(job_handle, profile)` → `prepare(job_id, profile)`;
   `attach(job_id, refs)` is a port operation.
3. `Lease` gains a required `kind`; `first_token_deadline_at` is nullable.
4. `Feedback.calibration_set` is `bool` (was `str | None`); `rubric_version` added;
   `FeedbackName` gains a fifth value.
5. `JudgeRun.rubric_version` is `int` (was `str`).
6. `wire.TraceExport` is flat (no nested `envelope`); `wire.UploadCompleted.media` is
   a `MediaSummary`.
7. `FeedbackService.label_calibration` takes `rubric_version`; `list_calibration` is
   new.
8. `PilotSettings.infrx_mode` defaults to `""`; `config.Settings` gains `pilot`.
