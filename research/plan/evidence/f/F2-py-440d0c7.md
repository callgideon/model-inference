## Failure drill

Deterministic injection through `FailurePlan` (`fail`, `raise_`, `crash_after_commit` on the *n*-th call of a named operation) and the scripted engine. Each drill is a conformance case, so every track re-runs it against its real adapter.

| Injection point | Durable state before | Durable state after | Duplicate/retry behaviour | Cleanup |
|---|---|---|---|---|
| Crash **after** the admitting commit, before the acknowledgment | no job, wallet reserved 0 | job `preparing`, one hold, three reservations, one `prepare_dispatch` event | retry with the same key returns the committed admission with `replayed=True`; reserved total unchanged; exactly one active job | none needed; the caller's retry is the cleanup |
| Same key, different canonical payload | one admitted job | unchanged | `IdempotencyConflict` → 409, no second job or hold | — |
| Idempotency mapping aged past `IDEMPOTENCY_TTL_S` after terminal | terminal job, tombstone | unchanged | `IdempotencyExpired` → 410; no new billable job is created silently | client must mint a new key |
| Crash **after** the journal append commit | no chunks | chunk committed, publication marker set | the events are readable by `read_owned` although the caller never relayed them (commit before relay) | recovery must not regenerate; see next row |
| Lease expiry **after** first committed chunk | `running`, published | `failed` / `lost_after_publication`, free | no requeue; no second attempt; one terminal outcome | capacity and journal reservation released; stored bytes still charged until pruned |
| Lease expiry **before** any output, twice with `MAX_PREPUBLICATION_RETRIES=1` | `running`, unpublished | `queued` once, then `failed` / `retries_exhausted` | bounded retries; the absolute deadline still wins in the deadline case | reservations released once |
| Stale generation and expired lease at heartbeat, append and complete | `running` at generation 2 | unchanged | `StaleLease` on every mutation; the fenced worker writes nothing | — |
| Duplicate completion (identical, then different) | terminal, settled | unchanged | identical call replays the stored outcome; a different one raises `AlreadyTerminal` and the ledger does not move | — |
| Concurrent cancel and complete (`asyncio.gather`) | `running`, hold held | exactly one terminal outcome | both callers observe the same committed outcome (or a typed conflict); hold resolved once, reserved back to 0 | — |
| Terminal with no authoritative usage after publication | hold held | `held_unknown`, debit 0, `reconcile_after` = +24h | before 24h the hold stays; after 24h with the attempt fenced and the job terminal it is released as `released_platform_absorbed`; ledger untouched (no retrodebit) | reconciliation emits a second `usage_projection` |
| Engine reports tokens beyond the validated envelope | hold held | `platform_error`, free, usage discarded | never charged as an unreserved debit | hold released |
| 8 concurrent admissions, room for 3 (`asyncio.gather`) | empty | 3 jobs, 3 holds | 5 callers get `CapacityExhausted`/`InsufficientCredit`; available balance never negative; reserved equals the sum of the 3 holds | — |
| Journal event over `JOURNAL_EVENT_MAX_BYTES` | no chunks | no chunks | `JournalWriteFailed`; nothing truncated | — |
| Journal prefix pruned, then replay from an old cursor | 3 chunks | 1 chunk | `ReplayGap` → 410 for the pruned cursor; a cursor past the gap reads normally | — |
| Whole journal expired after terminal | chunks + outcome | outcome only | `JournalExpired` → 410 while job status survives | bytes freed from the global budget |
| Engine faults: prefill stall, mid-stream stall, malformed usage, missing usage, abrupt exit, cancellation race, split reasoning delimiters | — | — | no fault yields authoritative usage except the cancellation race, which yields exactly one usage event for the work done; an abrupt exit raises a non-domain error | — |

## Limits

- **Fakes only.** Every conformance pass here is against in-memory adapters. This is **implemented**, never integrated or live verified. D (PostgreSQL), Q (Valkey and memory), W (engine), T (spool/ClickHouse) and M (object store) must each run the same suite against the real service; owners as in the suite table of `infrx/contracts/README.md`.
- **Console half pending.** `pnpm test` and `pnpm lint` did not run in this worktree (no `node_modules`, and `apps/app/**` is the parallel agent's path). Recursive console test discovery and the TypeScript DTO surface of 08 §9 are that agent's deliverable; the Makefile only names the commands. Owner: console F2 agent + coordinator.
- **Benchmark target not run.** `models/marlin2b/tests` does not exist yet (E1). `make bench-test` reports "not run" by design rather than printing a pass.
- **Lock resolution is today's.** `uv.lock` pins whatever the index offered on 2026-09-20 (fastapi 0.141.1, pydantic 2.13.5, …). A resolver refresh is a coordinator action, not a track's.
- **Single-lock concurrency in the fake.** `FakeJobStore` serializes with one `asyncio.Lock` instead of taking the documented lock order (capacity scope, org, key, wallet, lexicographic within a class). The concurrency cases therefore prove the *invariant*, not D's lock ordering; DUR-CAP against real PostgreSQL is what proves deadlock freedom. Marked in the source with a `ponytail:` comment. Owner: D.
- **Optional harness hooks skip cases.** A factory without `failures`, `publish`, `revoke_key`/`unrevoke_key`/`suspend_org` or `journal_bytes` makes the matching cases return early. The fakes provide all of them, so nothing was skipped here, but an adapter's evidence must state which hooks it supplied.
- **Not covered by this task, by design:** SSRF/DNS-rebinding behaviour (M/G own MEDIA-SEC against real sockets), real ClickHouse DDL and dedup (T), RLS and column grants (D/DUR-RLS), callback delivery (G5), console flows, any latency or throughput number. No performance claim is made anywhere in this task.
- **`OutboxKind.callback_delivery`** is in the vocabulary but no fake emits it; G5/D own its semantics.
