## F1 — R37 was not in `ports.py`, and the new code double counted

**The port contradicted the exported suite.** `TraceSink.open` declared
`(request_id, org_id, mode)` while `trace_bounds__an_open_capture_past_its_deadline_is_reaped`
called `open(id, org, mode, deadline)`: a sink implementing the Protocol exactly would
pass `isinstance` and then fail that case with a `TypeError`. Now:

- `open(request_id, org_id, mode, deadline_at)` with `deadline_at` **required**, because
  it is what makes a capture reapable — a capture without one could hold budget until the
  process restarted, which is the leak R37 exists to close. The fake returns a **no-op
  capture** for a `None` deadline rather than an unreapable one.
- `TraceCapture.__enter__`/`__exit__` and `TraceSink.reap(grace_s)` are declared.
- The stale `open` docstring is corrected (off/minimal → a no-op capture).
- `test_a_sink_built_from_the_declared_signatures_alone_satisfies_the_suite` writes a
  minimal sink from the Protocol docstrings and nothing else, asserts `isinstance` for
  both Protocols, and makes every call the suite makes — then repeats them against the
  fake. That is the test the r4 port would have failed.

**New-code defects, all reproduced first:**

| Defect | Reproduction | Fix | Mutant |
|---|---|---|---|
| `abandoned` counted **twice** | open, add, abandon, finish → `loss_reasons["abandoned"] == 2` | a capture contributes at most one loss count however it ends; `_drop(..., counted=True)` records the drop without recounting the loss | `capture_counts_its_loss_twice`, `drop_recounts_a_counted_loss` |
| `finish` claimed acceptance after a drop | a dropped first `finish` then a second → `accepted_in_memory` | the **first** result is remembered and returned, as the docstring says | `finish_forgets_its_first_result`, `finish_is_not_idempotent` |
| `add(non-bytes)` raised `TypeError` | `add(12345)` | dropped and counted `malformed` — the trace path never raises into the request path | `add_raises_on_a_non_byte_part` |
| `reap(grace_s<0)` reaped live captures | `reap(-100)` | clamped to 0 | `negative_grace_reaps_live_captures` |
| a **metadata-budget** drop kept its charge (m20's sibling) | finish into an exhausted metadata reserve | every dropped path releases the charge, through one shared branch | `metadata_drop_keeps_its_charge`, `queue_ceiling_ignored`, `metadata_reserve_ignored` |

## F2 — R39's reserve was computed over one cause

`check_terminal_capacity` took the maximum over `cause in (platform_error,)`, which is 3
bytes short of `journal_write_failed` + `failed` + `released_platform_absorbed` (and 1
short of `deadline_exceeded` + `expired`). At `JOURNAL_JOB_RESERVE_BYTES` 94–96 a
settlement released the hold and *then* refused the caller. The maximum is now computed
over **every** `TerminalCause × JobState × SettlementState`, and
`dur_settle__a_settlement_that_cannot_journal_moves_no_money` sweeps reserves
`60, 80, 90, 94, 95, 96, 100, 120, 200` bytes × all 14 causes, asserting all-or-nothing
on each and that the sweep really crosses the boundary — instead of the 16-byte reserve
where even the check failed.

`recover` also no longer aborts on one unsettleable job: the refusal is caught, recorded
(`unsettleable`, a new documented hook) and returned among the sweep's products, so the
other overdue jobs still get reaped and release their holds.
`dur_settle__one_unsettleable_job_does_not_stop_the_sweep` pins it, with two mutants.

## F3 — evidence corrections, and the typed refusals behind them

Four corrections are appended to `F2-py-912bed8.md` in place: the untyped-error claim
(false at that SHA), the R39 "largest payload" sentence (F2 disproves it), R37 "G needs no
branch" (a minimal envelope was dropped as malformed), and R37 not being in `ports.py`.
The fixes:

- `admit`'s negative-hold case and the judge's monetary case now assert
  `isinstance(exc, errors.DomainError)` **and** the code. The judge assertion checks the
  internal code **before** `errors.http_status`, which raises for internal codes: the old
  order made the `or` branch dead and would have crashed the case for an adapter that
  legitimately answers `budget_exceeded`. The judge case now drives negative, non-finite,
  over-scale and float reservations, all of which must be typed refusals.
- **`finish` on a no-op capture behaves as `offer`** (preferred option; 01 requires the
  minimal metadata row and does not contradict it), so a `minimal` request yields exactly
  one metadata envelope with zero content bytes and an `off` request none at all. G opens,
  adds, finishes and never branches on the mode; `ports.py` says so and
  `trace_bounds__off_mode_produces_no_trace_at_all` pins both modes.

## Corrections (r6 review, fixed in the following pass)

Two claims in this report were wrong, both about code r5 itself introduced:

1. **"`finish` on a no-op capture behaves as `offer`" was the defect, not the fix.** It
   called `sink._offer_metadata(envelope)` without consulting the capture, so the
   **envelope** decided what was stored - which makes the trace mode a client-supplied
   field, exactly what R12 forbids. Five consequences the r6 review reproduced: a `full`
   capture with no deadline discarded its content with `loss_reason: none` and no counter
   (02 requires a loss to be marked *and* counted); a `minimal` capture accepted a `full`
   envelope **with content**; an `off` capture queued a row (01: off produces none); no
   identity check, so another tenant's envelope was accepted on the no-op path while the
   accumulating path dropped it; and a content-carrying envelope was stored as
   `content_complete=True` although every `add` had returned False. `_finish_no_op` now
   decides from the capture's own mode, identity and state, with one mutant per branch.
2. **`metadata_drop_keeps_its_charge` was reported killed but was not the corpus mutant
   m20b.** It deleted the *shared* release line, and its only named case drove
   `trace_queue_max=1`, so it died through the `queue_full` branch while a finish dropped
   for `metadata_budget` kept its charge. The case now has a metadata-exhaustion phase and
   `charge_released_only_on_queue_full` is a mutant specific to the reason.

Also corrected in the same pass: `offer` was not metadata-only (an envelope carrying
content was queued without ever being charged), `recover` returned `DomainError` objects
inside a tuple annotated `tuple[TerminalOutcome | IndexEvent, ...]`, one assertion in
`dur_settle__one_unsettleable_job_does_not_stop_the_sweep` was `... == 0 or True`
(vacuous), and the README's R37 row still described the pre-fix no-op behaviour.
