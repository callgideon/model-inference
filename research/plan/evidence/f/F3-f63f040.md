## Proposed rulings (coordinator numbers from R156)
1. Lab refs: `lab:<kind>:<provider_org_id>:<object_id>@sha256:<hex>`; identity = sha256 of canonical JSON; anything else is mutable and refused; every ref in a record belongs to the record's `provider_org_id` (plus server resolution).
2. One validator, five reasons in the fixed order unknown_schema > mutable_ref > cross_provider_ref > mixed_units > invalid; `packages/shared/contracts/lab/fixtures.json` is the single conformance source for both halves; `lab.<name>.<n>` versions never upgrade silently.
3. Lab money: `{unit,value}`, CREDIT (provider_dev inference) or PROVIDER_USD (judge/teacher/training/external, named payer); legacy USD never a Lab unit; siblings same unit; reservation <= limit; one budget per unit; no conversion.
4. Rights gates: schedule/access -> provider_sharing, export -> training, external_submission -> external_judging, each checked against the current membership AND grant at the gate; manifests are audit evidence only.
5. State machines and keys as `infrx/contracts/lab/states.py`; `ambiguous` reconciles by lookup, never resubmits; keys `run:`/`attempt:`/`submit:` derived, not chosen.
6. Rollout cohort: bucket = sha256(policy_id "\n" subject) mod 10000 over candidates in order (stable across versions); only a canary carries candidate weight; expand requires evidence refs.
7. v1/v2 contract bytes pinned by `tests/contracts/lab/frozen_contracts.json` at 9a6c3685; a contract revision updates the pin in the same commit.
