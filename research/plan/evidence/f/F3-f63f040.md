### Proposed rulings, amended (coordinator numbers from R157; R156 is taken)
1. (amended) Lab refs use the grammar `lab:<kind>:<provider_org_id>:<object_id>@sha256:<hex>`, and identity is the sha256 of the record's **RFC 8785 (JCS)** canonical JSON: keys by UTF-16 code unit, compact, ECMAScript number spelling, UTF-8. Both halves refuse (`invalid`) a non-finite number or an integer outside +-(2^53-1). Anything else is mutable and refused. Every declared ref belongs to the record's `provider_org_id`, and the server also resolves it.
2. (amended) One validator gives five reasons in this order: unknown_schema > mutable_ref > cross_provider_ref > mixed_units > invalid. The ref and unit scans cover declared fields only. Free-form content (`input_schema`, `input_mapping`, `reference_output`, `label` = `OPAQUE`) is never read as a ref or amount. `fixtures.json` is the single conformance source for both halves, and a `lab.<name>.<n>` version never upgrades silently.
4. (amended) Each rights gate checks the current membership AND the current grant for a purpose the gate allows. schedule/access use provider_sharing and export uses training (each is its gate's default). external_submission uses the ExternalRun's own purpose, external_judging or training, which the caller names from the run; there is no default and no cross-purpose. Manifests are audit evidence only.
3, 5, 6 and 7 are unchanged.
