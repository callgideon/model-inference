## Limits

- **Fakes only.** Every conformance pass is against in-memory adapters:
  **implemented**, never integrated or live verified. D, Q, W, T and M must each
  run the same suite against the real service.
- **R4's `accepted_at` is `Admission.admitted_at`.** The same fact under the name
  `06` and the console already use; no field was added for it. If the coordinator
  wants the literal name, that is a rename across both halves.
- **`resolve_ambiguous` takes the provider id as a keyword.** R8 lists four
  positional arguments and also requires the id; see amendment request 4.
- **The entitlement source is a callable on the fake.** Nothing here proves D's
  query is in the same transaction; DUR-ADMIT against real PostgreSQL does.
- **`expire(now)` still accepts a time** (01's signature) and only clamps it. If
  R7 means the parameter must go, that is a one-line change plus D's adapter.
- **Cumulative queue wait and the 409 on re-admission** remain F2's readings of 01
  and 06, now confirmed by R5 and R6.
- **Single-lock concurrency in the fake** (unchanged, `ponytail:` comment in the
  source): `FakeJobStore` serializes with one `asyncio.Lock` instead of the
  documented lock order.
- **Optional harness hooks skip cases.** The fakes provide all of them, so nothing
  was skipped here; an adapter's evidence must say which hooks it supplied.
- **Console half pending.** `pnpm test`/`pnpm lint` did not run. The only console
  interaction was reading its money case list.
- **Not covered by design:** SSRF/DNS rebinding, real ClickHouse DDL and dedup,
  RLS and column grants, callback delivery, console flows, any latency or
  throughput number. No performance claim is made.
