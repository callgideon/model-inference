## Limits

- **Not integrated.** Not merged, not deployed, never run against real vLLM, real Supabase, real DNS or `ffprobe`. Every HTTP interaction in evidence is a mock transport. No live or paid check was performed; anything of that kind is **pending**, not passed.
- Console suite and lint (`pnpm test`, `pnpm lint` in `apps/app`) **not run**: `node_modules` absent and dependency manifests are not owned by this task. No console file changed. Owner: coordinator / F2.
- The parity matrix is 15 representative cases, not an exhaustive product of inputs. Untested by it: real multi-hop redirects over a live socket, the `input_video` part shape, `MAX_VIDEO_SECONDS` rejection, malformed `data:` payloads, usage-queue overflow, `get_prices` TTL behavior through the route, concurrent in-flight accounting under real load. Several are covered indirectly by the baseline suite; the rest belong to G/M/E oracles (MEDIA-SEC, API-STREAM, PERF-PILOT).
- Behavior preserved on purpose, including known weaknesses that are **not** F1's to fix (they are listed so they are not mistaken for regressions): 429 is checked after authentication but before media work, so an over-capacity request with a video still pays the auth round-trip and the capacity check does not cover media time; `/health` echoes upstream exception text to the caller; with neither `GATEWAY_API_KEY` nor `SUPABASE_URL` set the gateway serves unauthenticated; the streaming `<think>` strip is a first-chunk heuristic that mangles a reasoning block split across chunk boundaries (visible in the parity output as an empty first delta); the legacy `usage_events` row shape carries `cost_usd: 0` and is recomputed by the shipper; usage rows for legacy-key requests never reach Supabase; `prepare_video` validates then connects, so the documented DNS-rebinding window remains. Owners: G (gateway/auth/limits), M (media), D (accounting).
- The legacy-global shim is a compatibility layer with a shelf life: it forwards a fixed table, so a *new* name added to `infrx` is not automatically visible as `gateway.<name>`, and `del gateway.<name>` is not supported. It exists so F1 changes no test and no deployment; once G owns the routes and the tests move to `create_app()`, the table should shrink to `app` (tracked by the `ponytail:` note in the module). Risk if left forever: two ways to reach the same state. Owner: G, after F2.
- `create_app()` builds its default clients eagerly (unchanged from the old import-time behavior), so a caller that injects neither `client` nor `sb` still constructs two `httpx.AsyncClient` objects. Harmless (no connection until first use) but worth knowing when many apps are built in one process.
