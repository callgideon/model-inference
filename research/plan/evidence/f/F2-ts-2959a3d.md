## 1. Blocking findings

### B1 — `keys.create` replay handed the secret to anyone, forever

The idempotency record stored the whole `ApiKeyCreated`, secret included, keyed by
`org|operation|key`. Any later replay returned it: the creating user, a second owner, the operator
session, and after revocation. Ruled by **R16**: shown once, to the first response only.

Fixed by storing less rather than by checking more — the record now holds the key's **id**, and a
replay rereads the key from the organization's key list and returns `{...metadata, secret: null,
replayed: true}` with the current `revoked_at`. There is no stored secret for an authorization
mistake to unlock, which is why the fix is a property and not a guard. `ApiKeyCreated.secret` is
`string | null` and the type carries `replayed`. The false "never stored" comment is gone (the
secret now genuinely exists only in the response object), and the README no longer implies C stores
secrets — it says C stores the key id and rereads the key, as the fake does.

Cases (conformance, so C runs them): first response carries the secret and `replayed: false`;
same-user replay → `secret: null`, `replayed: true`, same id; **different session** (operator)
replay → same id, `secret: null`; replay after revoke → `revoked_at` set, `secret: null`; and an
exhaustive read sweep — usage, usageSummary, usageDaily, balances, ledger, traces, settings.get,
keys.list, judgeRuns, adminOrgs, calibration.list plus all three replays — asserting the secret
string appears in none of them. Fake-only (`unsafeDebugState()`, a hook that exists for this one
assertion): a deep scan of the entire fake state contains the key's public prefix but not the
secret, before and after revocation.

### B2 — an operator session's ordinary feedback was labelled `operator`

`feedback.submit` set `author_role: session.isOperator ? "operator" : "customer"`, which 02 forbids:
console-origin input is not automatically an operator label. Ruled by **R19**.

Provenance is now a parameter of the single `appendFeedback` helper — the only place a feedback
entry is created — so every caller states it explicitly and `feedback.submit` passes `customer`
unconditionally, with `calibration_set: false` and `rubric_version: null`. Operator labels come from
the new operator-only `calibration.label`, whose entry is a `calibration_label`: the only name that
may carry `author_role: "operator"`, `calibration_set: true` and a rubric version, and a name a
client cannot submit because it is absent from the input vocabulary (`FEEDBACK_NAMES` for input,
`FEEDBACK_ENTRY_NAMES` for stored entries). `calibration.list` is the operator-only view of the set.

Also added, with the same validate → replay → write → record discipline, operator-only role checks,
audited reasons and required idempotency keys: `adminSetSuspension` and `adminSetEntitlements`.
Suspension gates new work only — the conformance case snapshots every ledger row and every usage
row's `cost`, `settlement_state` and `max_hold`, suspends, restores, and asserts the snapshot is
byte-identical.

The reviewer's point that nothing pinned the label (forcing `"customer"` everywhere left 51/51
passing) is answered directly: the provenance case submits through the same control with owner,
member **and** operator sessions and asserts `channel`, `author_role`, `calibration_set` and
`rubric_version` on each, and `assertFeedbackEntry` applies the R19 invariant to every listed entry.
The round-3 evidence's "exercised indirectly" wording was wrong — it was not exercised at all —
and is corrected here.

### B3 — the discovery guard walked past dot paths

Node's glob does not match a path segment starting with `.`, so `tests/.hidden/h.test.ts` and
`tests/contracts/.wip.test.ts` never ran; the guard skipped the dot-directory and its `[^/]*`
happily matched the dotfile, so it stayed green. Any dot segment now counts as **unmatched**, and
only `node_modules` and `.git` are skipped outright (never source, at any depth); `out`, `build`,
`coverage`, `dist` remain root-only skips.

Drilled in a scratch copy of `apps/app` (`rsync`, `node_modules` symlinked; the worktree untouched):
with the check, the guard fails naming both files and neither hidden test runs; with the check
removed, **60/60 pass** — the reviewer's observation reproduced exactly. The round-3 evidence claim
that the guard reports every undiscovered test was too strong for dot paths and is corrected here.

## 6. Limits

- Everything still runs against the fake. Nothing here proves C or the database.
- **N8 is defence in depth, not a proven path.** A read can only overflow if stored money already
  exceeds the domain, which every write now prevents, so the branch is unreachable from outside and
  no mutation drill covers it. It exists so that a future writer of bad data yields `internal_error`
  rather than a thrown `RangeError`.
- **N9 is a cost guard, not a behaviour change.** A million-digit numeral was already invalid; the
  test pins the bound and that huge inputs are refused, but no test can distinguish the fast
  rejection from the slow one.
- The fake's idempotency records never expire, so `idempotency_expired` is still unexercised.
- `calibration.list` scans every organization's traces; C will index it. The suite only requires the
  role check and the contents.
- Entitlement limit names, `MAX_RUBRIC_VERSION`, `MAX_ENTITLEMENT_LIMIT` and the calibration label
  vocabulary are provisional shapes with numbers chosen here (R17's precedent).
- `unsafeDebugState()` is a fake-only hook. C cannot offer it, so the portable half of the
  secret-retention assertion is the read sweep; a real implementation that stored the secret in a
  column nothing reads would pass the sweep and fail a schema review, not this suite.

## 7. Open questions (new only)

1. **`OrgEntitlements` shape.** `model_ids` plus three named integer limits is a guess that fits U3's
   "entitlement controls" and nothing more precise. If D1's schema names different controls, this is
   a contract revision before C builds the page.
2. **An empty `model_ids` means "the platform default set", not "no models".** That reading matters
   for the suspension/entitlement page copy; the alternative (empty = nothing entitled) would need
   an explicit default marker.
3. **Python `INTERNAL_CODES` still carries `journal_write_failed`**, which 08 §3 lists only as a
   `TerminalCause`. Forwarded in round 3, restated here because the 27-code HTTP parity now passes
   while the internal-code sets still differ by one.
4. **`calibration.label` reaches a trace in any organization** (operator authority, tenant taken
   from the row). If operators should be scoped to a subset of organizations, that is a rule the
   contract does not yet have.
