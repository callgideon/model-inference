## Limits

- **Fake only.** Everything above is the in-memory fixture implementation. C must rerun `runConsoleServicesConformance` against real PostgreSQL/ClickHouse before any of it counts as integrated.
- **Cross-language money parity is now demonstrated for the parse domain only** — the fixture strings round-trip through both parsers identically. The `charge_half_up` / `hold_ceiling` constants are still asserted by each side separately; a single shared fixture file consumed by both suites remains a coordinator decision. TypeScript never multiplies, so it cannot verify the Python rounding.
- **`UsageRow.settlement_state` is non-nullable**, so an in-flight job reads `held_unknown` and its hold is counted in `usageSummary.pending_reconciliation`; a UI that labels that "awaiting reconciliation" will say so for live requests. Owner: coordinator (a nullable field for non-terminal rows is a DTO change U/V consume).
- **Fake-only cursor semantics.** Cursors are offset-based and bound to the page size, so changing `limit` mid-walk is `invalid_cursor`, and a grant issued during a ledger walk can repeat one entry. The suite requires neither property, so C's keyset cursors are not over-constrained; recorded in the README.
- **`judgeRuns` is readable by a member.** No handoff restricts it. If J or U want it owner-only, that is a coordinator amendment.
- **Not exercised:** concurrency (simultaneous grants, a hold taken while a balance is read), RLS and column grants (DUR-RLS), real projection lag, signed-URL issuance and expiry (C2/M3), durable feedback acceptance (D6), real judge submission (J).
- **No DOM or component test stack** (08 §6 forbids adding one in F2).
- **`tsc --noEmit` needs a prior `next build`** on a clean checkout: four pre-existing app files reference Next's generated `PageProps`/`LayoutProps`. Not F2-ts's files; worth a coordinator decision because it affects everyone's local check.
- **`tsconfig.json` targets ES2017**, where BigInt literals (`0n`) do not compile; the money module uses `BigInt(0)` and `BigInt("100000000000000000000")`. An ES2020 bump is an integration request.
- **The discovery guard covers `*.test.ts` / `*.test.tsx` only**, not `.test.mts` or `.spec.ts`.
- `pnpm build` succeeded locally without secrets; that is not a deployment claim.
