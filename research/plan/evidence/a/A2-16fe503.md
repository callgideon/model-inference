## What is done (brief items)

1. **Signup, verify-email, resend, sign-in, password recovery, expired-link states** against the configured auth service (Supabase GoTrue via the existing browser client):
   - `app/(auth)/signup/` (new): email/password `signUp` with `emailRedirectTo = <origin>/auth/callback?next=/welcome`; success and "address already registered" (`user_already_exists`/`email_exists`) give the identical "Check your email" state (no enumeration); inline resend.
   - `app/(auth)/verify-email/` (new): explanation + `ResendForm` (`auth.resend({type:"signup"})`); same answer whether or not the address is pending; 60 s button cooldown; rate limit/outage reported as fixed copy.
   - Sign-in: `invalid_credentials` and `user_not_found` read identically; `email_not_confirmed` links to resend; 429/`over_*_rate_limit` → "Too many attempts"; unknown errors → generic. The raw server `error.message` is never shown on any auth page (static check A2-COPY-02).
   - Recovery: forgot-password now reports a rate limit/outage instead of falsely saying "sent"; update-password maps a missing/expired recovery session to "link expired" + a link to request a new one; `same_password`/`weak_password` fixed copy; min length hint 8 (shared `MIN_PASSWORD_LENGTH`).
   - Callback (`app/auth/callback/route.ts`): link errors become fixed codes `link_expired`/`link_invalid` (the provider's `error_description` — free text anyone can put in a link — is no longer reflected into /login); `otp_expired`/`flow_state_*` → expired; unknown `type` or missing code → invalid; recovery → `/update-password`; stricter same-site `next` (backslash/control chars refused).
   - Login page: invitation-only copy replaced by a "Create an account" link; `?error=` shows only known codes' fixed copy.
   - Abuse/rate limits and callback/origin allowlist are auth-service configuration (P-05, see "Unresolved inputs"); the App surfaces them truthfully and never widens them.
2. **Grant through the trusted idempotent entitlement** — `app/(auth)/grant.ts` (server-only, service-role client, `typeof window` guard) calls A1's `public.claim_signup_grant(p_user_id, p_campaign_version='consumer-v1')` (0015). The database derives verification itself and is idempotent per individual and per verified email (R71). Called from three places, all with the **server-verified** user id (`getUser()`), never a URL/client value:
   - the email-link callback after a successful exchange/verify (RV-06: the callback never claimed before);
   - sign-in (the 02 "first-login" path for existing verified users, and for a link opened on another device where the PKCE exchange fails after GoTrue already confirmed the address) — via the zero-argument server action `claimOnboarding()` (`app/(auth)/welcome/actions.ts`; Next's server-action Origin check covers cross-site posts);
   - the onboarding retry button.
   A claim failure never blocks sign-in (lands on /welcome to retry). Reopened callbacks, concurrent sessions and new org memberships resolve to the one grant (real-PG A2-PG-02/03). Unverified users cannot be granted (A2-PG-01) and the browser roles cannot call the grant directly (A2-PG-04: `anon`/`authenticated` → 42501, nothing minted). A key an unverified user might create is unfunded by construction (no wallet exists until the grant; key actions are C3A's).
3. **After verification**: `/welcome` (new, session-protected by the existing middleware) reads `console_wallet_summary(user)` (0008) with the user's JWT and shows the **actual** available CREDIT balance (`displayCredit`, exact decimal string, labelled credits; no USD), the one-time/no-refill statement, and next steps (API key, docs example, models). No wallet → "not issued yet" + "Issue my credits" retry (recoverable incomplete onboarding); a failed read → "could not be loaded" + reload — never a zero or a guessed figure (A2-BAL-*). Held reasons (identity reuse, rollout hold, retired) show a generic "needs a manual check" message (no enumeration of other accounts).
   Accessibility: every auth input has a `<Label htmlFor>`; every error region has `role="alert"` (static check A2-A11Y-01); notices `aria-live`; focus moves to the "Check your email" heading after signup; page titles are `<h1>`; icons `aria-hidden`; layout is the existing `max-w-sm px-4` auth layout (mobile). **Staging fresh-email journey not run** (P-05; local fake mail cannot close E4).

  "utf8",
);

const PUBLIC = table ? [...table[1].matchAll(/"([^"]+)"/g)].map((m) => m[1]) : [];
